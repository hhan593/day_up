## 1. 概述

为提升系统操作效率、优化业务模块的聚合度，并使系统命名更贴合实际业务场景，本次对系统全局导航菜单进行了全面梳理与重构。本文档详细记录了菜单架构的调整方案、具体变更明细以及对外发布的更新摘要，作为后续研发、测试及运营推广的标准依据。

## 3. 模块变更详细说明（需求拆解）

_说明：本章节以“变更动作”为维度进行分类，逻辑严密，作为 PRD（产品需求文档）补充或研发、测试的任务拆解依据。_

### 3.1 模块合并与重构

- **供应商管理**：由原「厂商管理」与「渠道管理」合并而来，实现供应链路的集中管控。
- **费用中心**：由原「财务管理」、「提现审核」、「余额审计」整合而成。中心内下设四个二级模块：
    - **账户总览**：展示全局财务数据看板。
    - **收支情况**：记录详细的资金流水。
    - **发票管理**：处理开票申请与发票记录。
    - **资金管理**：包含“充值”与“提现”两个三级子功能。
- **系统配置**：新增为一级父菜单，将原「用户管理」、「内容管理」、「日志管理」收纳至其下级，实现前台业务与后台配置的有效分离。

### 3.2 模块重命名

- 原「媒体任务」更名为 **资源包管理**。
- 原「分销管理」更名为 **销售报价**。

### 3.3 保持不变模块

- **模型管理**、**订单列表**、**APIkey管理**：维持原有层级、路由与功能不变，保障核心业务的稳定性。

## 4. 版本更新公告 / 汇报摘要

_说明：本章节语言精炼、正式，强调业务价值的提升。用于向管理层汇报、写入版本 Release Notes（更新日志）或作为对外的系统升级公告。_

> **📢 系统菜单架构优化与升级说明**
> 
> 为提升系统操作效率与业务模块的聚合度，本次对系统导航菜单进行了全面优化，具体调整如下：
> 
> 1. **供应链与业务模块整合**：将原“厂商管理”与“渠道管理”统一合并为「供应商管理」，实现供应链路的集中管控；原“媒体任务”升级为「资源包管理」，原“分销管理”调整为「销售报价」，使业务命名更贴合实际场景。
> 2. **财务体系重构**：全新推出「费用中心」，深度整合原财务管理、提现审核及余额审计功能。中心内设账户总览、收支情况、发票管理，以及包含充值/提现功能的资金管理模块，实现财务数据的全链路闭环。
> 3. **系统设置聚合**：新增「系统配置」一级菜单，将用户、内容及日志管理统一归口，使前台业务与后台配置有效分离，界面更加清爽。
> 4. **核心功能保留**：模型管理、订单列表及 APIkey 管理保持原有架构不变，保障核心业务的稳定性。

## 5. 实施注意事项（研发/测试备忘）

为确保本次菜单架构调整平稳落地，请相关团队关注以下事项：

1. **权限迁移（RBAC）**：菜单结构调整后，需同步更新权限树。确保原有角色的菜单访问权限平滑迁移，避免用户登录后出现“无权访问”或“菜单丢失”的情况。
2. **路由与书签兼容**：前端路由 Path 建议保持向后兼容，或配置重定向（Redirect），防止用户浏览器中保存的旧版菜单书签失效。
3. **数据兼容与迁移**：菜单合并（如厂商与渠道合并为供应商）若涉及底层数据表结构的变更，需提前准备数据迁移脚本（Migration），并在测试环境进行充分验证。
4. **UI/UX 交互**：「费用中心」和「系统配置」作为包含多级子菜单的父级节点，需确认其展开/折叠的交互逻辑及图标设计。
