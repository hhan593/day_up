## 二、核心框架深度解析

### 2.1 LangChain

**定位：** Agent 生态的"标准库"，组件最齐全

**核心概念：**
```
Chain（链）: 步骤序列（Prompt → LLM → 输出解析）
Agent：     使用工具的决策循环
Memory：    对话历史管理
Retriever： 文档检索器（RAG 核心）
```

**典型使用场景：**
```typescript
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { TavilySearchResults } from "@langchain/community/tools/tavily_search";

// 创建带搜索工具的 ReAct Agent
const agent = createReactAgent({
  llm: new ChatOpenAI({ model: "gpt-4o" }),
  tools: [new TavilySearchResults({ maxResults: 5 })],
});

const result = await agent.invoke({
  messages: [{ role: "user", content: "今天比特币价格是多少？" }]
});
```

**优点：** 生态最成熟、文档完善、工具集成多  
**缺点：** 复杂场景下抽象层太重、调试困难、版本迭代快（API 变化频繁）

---

### 2.2 LangGraph

**定位：** 生产级 Agent 工作流编排，LangChain 的图式升级版

**核心概念：**
```
StateGraph（状态图）: 以"状态"为中心的有向图
Node（节点）:        执行具体逻辑的函数
Edge（边）:          节点间的流转关系
Conditional Edge:   根据条件动态路由
Checkpointer:       持久化状态，支持暂停/恢复
```

**架构示意：**
```
    START
      │
      ▼
  [规划节点]
      │
      ├── 需要搜索 ──→ [搜索节点] ──→ [综合节点]
      │                                    │
      ├── 需要计算 ──→ [计算节点] ──→ [综合节点]
      │                                    │
      └── 直接回答 ──────────────────────→ END
```

**典型使用（带 Human-in-the-loop）：**
```typescript
import { StateGraph, Annotation } from "@langchain/langgraph";
import { interrupt } from "@langchain/langgraph";

const AgentState = Annotation.Root({
  messages: Annotation<Message[]>({ reducer: (x, y) => x.concat(y) }),
  plan: Annotation<string>(),
});

const graph = new StateGraph(AgentState)
  .addNode("planner", plannerNode)
  .addNode("human_review", async (state) => {
    // 暂停，等待人工审核
    const approval = interrupt("请审核以下计划：" + state.plan);
    return { approved: approval };
  })
  .addNode("executor", executorNode)
  .addEdge("planner", "human_review")
  .addConditionalEdges("human_review", 
    (state) => state.approved ? "executor" : "planner"
  )
  .compile({ checkpointer: new MemorySaver() });
```

**优点：** 流程可控、可调试、支持持久化、LangSmith 深度集成  
**缺点：** 学习曲线较陡，需要理解图式编程思维

### 2.3 CrewAI

**定位：** 基于角色的多 Agent 协作框架，"团队隐喻"

**核心概念：**
```
Agent（智能体）: 有角色、目标、背景知识的 Agent 成员
Task（任务）:   需要完成的具体工作，可分配给特定 Agent
Crew（团队）:   Agent 的集合，协作完成复杂任务
Process：       顺序执行 / 层级管理（Manager Agent 分配）
```

**典型使用（内容创作团队）：**
```typescript
import { Agent, Task, Crew, Process } from "@crewai/crewai";

// 定义团队成员
const researcher = new Agent({
  role: "资深研究员",
  goal: "深度调研指定主题，收集最新、最准确的信息",
  backstory: "你是一位专注于 AI 领域的资深研究员，擅长检索和分析信息",
  tools: [searchTool, webScrapeTool],
  llm: "gpt-4o"
});

const writer = new Agent({
  role: "技术写作专家",
  goal: "将研究成果转化为清晰、有深度的技术文章",
  backstory: "你是一位经验丰富的技术作家，文章逻辑清晰、深入浅出",
  llm: "gpt-4o"
});

// 定义任务
const researchTask = new Task({
  description: "深度调研 AI Agent 的最新发展趋势，输出结构化调研报告",
  agent: researcher,
  expectedOutput: "包含最新趋势、主要框架、典型案例的调研报告"
});

const writeTask = new Task({
  description: "基于调研报告，撰写一篇 2000 字的技术博客",
  agent: writer,
  context: [researchTask]  // 依赖调研任务的输出
});

// 组建团队并启动
const crew = new Crew({
  agents: [researcher, writer],
  tasks: [researchTask, writeTask],
  process: Process.Sequential,  // 顺序执行
  verbose: true
});

const result = await crew.kickoff();
```

**优点：** 角色抽象清晰、任务依赖自动管理、适合流水线场景  
**缺点：** 灵活性不如 LangGraph，复杂条件控制较弱

---

### 2.4 AutoGen

**定位：** 微软出品，对话驱动的多 Agent 协作，最大灵活性

**核心概念：**
```
AssistantAgent:   AI 驱动的 Agent
UserProxyAgent:   代表人类用户的 Agent（可执行代码）
GroupChat:        多 Agent 群组对话
ConversableAgent: 可对话的基础 Agent 类
```

**典型使用（代码审查团队）：**
```typescript
import { AssistantAgent, UserProxyAgent } from "autogen";

const codeWriter = new AssistantAgent({
  name: "代码工程师",
  systemMessage: "你是一位资深 Python 工程师，负责编写高质量代码",
  llmConfig: { model: "gpt-4o" }
});

const codeReviewer = new AssistantAgent({
  name: "代码评审员",
  systemMessage: "你是代码评审专家，专注于代码质量、安全性和性能",
  llmConfig: { model: "gpt-4o" }
});

const userProxy = new UserProxyAgent({
  name: "用户",
  humanInputMode: "TERMINATE",  // 完成时请求人工确认
  codeExecutionConfig: { workDir: "./code_workspace" }
});

// 发起群组对话
await userProxy.initiateChat(
  codeWriter,
  "帮我写一个高性能的分页查询工具函数，并让评审员检查代码质量"
);
```

**优点：** 最灵活、原生 Human-in-the-loop、Azure 生态深度集成  
**缺点：** 多 Agent 对话成本高、难以精确控制执行流程

---

### 2.5 OpenAI Swarm（学习用）

**定位：** OpenAI 官方的轻量级多 Agent 框架（教育用途）

**核心概念：**
```
Agent：  有系统提示和工具的 LLM
Handoff：Agent 之间的任务移交
```

```typescript
// Swarm 极简示例
const triageAgent = {
  name: "分诊 Agent",
  instructions: "根据用户问题类型，转交给合适的专家 Agent",
  functions: [transferToSales, transferToSupport]
};

const salesAgent = {
  name: "销售 Agent",
  instructions: "解答销售相关问题，推荐合适的产品方案"
};
```

**适合：** 理解多 Agent 原理，不建议生产使用

## 三、框架选型决策树

```
开始选框架
    │
    ├── 我只是想快速试验 Agent 想法？
    │       └── smolagents / Swarm（最简单）
    │
    ├── 我需要构建 RAG 知识库系统？
    │       └── LlamaIndex（专业）
    │
    ├── 我需要多个 Agent 角色协作流水线？
    │       ├── 业务流程明确 → CrewAI
    │       └── 需要灵活对话 → AutoGen
    │
    ├── 我需要复杂的工作流控制（条件、循环）？
    │       └── LangGraph（生产首选）
    │
    ├── 我需要可视化拖拽，不想写太多代码？
    │       ├── 开源自部署 → Dify / Flowise
    │       └── 商业服务 → Coze / Make
    │
    └── 我需要一个大而全的通用框架？
            └── LangChain（组件层）+ LangGraph（编排层）
```

## 四、框架组合推荐

### 生产级标准组合（推荐）
```
数据层: LlamaIndex（RAG、文档处理）
编排层: LangGraph（状态管理、流程控制）
组件层: LangChain（LLM 调用、工具集成）
可观测: LangSmith（监控、评估、调试）
```

### 多 Agent 协作组合
```
协作层: CrewAI（结构化任务分工）
编排层: LangGraph（复杂条件路由）
组件层: LangChain（底层支持）
```

### 轻量快速开发组合
```
Dify（一站式：RAG + Agent + 可视化编排）
```

## 五、性能与成本对比

| 框架 | LLM 调用次数 | 延迟 | 成本 | 稳定性 |
|---|---|---|---|---|
| LangChain（简单 Agent）| 较少 | 低 | 低 | 高 |
| LangGraph | 可控 | 可控 | 可控 | 高 |
| CrewAI（顺序）| 多 | 高 | 高 | 中 |
| AutoGen（群组对话）| 很多 | 很高 | 很高 | 中 |
| Swarm | 少 | 低 | 低 | 中 |

> 多 Agent 系统成本显著高于单 Agent，生产环境需严格控制轮次和工具调用次数。
