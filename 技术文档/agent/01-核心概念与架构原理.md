# AI Agent — 核心概念与架构原理

> 本文深入解析 Agent 的五大核心技术组件：RAG、Memory、Tools、Planning、Reasoning

---

## 一、Agent 架构总览

2023 年，前 OpenAI 研究员 Lilian Weng 提出了 Agent 的经典定义：

```
Agent = LLM Brain + Planning + Memory + Tools
```

```
┌──────────────────────────────────────────────────────────┐
│                        Agent Loop                        │
│                                                          │
│  用户输入 ──→ [感知] ──→ [规划/推理] ──→ [行动]           │
│                  ↑              │           │            │
│                  └── [记忆] ←──┘    [工具调用]           │
│                                       │                  │
│                               [环境/外部系统]             │
│                                       │                  │
│                  ←─────── [观察结果] ←┘                  │
└──────────────────────────────────────────────────────────┘
```

## 二、Planning（规划）

### 2.1 核心作用

Planning 是 Agent 的"大脑"，负责：
- 分析当前状态与目标差距
- 将复杂任务拆解为可执行子步骤
- 决定调用哪些工具、以什么顺序执行

### 2.2 主流规划范式

#### Chain-of-Thought（CoT）
让模型逐步推理，在输出答案前先"想清楚"。

```
问题：如果 5 个人各有 3 个苹果，总共多少苹果？
CoT：5 个人 × 每人 3 个 = 15 个苹果。
答案：15
```

#### ReAct（Reasoning + Acting）
交替进行思考（Thought）和行动（Action），每步观察（Observation）结果后更新推理。

```
循环：Thought → Action → Observation → Thought → ...

Thought: 需要查询北京今天的天气
Action: search("北京今天天气")
Observation: 北京今天晴，25°C
Thought: 已获取天气信息，可以回答用户
Action: finish("北京今天晴，气温25°C")
```

#### ReWOO（Reasoning WithOut Observation）
提前制定完整计划，再并行执行，适合可预见的任务流。

```
Planner（规划器）: 制定完整步骤列表
    步骤1: 搜索 X
    步骤2: 搜索 Y
    步骤3: 综合 步骤1、步骤2 的结果

Worker（工作器）: 并行执行每个步骤
Solver（求解器）: 汇总结果，输出最终答案
```

优点：减少 LLM 调用次数，降低延迟和成本。

#### Tree of Thoughts（ToT）
探索多个推理路径，选择最优路径。

```
                根问题
               /  |  \
           路径A 路径B 路径C
           / \         |
         A1  A2       C1
         ✓              ✗
```

#### Reflexion（反思）
Agent 执行后对结果进行自我评估，生成反思记忆供下一轮使用。

```
执行 → 评估结果 → 生成反思 → 存入记忆 → 重新规划
```

### 2.3 查询分解（Query Decomposition）

```typescript
// 复杂任务分解示例
const complexTask = "帮我分析竞争对手A、B、C的产品定价策略并给出建议";

const subtasks = [
  "搜索竞争对手A的产品定价信息",
  "搜索竞争对手B的产品定价信息",
  "搜索竞争对手C的产品定价信息",
  "对比分析三家定价策略的异同",
  "结合市场情况生成定价建议"
];
```

## 三、Memory（记忆系统）

### 3.1 记忆类型对比

| 类型 | 对应人类记忆 | 技术实现 | 生命周期 |
|---|---|---|---|
| **感知记忆** | 感官输入 | 当前 Prompt / 输入 | 单次请求 |
| **短期记忆** | 工作记忆 | 对话历史（上下文窗口）| 单次会话 |
| **长期记忆** | 陈述性记忆 | 向量数据库、KV 存储 | 持久化 |
| **程序性记忆** | 技能记忆 | 微调模型参数 | 永久（模型内）|

### 3.2 短期记忆管理

上下文窗口有限，需要策略管理对话历史：

```typescript
// 对话历史压缩策略
class ConversationMemory {
  private messages: Message[] = [];
  private maxTokens = 4000;

  // 策略1：滑动窗口（保留最近 N 轮）
  slidingWindow(keepLast: number) {
    this.messages = this.messages.slice(-keepLast * 2);
  }

  // 策略2：摘要压缩（用 LLM 总结历史）
  async summarize() {
    const summary = await llm.summarize(this.messages);
    this.messages = [{ role: 'system', content: `历史摘要: ${summary}` }];
  }

  // 策略3：重要性筛选（保留关键消息）
  filterByImportance() {
    this.messages = this.messages.filter(m => m.importance > 0.7);
  }
}
```

### 3.3 长期记忆（向量数据库）

```
存储流程：
文本 → 嵌入模型（Embedding Model）→ 向量 → 向量数据库

检索流程：
查询文本 → 向量化 → 相似性搜索（余弦相似度）→ Top-K 结果
```

**主流向量数据库对比：**

| 数据库 | 特点 | 适用场景 |
|---|---|---|
| Chroma | 轻量、本地友好、Python 原生 | 开发测试、小规模应用 |
| Pinecone | 云原生、高性能、托管服务 | 生产环境、大规模 |
| Weaviate | 支持混合搜索（向量+关键词）| 企业级知识库 |
| Qdrant | Rust 实现、高性能、自托管 | 私有化部署 |
| Milvus | 大规模分布式、开源 | 超大规模场景 |

### 3.4 记忆的实际应用

```typescript
// mem0 风格的 Agent 记忆管理
class AgentMemory {
  async remember(userId: string, fact: string) {
    const embedding = await embed(fact);
    await vectorDB.upsert({ userId, text: fact, vector: embedding });
  }

  async recall(userId: string, query: string, topK = 5) {
    const queryVec = await embed(query);
    return await vectorDB.search({ userId, vector: queryVec, topK });
  }

  async forget(userId: string, factId: string) {
    await vectorDB.delete({ userId, id: factId });
  }
}
```

## 四、Tools（工具系统）

### 4.1 工具的作用

工具让 Agent 突破 LLM 静态知识的边界：

| 工具类型 | 示例 | 解决的问题 |
|---|---|---|
| **搜索工具** | Tavily、Bing Search | 实时信息、最新数据 |
| **代码执行** | Python REPL | 数学计算、数据分析 |
| **数据库查询** | SQL、MongoDB | 私有业务数据 |
| **文件操作** | 读写文件、PDF解析 | 处理本地/远程文档 |
| **API 调用** | 天气、地图、支付 | 第三方服务集成 |
| **向量检索** | RAG 检索器 | 知识库查询 |
| **浏览器控制** | Playwright、Selenium | 网页操作、数据抓取 |

### 4.2 工具定义示例

```typescript
// LangChain 风格的工具定义
import { DynamicStructuredTool } from "@langchain/core/tools";
import { z } from "zod";

const searchTool = new DynamicStructuredTool({
  name: "web_search",
  description: "搜索互联网获取最新信息，当需要实时数据或不确定知识时使用",
  schema: z.object({
    query: z.string().describe("搜索关键词"),
    maxResults: z.number().optional().describe("返回结果数量，默认5")
  }),
  func: async ({ query, maxResults = 5 }) => {
    const results = await tavilyClient.search(query, { maxResults });
    return JSON.stringify(results);
  }
});
```

### 4.3 工具选择策略

Agent 决定调用哪个工具的决策过程：

```
用户输入 → LLM 分析意图 → 匹配工具列表
                              ↓
                    生成工具调用 JSON
                    {
                      "tool": "web_search",
                      "args": { "query": "..." }
                    }
                              ↓
                    执行工具 → 获取结果 → 继续推理
```

## 五、RAG（检索增强生成）

### 5.1 为什么需要 RAG？

| 问题 | RAG 解决方案 |
|---|---|
| LLM 知识有截止日期 | 实时检索最新文档 |
| 无法访问私有数据 | 构建私有知识库 |
| 模型幻觉 | 基于真实文档生成 |
| 无法引用来源 | 检索结果可溯源 |

### 5.2 标准 RAG 流程

```
离线阶段（索引）：
文档 → 分块（Chunking）→ 嵌入（Embedding）→ 存入向量数据库

在线阶段（检索生成）：
用户问题 → 向量化 → 相似度检索 → Top-K 文档
              ↓
    组装 Prompt（问题 + 上下文）→ LLM → 回答
```

### 5.3 高级 RAG 技术

#### 查询优化
```typescript
// HyDE：生成假设性文档提升检索质量
async function hydeSearch(query: string) {
  // 先让 LLM 生成一个"假设性答案"
  const hypothetical = await llm.invoke(
    `请为以下问题生成一个详细答案（不必准确）：${query}`
  );
  // 用假设性答案去检索（语义更接近目标文档）
  return await vectorDB.search(hypothetical);
}
```

#### 重排序（Reranking）
```
初步检索 Top-20 → Cross-Encoder 重排序 → 保留 Top-5
（提高精确度，过滤噪声）
```

#### Agentic RAG
```
简单问题 → 直接 RAG 检索
复杂问题 → Agent 分解 → 多轮检索 → 综合推理 → 回答
```

#### GraphRAG（微软）
```
传统 RAG：基于文本相似度检索
GraphRAG：构建知识图谱 → 基于实体关系检索 → 支持全局推理
```

适用场景：跨文档关联分析、多跳推理问题。

### 5.4 RAG 评估指标

| 指标 | 定义 | 工具 |
|---|---|---|
| 检索相关性（Context Relevancy）| 检索到的文档与问题的相关程度 | RAGAS |
| 答案忠实度（Faithfulness）| 答案是否完全基于检索内容 | RAGAS |
| 答案相关性（Answer Relevancy）| 答案是否回答了问题 | RAGAS |
| 上下文召回（Context Recall）| 是否检索到所有相关内容 | RAGAS |

## 六、Reasoning（推理）详解

### 6.1 Think-Act-Observe 循环

```
┌─────────────────────────────────────────┐
│                                         │
│  Think（思考）: 分析当前状态，决定下一步   │
│        ↓                                │
│  Act（行动）: 调用工具或生成输出          │
│        ↓                                │
│  Observe（观察）: 获取行动结果            │
│        ↓                                │
│  更新上下文 → 返回 Think                 │
│                                         │
└─────────────────────────────────────────┘
```

### 6.2 Self-Reflection（自我反思）

```typescript
// 反思式 Agent 伪代码
async function reflectiveAgent(task: string) {
  let result = await execute(task);
  
  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    const evaluation = await llm.evaluate({
      task,
      result,
      prompt: "评估此结果是否正确完成了任务？列出存在的问题。"
    });
    
    if (evaluation.isCorrect) break;
    
    // 将反思存入记忆，指导下一次尝试
    await memory.add(`反思：${evaluation.issues}`);
    result = await execute(task, memory.getRelevant(task));
  }
  
  return result;
}
```

### 6.3 推理框架选择指南

| 场景 | 推荐框架 | 理由 |
|---|---|---|
| 简单问答、工具调用 | ReAct | 通用性强，实现简单 |
| 复杂多步骤任务 | ReWOO | 减少 LLM 调用，并行执行 |
| 需要探索多方案 | Tree of Thoughts | 广度搜索最优路径 |
| 需要错误修复 | Reflexion | 自我改进，持续优化 |
| 数学/代码推理 | CoT + 代码执行 | 结合符号推理 |
