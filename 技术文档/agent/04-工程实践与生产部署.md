> 从开发到生产：可观测性、评估体系、Prompt 管理、部署方案

## 一、工程化核心原则

> 从第一天起就规划：**可观测性、评估体系、成本控制、回滚策略、人工审核机制**

Agent 工程化的最大挑战：
- LLM 输出不确定，难以用传统方式测试
- 多步骤执行，错误难以定位
- 工具调用链路复杂，成本难以预测
- 生产环境行为与测试环境可能不一致

## 二、可观测性（Observability）

### 2.1 为什么 Agent 特别需要可观测性？

```
普通 Web 应用：请求 → 处理 → 响应（单步，易调试）

Agent 应用：
用户输入
  → LLM 推理（思考）
  → 工具调用 A（搜索）
  → LLM 分析结果（再推理）
  → 工具调用 B（数据库查询）
  → LLM 综合（最终推理）
  → 输出
  
任何一步出错，都需要能"看见"每一步发生了什么
```

### 2.2 可观测性核心维度

| 维度 | 监控内容 | 意义 |
|---|---|---|
| **Trace（轨迹）** | 每次 LLM 调用的完整输入输出 | 定位推理失误 |
| **工具调用** | 哪个工具、什么参数、返回什么 | 发现工具使用问题 |
| **Token 用量** | 每步消耗的 token 数 | 成本控制 |
| **延迟** | 每步耗时、总耗时 | 性能优化 |
| **错误率** | 工具调用失败率、LLM 错误率 | 稳定性监控 |
| **用户反馈** | 点赞/踩、明确评分 | 质量感知 |

### 2.4 自定义监控指标

```typescript
// 关键指标收集
class AgentMetrics {
  private metrics: Map<string, number[]> = new Map();

  record(metric: string, value: number) {
    if (!this.metrics.has(metric)) this.metrics.set(metric, []);
    this.metrics.get(metric)!.push(value);
  }

  async trackAgentRun(agentFn: () => Promise<string>, runId: string) {
    const start = Date.now();
    let tokenCount = 0;
    let toolCallCount = 0;

    try {
      const result = await agentFn();
      const latency = Date.now() - start;
      
      this.record("latency_ms", latency);
      this.record("token_count", tokenCount);
      this.record("tool_calls", toolCallCount);
      this.record("success_rate", 1);
      
      return result;
    } catch (err) {
      this.record("success_rate", 0);
      this.record("error_count", 1);
      throw err;
    }
  }
}
```

## 三、评估体系（Evaluation）

### 3.1 Agent 评估的难点

| 挑战 | 描述 |
|---|---|
| 无确定答案 | 同一问题有多种正确回答 |
| 过程重要性 | 结果对但推理过程错了也是问题 |
| 多步骤 | 哪一步出错的评估很复杂 |
| 成本 | 每次评估都要消耗 LLM token |

### 3.2 评估维度

```
最终输出评估：
  ├── 事实准确性（Faithfulness）
  ├── 答案相关性（Answer Relevancy）
  └── 完整性（Completeness）

过程评估：
  ├── 工具选择正确性（Tool Selection Accuracy）
  ├── 工具调用顺序合理性
  └── 无效工具调用次数

效率评估：
  ├── 总 token 消耗
  ├── 工具调用次数
  └── 端到端延迟

安全评估：
  ├── 有害内容过滤
  └── 提示注入防护
```

### 3.3 评估实现方式

#### 方式1：基于规则的评估（最快、最便宜）
```typescript
// 关键词检查、格式验证
function ruleBasedEval(output: string, expectedKeywords: string[]) {
  return {
    score: expectedKeywords.filter(kw => output.includes(kw)).length 
           / expectedKeywords.length,
    passed: expectedKeywords.every(kw => output.includes(kw))
  };
}
```

#### 方式2：LLM Judge（最灵活）
```typescript
// 用另一个 LLM 评估输出质量
async function llmJudge(question: string, answer: string, criteria: string) {
  const evaluation = await openai.chat.completions.create({
    model: "gpt-4o",  // 评估模型通常选更强的
    messages: [{
      role: "user",
      content: `请评估以下回答的质量（1-10分）
问题：${question}
回答：${answer}
评估标准：${criteria}
请给出分数和理由，格式：{"score": X, "reason": "..."}`
    }]
  });
  return JSON.parse(evaluation.choices[0].message.content!);
}
```

#### 方式3：RAGAS（RAG 专用评估）

## 四、Prompt 工程与版本管理

### 4.1 System Prompt 设计原则

```
好的 System Prompt 包含：
1. 角色定义：你是谁、你的专长是什么
2. 任务边界：你能做什么、不能做什么
3. 行为规范：输出格式、语气风格
4. 工具使用指引：何时使用哪个工具
5. 错误处理：遇到不确定情况如何处理
```

```typescript
const SYSTEM_PROMPT = `你是一位专业的数据分析助手。

## 你的能力
- 分析 CSV、Excel、JSON 格式的数据文件
- 生成统计摘要和可视化图表
- 回答数据相关的业务问题

## 工具使用原则
- 当用户上传文件时，始终先用 read_file 工具读取内容
- 数学计算使用 python_repl 工具，不要自行计算
- 不确定数据真实性时，明确告知用户

## 输出格式
- 分析结果使用 Markdown 格式
- 数字结果保留2位小数
- 始终提供结论摘要

## 边界
- 不处理个人隐私数据（身份证号、银行卡号等）
- 不生成或执行会修改生产数据的操作`;
```

## 五、成本控制

### 5.1 主要成本来源

| 来源 | 占比（典型）| 优化方向 |
|---|---|---|
| LLM 推理 | 60-80% | 模型降级、缓存、减少调用 |
| 工具调用 | 10-20% | 缓存、批处理 |
| 向量数据库 | 5-10% | 本地缓存、分层存储 |
| 嵌入模型 | 5% | 批量嵌入、缓存 |

### 5.2 成本优化策略

```typescript
// 1. 语义缓存（相似问题复用答案）
import { RedisSemanticCache } from "@langchain/community/caches/ioredis";

const cache = new RedisSemanticCache({
  redisClient: redis,
  embeddingsTTL: 3600,        // 缓存 1 小时
  similarityThreshold: 0.95   // 相似度超过 95% 视为命中
});

// 2. 模型路由（简单问题用便宜模型）
async function routeToModel(query: string, complexity: number) {
  if (complexity < 0.3) {
    return "gpt-4o-mini";   // 简单问题：便宜 10x
  } else if (complexity < 0.7) {
    return "gpt-4o";
  } else {
    return "claude-opus-4-6";  // 复杂问题：最强
  }
}

// 3. 工具调用结果缓存
const toolCache = new Map<string, { result: string; expiry: number }>();

async function cachedToolCall(toolName: string, args: object) {
  const key = `${toolName}:${JSON.stringify(args)}`;
  const cached = toolCache.get(key);
  
  if (cached && cached.expiry > Date.now()) {
    return cached.result;  // 缓存命中
  }
  
  const result = await executeTool(toolName, args);
  toolCache.set(key, { result, expiry: Date.now() + 300_000 }); // 5分钟
  return result;
}

// 4. 限制工具调用次数
const MAX_TOOL_CALLS = 10;
let toolCallCount = 0;

// 在 Agent 循环中检查
if (toolCallCount >= MAX_TOOL_CALLS) {
  return "已达到最大工具调用次数，当前信息：" + currentContext;
}
```

## 六、安全与可靠性

### 6.1 Prompt 注入防护

```typescript
// 输入清洗
function sanitizeInput(userInput: string): string {
  // 移除可能的系统指令注入
  const dangerousPatterns = [
    /ignore previous instructions/i,
    /system:/i,
    /\[INST\]/i,
    /<\|system\|>/i
  ];
  
  let sanitized = userInput;
  for (const pattern of dangerousPatterns) {
    sanitized = sanitized.replace(pattern, "[filtered]");
  }
  return sanitized;
}

// 输出验证
function validateOutput(output: string, allowedActions: string[]) {
  // 检查 Agent 是否试图执行未授权操作
  const requestedActions = extractActions(output);
  return requestedActions.every(action => allowedActions.includes(action));
}
```

### 6.2 工具权限控制

```typescript
// 工具沙箱 - 限制危险操作
const toolPermissions: Record<string, Permission[]> = {
  "read_file": ["filesystem:read"],
  "write_file": ["filesystem:write"],      // 需要额外权限
  "execute_code": ["sandbox:execute"],     // 沙箱执行
  "send_email": ["email:send"],            // 需要人工确认
  "delete_record": ["db:write", "human:approve"]  // 必须人工审核
};

async function executeToolWithPermission(
  toolName: string,
  args: object,
  userPermissions: Permission[]
) {
  const required = toolPermissions[toolName] ?? [];
  const hasPermission = required.every(p => userPermissions.includes(p));
  
  if (!hasPermission) {
    throw new Error(`权限不足：执行 ${toolName} 需要 ${required.join(", ")}`);
  }
  
  return await executeTool(toolName, args);
}
```

### 6.3 Human-in-the-Loop

```typescript
// LangGraph 中的人工介入节点
import { interrupt } from "@langchain/langgraph";

async function criticalActionNode(state: AgentState) {
  const action = state.plannedAction;
  
  // 触发人工审核
  const approval = interrupt({
    message: `Agent 准备执行以下操作，请确认：`,
    action: action,
    impact: assessImpact(action),  // 评估影响范围
    options: ["approve", "reject", "modify"]
  });
  
  if (approval.decision === "approve") {
    return await executeAction(action);
  } else if (approval.decision === "modify") {
    return { plannedAction: approval.modifiedAction };
  } else {
    return { status: "cancelled", reason: approval.reason };
  }
}
```

### 7.2 FastAPI 封装 Agent

```typescript
// 使用 Hono（TypeScript 轻量框架）封装 Agent API
import { Hono } from "hono";
import { stream } from "hono/streaming";

const app = new Hono();

// 流式 Agent 接口
app.post("/agent/stream", async (c) => {
  const { message, sessionId } = await c.req.json();
  
  return stream(c, async (stream) => {
    const agent = createAgent(sessionId);
    
    for await (const event of agent.streamEvents(message)) {
      if (event.event === "on_chat_model_stream") {
        await stream.write(
          `data: ${JSON.stringify({ type: "text", delta: event.data.chunk.content })}\n\n`
        );
      } else if (event.event === "on_tool_start") {
        await stream.write(
          `data: ${JSON.stringify({ type: "tool_start", tool: event.name })}\n\n`
        );
      }
    }
    
    await stream.write("data: [DONE]\n\n");
  });
});
```
