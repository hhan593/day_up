# 28. 数据标注平台架构详解

> 本文是「智驾数据标注平台」（仓库 `nest-test/annotation-platform`）落地的架构回写，对应计划书《技术文档/数据标注平台/00-平台计划书.md》M0–M5 全部里程碑。
> 关联：`23-3D数学基础`（cuboid/变换链）、`24-WebGL渲染管线`（点云渲染）、`26/27`（格式规范与帧生成理论）

## 1. 平台定位

领域无关、配置驱动的训练数据标注生产平台，覆盖「数据接入 → 任务分配 → 标注 → 质检 → 版本化导出」闭环，支持 2D 图像 / 视频帧跟踪 / 3D 点云 / 融合一致性四类能力。

## 2. 总体架构

```
apps/web (React18+Vite+Konva+three.js) ──/api 代理──▶ apps/api (NestJS)
packages/annotation-core（框架无关标注引擎：Shape/History/几何）        │
packages/shared（zod DTO + 枚举 + 纯几何：IoU/投影/一致性）        Prisma ▼ PostgreSQL
apps/api modules：auth/users/projects/scenes/assets/tasks/          BullMQ ▶ Redis
  annotations/reviews/scenes/media(fusion)/export/storage      Workers：抽帧/导出
```

**领域无关的关键设计**：标签体系/标注工具/质检策略全部是 `Project.ontology / qcPolicy`（jsonb 配置），DB 不感知领域；标注数据形状由配置驱动（`AnnotationData.shapes` 是 bbox/cuboid 的 union）。

## 3. 模块职责（NestJS）

| 模块 | 职责 | 关键点 |
|------|------|--------|
| auth | JWT + RBAC（全局守卫链 JwtAuthGuard→RolesGuard） | `@Public()` 放行、`@Roles()` 鉴权 |
| projects | 项目=配置聚合根 | 本体/工具/冗余度/一致性阈值全在 jsonb |
| scenes | Scene/多传感器资产/标定/Track/插值/融合报告 | `POST /scenes/:id/assets` 图片·视频·bin 三分支 |
| assets | 上传、图片尺寸解析、自动建任务 | `image-size` 纯 JS 解析 |
| tasks | **生命周期状态机**（纯函数 `state-machine.ts`） | PENDING→ASSIGNED→IN_PROGRESS→SUBMITTED→APPROVED（±reject/reset） |
| annotations | 标注版本链（每次保存新 revision，parentRevisionId 链接） | ASSIGNED 首存自动转 IN_PROGRESS |
| reviews | 审核队列/驳回理由(ReviewRecord)/**冗余组一致性**/整组通过/驳回 | `consistencyReport` 纯函数（shared） |
| export | 格式策略注册表：COCO/YOLO/**KITTI**/**nuScenes** | `ExportFormatter` 接口 + BullMQ 异步 worker + zip |
| media | **ffmpeg 抽帧 worker**：视频→帧资产→逐帧任务 | `execFile` 超时保护、2fps/上限 60 帧 |
| fusion（scenes 内） | **3D→2D 投影一致性**：cuboid 8 顶点 K[R\|t] 投影 AABB vs 2D 框贪心匹配 | `fusionCheck` 纯函数（shared，精确单测） |
| storage | `StorageDriver` 抽象（Local 已实现，S3/MinIO 可插） | DIP：Symbol token 注入 |

## 4. SOLID 落点（同计划书 §5.2，已验证）

- **SRP**：tasks 只管状态流转；export 只管编排；fusion 只算投影比对
- **OCP**：新增导出格式=注册一个 Formatter（KITTI/nuScenes 即这样加进来的）；新增标注工具=前端 Tool 实现
- **LSP**：Local→S3 存储切换、格式器互换均不改调用方
- **ISP**：导出器只读 `AnnotationPage`；`PrelabelProvider` 只暴露 predict
- **DIP**：`STORAGE_DRIVER`/队列 token 注入抽象

## 5. 智驾核心流程（已端到端实测）

1. **2D 闭环**：上传→指派→Konva 工作台画框（撤销/重做/拖动）→提交→审核→COCO/YOLO zip（逐字段 golden 校验）。
2. **冗余一致性**：qcPolicy.redundancy=R → 每资产复制 R 任务（同 groupId）分给 R 人 → 全部提交后 `consistencyReport` 两两贪心匹配 IoU → 达标整组通过，否则整组驳回。
3. **视频跟踪**：场景传视频 → ffmpeg 2fps 抽帧（≤60 帧）→ 逐帧任务 → 帧工作台画框挂 TrackId → 两关键帧间 `interpolate` 线性插值 → 批量写入中间帧。
4. **3D 点云**：KITTI bin（float32×4）→ FRAME_3D 任务 → three.js 双视口（上 BEV 正交/下透视）→ cuboid 添加/TransformControls 平移旋转 → KITTI 15 列导出。
5. **融合一致性**：场景标定 K+外参 → 3D 框 8 顶点投影 AABB → 与相机 2D 框贪心匹配 IoU → 漏标/错标一屏可见。

## 6. 踩坑记录（对教学最有价值的部分）

| 坑 | 根因 | 解法 |
|----|------|------|
| 共享包 ESM/CJS 双端冲突 | api 需 CJS、vite 对链接包不预打包 | shared=CJS（api 用）；annotation-core=ESM（vite 直用） |
| pnpm 11 拦截依赖构建脚本 | 安全策略 | `pnpm-workspace.yaml` onlyBuiltDependencies 白名单 |
| zod 剥掉未知字段 | ValidationPipe whitelist + 无装饰器 DTO | DTO 统一走 `parseDto(schema, body)` |
| Prisma 枚举/关系变更不生效 | 手动迁移后忘 `prisma generate` / 进程缓存 | generate + touch 重启；1:1 关系需 `@unique` |
| three r169+ TransformControls | 不再是 Object3D | `scene.add(transform.getHelper())` |
| effect 空依赖 + 异步数据挂载 | mountRef 拿到 null 后永不重跑 | 依赖数组带 `!!task`（数据到达重建视口） |
| Nest 方法名与注入属性撞名 | `fusion` 属性 vs 方法 | 方法改名 `fusionReport` |

## 7. 数据模型（12 表）

User / Project(ontology+qcPolicy jsonb) / Scene / Calibration / Asset(scene+sensor+timestamp) / Frame / Task(groupId·frameId·sceneId) / TaskAssignment / Track / AnnotationRevision(版本链+trackId) / ReviewRecord / ExportJob —— ER 见计划书 §5.4。
