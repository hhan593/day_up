# 03 · 所有权与移动语义（Ownership）

> 体系定位：**Rust 最核心、最独特的机制**。理解了所有权，借用、生命周期、并发安全全部顺理成章。
> 深入借用：[04-借用与引用](./04-借用与引用.md)；速查：`补充知识点/05-借用与引用.md`。

---

## 1. 三条规则（背下来）

1. 每个值有且仅有一个**所有者（owner）**变量。
2. 同一时刻只能有一个所有者。
3. 当所有者离开作用域，值被自动 **drop**（释放内存）。

```rust
{
    let s = String::from("hello");  // s 是 owner
}                                       // 作用域结束，s 被 drop，内存释放
```

---

## 2. 移动（Move）：所有权转移

把值赋给另一个变量，默认是**移动**而非浅拷贝：

```rust
let s1 = String::from("hello");
let s2 = s1;            // 所有权从 s1 移到 s2
// println!("{s1}");   // ❌ s1 已失效（move 后不可用）
println!("{s2}");      // ✅
```

为什么不是拷贝？`String` 在堆上存数据，栈上只有指针/长度/容量三件套。若赋值成浅拷贝，两个变量指向同一块堆内存，离开作用域会**二次释放（double free）**——这是 C/C++ 经典内存安全问题。Rust 用"移动后令原变量失效"从编译期杜绝。

> 在浏览器/Node 这类有 GC 的语言里你不需关心这些；Rust 选择无 GC 的确定性释放，代价就是这条规则。

---

## 3. 栈上的 Copy 类型例外

实现了 `Copy` trait 的类型（整数、浮点、`bool`、`char`、以及全 `Copy` 字段的元组/数组）**赋值即复制，不移动**：

```rust
let x = 5;
let y = x;     // i32 是 Copy，复制一份
println!("{x} {y}");  // 都可用
```

`Copy` vs `Move` 速判：类型是否在堆上拥有数据？
- 纯栈数据（`i32` / `f64` / `(i32,i32)` / `[i32;3]`）→ 往往 `Copy`。
- 拥有堆数据（`String` / `Vec` / `Box`）→ 默认 `Move`。

细节：`补充知识点/03-结构体语法.md` 讲 `Copy` 的 derive 条件。

## 4. 函数传参与返回

```rust
fn take(s: String) {}      // 拿到所有权
fn give() -> String { String::from("x") }  // 返回所有权

let s = String::from("a");
take(s);                   // s 被移动进函数，之后不可用
let s2 = give();           // 所有权从函数返回
```

**返回以"转移所有权"是 Rust 返回大对象的零成本方式**——没有拷贝，只是移动栈上的三件套。

克隆（显式，有成本）：

```rust
let s1 = String::from("hi");
let s2 = s1.clone();   // 深拷贝堆数据，s1 仍可用（但要付 O(n) 代价）
```

## 5. drop 与 RAII

Rust 用 **RAII**（资源获取即初始化）：值离开作用域自动 `drop`。文件、锁、数据库连接都靠这个确定性释放——不需要 `finally` / `defer` / GC：

```rust
{
    let f = File::open("x.txt").unwrap();
    // 使用 f ...
}   // f 在这里确定性关闭，无论是否发生错误
```
