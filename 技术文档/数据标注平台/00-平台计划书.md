# A 线 · 知识文档计划

## 26. 数据标注体系与格式规范（→ 文档 26 篇）

1. **标注类型全景**：2D 检测框 / 多边形分割 / 3D cuboid / 点云分割 / 跟踪（MOT）/ 车道线 / 可行驶区域——每类配智驾语境示例（车辆、行人、骑行者、红绿灯…）。
2. **智驾数据集的组织方式**：Scene/Clip（一次 10–30s 同步采集）→ Sample（时刻）→ 多传感器数据（1×LiDAR + 4–8×相机）；本体（ontology）设计：动态目标 3D 框 + 类别 + 遮挡/截断属性，静态元素（车道线、标志）。
3. **格式规范逐字段拆解**（平台导出模块的规格来源，按智驾优先级排序）：
   - **KITTI**：label txt 字段表（15 列）、calib 投影文件、velodyne bin 结构；
   - **nuScenes**：表结构（sample/sample_data/sample_annotation/scene/calibrated_sensor…）、token 关联体系、23 类 taxonomy；
   - **COCO / YOLO**：相机 2D 框通用格式（bbox 约定、segmentation RLE）；
   - 自定义 JSON → 上述格式互转的坑（坐标系/朝向角定义差异）。
4. **质量管理（智驾特化）**：一致性度量（3D IoU / BEV IoU、Hungarian 匹配）、跟踪 ID 连续性检查、**融合一致性**（3D 框投影到相机 vs 2D 框交叉验证）、金标准、仲裁。
5. **预标注与主动学习**：检测/跟踪模型预标 → 人工修正 → 回流训练的飞轮。

## 27. 3D 标注与帧生成（→ 文档 27 篇）

1. **LiDAR 与点云基础**：旋转式/固态雷达原理、bin/pcd 数据布局、强度通道、点云渲染（WebGL 大规模 Points 的 LOD 策略）。
2. **3D 标注核心**：cuboid 7 自由度（x,y,z,w,l,h,yaw）、地面拟合与吸附、BEV 俯视 + 透视双视口联动工作流。
3. **标定（智驾标注的数学核心）**：
   - 内参 K、外参 `[R|t]`；**相机-LiDAR 联合投影** `p_cam = K·[R|t]·p_lidar`；
   - 时间同步（硬件触发/软同步）、外参误差对融合标注的影响；
   - 3D 框 8 顶点投影像素多边形（融合校验的原理）。
4. **帧生成（三层含义）**：
   - ① **视频抽帧**：FFmpeg 命令、关键帧/场景切分策略对数据分布的影响；
   - ② **关键帧标注 + 插值**：跟踪场景下标关键帧、线性插值补中间帧、Track ID 保持；
   - ③ **合成数据生成**：用 Three.js 做智驾街景 domain randomization（道路/车辆/行人/光照随机化），渲染即得**完美真值**（3D 框零误差），sim-to-real 缓解思路。
5. **配套示例**（`~/threejs/examples/26-annotation/`）：

| 示例 | 内容 | 覆盖知识点 |
|------|------|-----------|
| `01-synthetic-driving-scene.html` | Three.js 智驾街景生成器：路面 + 随机车辆/行人位姿 + 模拟 LiDAR 点云 → 一键导出 KITTI 3D 框 + COCO 2D 框 JSON | 合成帧生成 + 自动标注 |
| `02-3d-box-projection.html` | 3D cuboid 经 `K[R\|t]` 投影到相机图像，8 顶点连线 + 与 2D 框 IoU 对比 | 联合标定、融合一致性 |
| `03-track-interpolation.html` | 两个关键帧间拖动框，中间帧自动插值 + Track ID 颜色标识 | 跟踪标注、帧生成 |

# B 线 · 数据标注平台方案（v1，智驾重心）

## 1. 目标与范围

**一句话**：面向智驾训练数据集的标注生产平台，覆盖「多传感器数据接入 → 场景/任务分配 → 标注（2D/3D/时序）→ 质检（含融合一致性）→ KITTI/nuScenes/COCO 版本化导出」闭环。

| 需求 | 说明 |
|------|------|
| 项目即配置 | 标注本体（车辆/行人/骑行者…）、工具类型、质检策略是 Project 配置（jsonb），架构领域无关 |
| **场景数据组织** | Scene → 多传感器 Asset（LiDAR bin / 相机图，带时间戳与标定引用），支持整段上传与单帧上传 |
| 2D 相机标注 | 矩形框/多边形/关键点，支持 8 相机独立标注与属性面板 |
| **3D 点云标注** | cuboid 7DoF、地面吸附、BEV+透视双视口、强度着色、LOD 大点云 |
| 时序与跟踪 | 关键帧标注 + 插值补帧、Track ID 管理（连续性自动校验） |
| **融合一致性校验** | 3D 框按标定投影到各相机，与 2D 框自动算 IoU，低于阈值进人工复核队列 |
| 质检工作流 | 提交 → 审核 → 驳回/通过 → 仲裁；抽样率、金标准、多人冗余可配 |
| 格式导出 | **KITTI / nuScenes 优先**，COCO/YOLO（相机 2D）次之；异步任务+进度 |
| 预标注接入 | KITTI/nuScenes 标注文件导入；HTTP 适配检测/跟踪模型服务 |
| 进度统计 | 场景/批次/标注员维度：完成量、驳回率、一致性分 |

**Non-goals（v1 不做）**：在线标定工具（只消费标定结果）、点云语义分割画笔、车道线矢量标注、模型训练、众包结算。

## 2. 角色与核心工作流

**角色（RBAC）**：`ADMIN`、`MANAGER`（建项目/分配/审核）、`ANNOTATOR`（2D/3D/时序标注）、`REVIEWER`（质检）。

**任务状态机**（轻量 transitions map，不引重型库）：

```
                    ┌───────── 驳回（带理由）─────────┐
                    ▼                               │
pending ──分配──▶ assigned ──开始──▶ in_progress ──提交──▶ submitted
   ▲                                                        │
   │                       审核通过 ──▶ approved ──┐        审核
   └────────── 管理员重置（数据/配置变更）──────────┼────────┘
                                                  ▼
                                            可导出（locked）
```

- 智驾扩展：驳回理由常量化（漏标/类别错/框贴合度/朝向错/ID 跳变），统计驳回原因分布反哺标注规范；
- 冗余模式：同任务派 N 份 → 3D IoU 一致性比对 → 达标自动通过，否则仲裁。

## 3. 总体架构

```
┌───────────────────────────┐        ┌────────────────────────────────┐
│   apps/web (React+Vite)   │  REST  │        apps/api (NestJS)       │
│   Zustand + React Query   │◄──────▶│  modules/*（见 §5）             │
│   annotation-core 引擎     │   WS   │    │ Prisma       │ BullMQ     │
│   ├─ 2D: Konva            │        │    ▼              ▼            │
│   ├─ 3D: three.js 点云+cuboid │    │ PostgreSQL     Redis          │
│   └─ 时序: 帧轨道+插值      │        │                ▼               │
└───────────────────────────┘        │  Workers：抽帧 / 点云LOD分块 /   │
                                     │  导出 / 预标注 / 融合一致性计算   │
                                     └────────────┬───────────────────┘
                                                  ▼
                                     MinIO（S3 兼容：bin/图片/产物）
```

同步 REST + 异步队列双路径；WS 推任务流转/导出/点云处理进度。

## 4. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | **NestJS 10**（指定） | 模块化 DI 贴合 SOLID |
| ORM/DB | Prisma + PostgreSQL | jsonb 存标定矩阵/标签体系/标注数据；关系表管场景-传感器-任务 |
| 队列 | BullMQ + Redis | 抽帧/点云分块/导出/预标注全部异步 |
| 对象存储 | MinIO（S3 API） | bin/pcd/图片大文件自托管；`StorageDriver` 抽象可换云 |
| 实时 | Socket.IO 网关 | 进度推送 |
| 前端 | React 18 + Vite + TS | Zustand（UI 态）+ React Query（服务端态） |
| 2D 标注 | Konva.js | Canvas 场景图，框/多边形/关键点 |
| **3D 点云** | **three.js** | 复用 23 篇变换链/24 篇管线知识；Points + 双视口 |
| 校验 | zod（shared）+ class-validator | 前后端同一份 DTO 类型 |
| 工程 | pnpm monorepo + turbo | 一仓三包 |
| 部署 | docker-compose | pg/redis/minio/api/web 一键起 |

## 5. 后端模块划分（NestJS）与 SOLID 映射

### 5.1 模块清单（依赖方向单向）

| 模块 | 职责（单一） | 主要接口 | 依赖 |
|------|-------------|---------|------|
| `auth` | JWT、RBAC 守卫 | `/auth/*` | users |
| `users` | 用户与角色 | `/users` | — |
| `projects` | **项目=配置聚合根**：标注本体、工具类型、质检策略（抽样/冗余/IoU阈值） | `/projects` | — |
| `scenes` | **智驾场景组织**：Scene、多传感器 Asset 挂接、Calibration 管理（内参/外参 JSON 校验） | `/scenes`、`/scenes/:id/assets`、`/calibrations` | projects |
| `assets` | 上传/签名 URL；视频→抽帧队列；点云→LOD 分块队列 | `/assets` | storage, queue |
| `tasks` | 生命周期状态机、分配（轮询/负载/指定）、冗余派发；任务粒度=单帧2D / 单帧3D / 整段跟踪 | `/tasks`、`/tasks/:id/transition` | scenes, assets |
| `annotations` | 标注 CRUD + revision 版本链；**Track 管理**（ID 分配/合并/连续性检查） | `/tasks/:id/annotations`、`/tracks` | tasks |
| `reviews` | 审核/驳回/仲裁；**融合一致性任务**（3D 投影 vs 2D IoU）结果入队 | `/reviews/*` | tasks, annotations, queue |
| `export` | 导出编排：KITTI/nuScenes/COCO/YOLO formatter 策略表 | `/export/jobs` | annotations, queue, storage |
| `prelabel` | KITTI/nuScenes 标注导入；HTTP 模型适配器批量预标 | `/prelabel/jobs` | assets, queue |
| `media`（worker） | ffmpeg 抽帧；**点云 bin → LOD 分块二进制**（供前端流式加载） | 队列消费 | queue, storage |
| `fusion`（worker） | 按标定把 3D 框投影到相机、与 2D 框 IoU 比对，产出一致性报告 | 队列消费 | queue, annotations |
| `events` | WS 网关：task.updated / export.progress / lidar.ready | `/socket` | — |

**横切**：`prisma`、`storage`（Local/S3 两实现）、`queue`、`common`（分页/异常过滤器/审计日志）。

### 5.2 SOLID 映射

| 原则 | 落点 |
|------|------|
| **SRP** | 模块即边界：`scenes` 只管数据组织、`tasks` 只管状态流转、`fusion` 只管投影比对、`export` 只管编排 |
| **OCP** | 新增导出格式=注册新 `ExportFormatter`；新增标注工具=前端 `Tool` 实现+项目配置枚举；新增雷达/相机厂商差异=资产解析器注册——核心零修改 |
| **LSP** | `StorageDriver`/`ExportFormatter`/`PrelabelProvider`/`PointCloudDecoder` 实现可互换 |
| **ISP** | 接口按消费方切割：导出器只读 `AnnotationPage`；`PrelabelProvider` 只暴露 `predict()` |
| **DIP** | service 依赖 `STORAGE_DRIVER`、`EXPORT_FORMATTERS`、`POINTCLOUD_DECODER` 抽象 token（Nest DI） |

### 5.3 核心抽象（示意）

```ts
export interface StorageDriver { /* put/getSignedUrl/delete */ }
export const STORAGE_DRIVER = Symbol('STORAGE_DRIVER');

export interface ExportFormatter {
  readonly format: 'kitti' | 'nuscenes' | 'coco' | 'yolo';
  render(page: AnnotationPage, ctx: ExportContext): AsyncIterable<ExportArtifact>;

export interface PointCloudDecoder {        // OCP：不同雷达原始格式
  decode(buffer: Buffer): Promise<{ points: Float32Array; intensity: Float32Array }>;

}
```

### 5.4 数据模型（Prisma，核心 12 表）

```
User(id, email, passwordHash, role)
Project(id, name, taskType: 'CAMERA_2D'|'LIDAR_3D'|'FUSION_TRACK',
        ontology jsonb,        -- 智驾本体：类别/属性(遮挡/截断)/工具/快捷键
        qcPolicy jsonb)        -- 抽样率、冗余度、IoU 阈值
Scene(id, projectId, name, location, weather?, meta jsonb)   -- 一次采集片段
Calibration(id, projectId, sensorName, kind: 'CAMERA'|'LIDAR',
            intrinsics jsonb,   -- K (3x3) / lidar 为空
            extrinsics jsonb)   -- 4x4，ego/lidar/cam 坐标系约定注明
Asset(id, sceneId?, projectId, kind: 'IMAGE'|'VIDEO'|'LIDAR_BIN'|'PCD',
      sensorName, timestampUs, storageKey, meta jsonb, lodKey?)  -- lodKey=分块产物
Frame(id, assetId, index, storageKey, timestampUs)            -- 视频抽出的帧
Task(id, projectId, sceneId?, assetId, frameId?, assigneeId?, status,
     taskKind: 'IMAGE_2D'|'FRAME_3D'|'TRACK_SEQ', priority)
TaskAssignment(id, taskId, annotatorId, round)
Track(id, sceneId, category, sourceTaskId)                    -- 跨帧目标
AnnotationRevision(id, taskId, assignmentId, authorId, data jsonb,
                   trackId?, parentRevisionId, createdAt)
ReviewRecord(id, taskId, reviewerId, decision, reasonCode, comment, score?)
ExportJob(id, projectId, format, filter jsonb, status, artifactKey, stats jsonb)
```

> `AnnotationRevision.data` 的形状由 `Project.ontology` 驱动（如 3D 框 = `{category, position[3], size[3], yaw, trackId, attrs{occlusion,truncation}}`），DB 不感知领域——领域无关的落点。

三个工作台：
1. **2D 相机台**（Konva）：缩放平移、框/多边形/关键点、预标注载入、遮挡/截断属性；
2. **3D 点云台**（three.js）：LOD 流式点云、BEV 正交 + 透视双视口联动、cuboid 7DoF 编辑（地面吸附/朝向盘）、强度着色；
3. **时序跟踪台**：传感器时间轴 + 帧轨道，关键帧打点、线性插值预览、Track ID 列表与跳变告警。

**融合审核台**：点云 3D 框选中 → 自动叠加显示其投影到各相机的多边形 vs 已有 2D 框 → IoU 低亮红，一键驳回。

## 8. 一次智驾标注的完整数据流

```
Manager 建项目（本体=车辆/行人/骑行者…，任务类型=FUSION_TRACK）
 → 上传 Scene：LiDAR bin ×N + 相机图 ×6N + calib.json
 → assets 入 MinIO；点云队列 LOD 分块；视频队列抽帧
 → 按帧生成 FRAME_3D 任务 / 按 Track 生成 TRACK_SEQ 任务 → 派发
 → Annotator 打开 3D 台：点云加载 → 画 cuboid（地面吸附）→ 挂 Track
 → 提交 → fusion worker：3D 框投影 6 相机 → 与 2D 框 IoU → 报告
 → Reviewer 在融合台复核（投影对齐可视化）→ 通过/驳回
 → Manager 导出 KITTI/nuScenes → formatter（含 calib 表）→ MinIO 产物
 → 签名 URL 下载 → 训练管线
```

## 9. 里程碑与验收（智驾优先级排序）

| 里程碑 | 内容 | 验收标准 | 预估 |
|--------|------|---------|------|
| **M0** 脚手架 | monorepo、compose、auth+RBAC、CI | 一键起、可登录 | 2 天 |
