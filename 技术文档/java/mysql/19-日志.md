# 19 - 日志

> 目标：掌握错误日志、binlog、查询日志、慢查询日志，理解两阶段提交。

---

## 19.1 四类日志

| 日志 | 作用 | 默认 |
|------|------|------|
| **错误日志 Error Log** | 记录启动、运行、关闭的错误信息 | 开启 |
| **二进制日志 Binlog** | 记录所有**数据变更**（DDL/DML） | 8.0 默认开启 |
| 查询日志 General Log | 记录所有 SQL（含查询） | 关闭（性能影响大） |
| **慢查询日志 Slow Log** | 记录执行超时的 SQL | 关闭（建议开） |

---

## 19.2 错误日志

```sql
show variables like 'log_error';
-- 默认位置：数据目录下 hostname.err
```

排查**启动失败、崩溃、连接错误**首先看它。

---

## 19.3 二进制日志 binlog

### 作用

- **主从复制**（从库读取主库 binlog 重放）。
- **数据恢复**（基于时间点恢复到某个时刻）。

### 格式

| 格式 | 说明 |
|------|------|
| `STATEMENT` | 记录 SQL 语句（函数/随机可能不一致） |
| `ROW` | 记录每行的变更（**推荐**，安全精确） |
| `MIXED` | 混合，一般语句用 statement，特殊用 row |

```sql
show variables like 'binlog_format';     -- 8.0 默认为 ROW
```

### 查看与管理

```sql
-- 查看 binlog 列表
show binary logs;

-- 查看当前写入的 binlog
show master status;

-- 查看 binlog 内容（命令行）
-- mysqlbinlog --base64-output=decode-rows -v binlog.000001
```

```bash
# 命令行查看
mysqlbinlog --no-defaults -v --base64-output=decode-rows /var/lib/mysql/binlog.000001
```

### 基于 binlog 恢复

```bash
# 1. 全量备份恢复
mysql -u root -p < full_backup.sql

# 2. 用 binlog 恢复备份之后的数据（按时间点）
mysqlbinlog --start-datetime="2026-09-18 09:00:00" \
            --stop-datetime="2026-09-18 10:00:00" \
            binlog.000001 | mysql -u root -p
```

### 清理

```sql
-- 删除指定编号之前的 binlog
purge binary logs to 'binlog.000010';

-- 按时间删除
purge binary logs before date_sub(now(), interval 7 day);
```

> **注意**：binlog 会持续增长，必须配置过期清理（`binlog_expire_logs_seconds`），否则撑爆磁盘。

## 19.4 redo log 与 binlog 的两阶段提交

保证两份日志**逻辑一致**：

```text
1. 写 redo log（prepare 状态）
2. 写 binlog
3. 提交 redo log（commit 状态）
```

| 崩溃时刻 | 恢复行为 |
|---------|---------|
| 写 redo(prepare) 后崩溃 | redo 无 commit、binlog 无记录 → **回滚** |
| 写 binlog 后、commit 前崩溃 | redo prepare + binlog 完整 → **提交**（按 binlog 恢复） |

> 为什么需要两阶段提交？若先写 redo 再写 binlog 时崩溃，主库有数据、从库没有 → 主从不一致。

## 19.5 慢查询日志（优化入口）

```sql
-- 开启（会话/全局）
set global slow_query_log = 'ON';
set global long_query_time = 1;               -- 超过 1 秒记录
set global slow_query_log_file = '/var/lib/mysql/slow.log';

-- 查看配置
show variables like 'slow_query%';
show variables like 'long_query_time';

-- 查看慢 SQL 条数
show status like 'slow_queries';
```

```ini
# my.cnf 永久配置
[mysqld]
slow_query_log = 1
long_query_time = 1
slow_query_log_file = /var/lib/mysql/slow.log
```

### 分析工具

| 工具 | 作用 |
|------|------|
| `mysqldumpslow` | 官方自带，按耗时/次数汇总 |
| `pt-query-digest` | Percona 工具，分析更详细（推荐） |

```bash
mysqldumpslow -s t -t 10 /var/lib/mysql/slow.log    # 按耗时取前 10
```

> **排查慢 SQL 标准流程**：慢查询日志找 SQL → `EXPLAIN` 看执行计划 → 加索引/改写（见 11、12 章）。

---

## 19.6 案例：定位并优化慢 SQL

```sql
-- 1. 开启慢查询日志
set global slow_query_log = 'ON';
set global long_query_time = 0.5;

-- 2. 执行一个有问题的查询
select * from tb_order where status = 1 and user_id = 100 order by create_time desc;

-- 3. 查看慢日志
show status like 'slow_queries';

-- 4. EXPLAIN 分析
explain select * from tb_order where status = 1 and user_id = 100 order by create_time desc;
-- 若 type=ALL、Extra=Using filesort → 需加索引

-- 5. 建联合索引
create index idx_status_user_time on tb_order(status, user_id, create_time);

-- 6. 再次 EXPLAIN 验证 type=ref、Extra 无 filesort
```

## 小结

- 四类日志：错误、二进制、查询、慢查询。
- **binlog** 用于主从复制与恢复，格式推荐 `ROW`，要配置过期清理。
- **redo(log) + binlog 两阶段提交**保证两份日志一致。
- **慢查询日志**是优化的入口，配合 `EXPLAIN` 定位。
- 分析工具：`mysqldumpslow`、`pt-query-digest`。
