# 20 - 主从复制

> 目标：理解主从复制原理，掌握主从搭建步骤与延迟处理。

---

## 20.1 什么是主从复制

**主库（Master）**处理写操作，**从库（Slave/Replica）**通过复制主库的 binlog 保持数据同步。

作用：
- **读写分离**（主写从读，提升并发）。
- **数据备份 / 容灾**。
- **故障切换**。

---

## 20.2 复制原理（重点）

```text
主库                          从库
 ① 写操作 → binlog
         │
         │  ② dump 线程推送 binlog
         └──────────────► ③ IO 线程写入 relay log（中继日志）
                                    │
                                    ④ SQL 线程读取 relay log 重放
                                    ↓
                                 从库数据与主库一致
```

三个线程：

| 线程 | 位置 | 作用 |
|------|------|------|
| **dump 线程** | 主库 | 把 binlog 发给从库 |
| **IO 线程** | 从库 | 接收 binlog 写入 relay log |
| **SQL 线程** | 从库 | 读取 relay log 并执行 |

> 记忆：**主库 dump，从库 IO + SQL**。

---

## 20.3 搭建步骤（基于 binlog，MySQL 8.0）

### 主库配置

```ini
# my.cnf
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog_format = ROW
```

```sql
-- 创建复制账号
create user 'repl'@'%' identified by 'Repl@123456';
grant replication slave on *.* to 'repl'@'%';

-- 查看主库状态（记录 File 与 Position）
show master status;
-- +------------------+----------+--------------+
-- | File             | Position | ...          |
-- | mysql-bin.000001 |      157 |              |
-- +------------------+----------+--------------+
```

### 从库配置

```ini
# my.cnf
[mysqld]
server-id = 2
relay-log = mysql-relay-bin
```

```sql
-- 配置主库信息
change master to
    master_host = '192.168.1.10',
    master_user = 'repl',
    master_password = 'Repl@123456',
    master_log_file = 'mysql-bin.000001',   -- 用主库 show master status 的值
    master_log_pos = 157;

-- 启动复制
start slave;      -- 8.0.22+ 也可用 start replica

-- 查看状态（关键：两个 Yes）
show slave status\G
-- Slave_IO_Running: Yes
-- Slave_SQL_Running: Yes
```

> **排错**：只要 `Slave_IO_Running` 或 `Slave_SQL_Running` 有一个 `No`，看 `Last_IO_Error` / `Last_SQL_Error` 定位。

## 20.4 复制类型

| 类型 | 说明 |
|------|------|
| **异步复制**（默认） | 主库提交后立即返回，不等从库 |
| **半同步复制** | 至少一个从库确认收到 binlog 才返回 |
| **同步复制** | 所有从库确认（性能差，几乎不用） |

```sql
-- 半同步（需装插件 rpl_semi_sync_master / slave）
install plugin rpl_semi_sync_master soname 'semisync_master.so';
set global rpl_semi_sync_master_enabled = 1;
```

> 异步复制的风险：主库宕机时，未同步的数据可能丢失。半同步降低该风险。

## 20.5 主从延迟

**原因**：
- 从库 SQL 线程单线程重放（主库并发写）。
- 大事务、大表 DDL。
- 从库硬件/负载比主库差。

**解决**：

| 方案 | 说明 |
|------|------|
| **并行复制**（8.0 默认） | 多线程重放，减少延迟 |
| 拆分大事务 | 避免单事务过大 |
| 提升从库配置 | 从库不低于主库 |
| 读写分离时**读主库** | 强一致场景强制走主库 |

```sql
-- 并行复制配置（8.0）
set global slave_parallel_workers = 4;
set global slave_parallel_type = 'LOGICAL_CLOCK';
```

> **面试常问**：主从延迟怎么解决？→ 并行复制、避免大事务、提升从库、强一致读主库、或用半同步。

---

## 20.6 案例：验证主从同步

```sql
-- 主库插入
insert into study.student (name, score) values ('复制测试', 88);

-- 从库查询（稍等片刻）
select * from study.student where name = '复制测试';   -- 能查到说明同步成功

-- 从库观察延迟秒数
show slave status\G
-- Seconds_Behind_Master: 0   （0 表示无延迟）
```

---

## 小结

- 主从复制：主库写 binlog → dump 线程推送 → 从库 IO 线程写 relay log → SQL 线程重放。
- 三线程：主库 dump，从库 IO + SQL。
- 搭建两步：主库建账号并看 `master status`；从库 `change master` + `start slave`。
- 复制类型：异步（默认）、半同步、同步。
- 延迟解决：并行复制、拆大事务、提升从库、强一致读主库。
