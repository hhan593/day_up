# 31 - 反射与注解（Reflection & Annotations）

> 来源：Oracle《The Java™ Tutorials》— Reflection、Annotations；Java SE 21 `java.lang.reflect` API 规范
> 官方：https://docs.oracle.com/javase/tutorial/java/reflect/ 、https://docs.oracle.com/javase/tutorial/java/annotations/
> 补充：Spring 动态代理与 AOP 落地部分参考 spring.io Framework Reference，属标准实践整理。

反射 = 运行期获取类型信息、动态调用编译期未知的类成员；注解 = 可被反射读取的声明式元数据。二者是 Spring IoC/AOP、MyBatis 映射、JUnit 测试发现的共同底座，也是 `13`/`14` 两篇默认的前置知识。

---

## 一、什么是反射 / 为什么需要它

- 传统调用 `new Order()` 要求类**编译期已知**；反射 = 运行期自省：先拿到 `Class` 对象，再动态读写构造器、字段、方法与修饰符。框架由此才能**面向配置编程**——XML 注册的 Bean、`@Service` 类、`@Test` 方法全由框架启动时反射实例化并调用。

```java
Class<?> clazz = Class.forName("com.demo.Order");   // 类名来自配置，编译期无需依赖 Order
Object order = clazz.getDeclaredConstructor().newInstance();  // public 无参构造
```

---

## 二、Class 对象

同一类在同一 ClassLoader 下只加载一次，堆中 `Class` 实例**唯一**，实例类型比较可直接 `a.getClass() == b.getClass()`。**三种获取方式的核心区别是是否触发静态初始化**：

| 获取方式 | 触发静态初始化？ | 特点 |
|---|---|---|
| `obj.getClass()` | 实例已存在，早已初始化 | 手上已有对象时最方便 |
| `Order.class` | **不触发**（类字面量仅取 Class 引用） | 编译期检查、不抛异常，常作 Class token |
| `Class.forName("com.demo.Order")` | **默认执行**（static 块/静态字段赋值） | 按名动态加载；三参重载 `forName(name, initialize, loader)` 可控 |

> 注意：面试问"`Class.forName` 会不会初始化"，答"默认 true，三参第二参可关"；加载/链接/初始化阶段划分见 `16-JVM内存模型与GC.md`。

**`Class.newInstance()` 已于 Java 9 废弃**：只能调 public 无参构造、无法传参；失败被包成无信息量的 `InstantiationException`/`IllegalAccessException`，甚至能绕过构造器的受检异常声明。正确写法 `clazz.getDeclaredConstructor(String.class).newInstance("Ann")`：可调任意构造器（含 private），构造器抛出的异常统一包在 `InvocationTargetException` 里便于定位原因。

## 三、反射 API 四大入口：Field / Method / Constructor / 修饰符与泛型

```java
public class User extends BaseEntity implements HasId {
    public static final String TABLE = "t_user";
    public String name;  private Integer age;  private List<String> tags = new ArrayList<>();
    public User() {}  public User(String name, Integer age) { this.name = name; this.age = age; }
    public String greet() { return "hi, " + name; }  private Integer getAge() { return age; }
}
```

```java
Class<?> c = User.class;
c.getName(); c.getSuperclass(); c.getInterfaces();   // 类名 / 父类 / 接口
c.getFields();            // 仅 public，含继承来的 TABLE
c.getDeclaredFields();    // 本类声明的全部字段（含 private），不含继承
Method m = c.getMethod("greet");  Object r = m.invoke(user);       // getMethod 为 public+含继承；装箱、接收需强转
Object u = c.getDeclaredConstructor(String.class, Integer.class).newInstance("Ann", 30);
Method pm = c.getDeclaredMethod("getAge");
pm.setAccessible(true);  Integer age = (Integer) pm.invoke(u);   // 突破 private 后调用
Modifier.isPrivate(pm.getModifiers());                // 修饰符是位掩码，用 Modifier.isXxx 判断
// 泛型：c.getDeclaredField("tags").getGenericType() 转 ParameterizedType 可得实参 String（擦除见 06）
```

- **`getXxx()` vs `getDeclaredXxx()` 是高频面试点**：前者只含 public 且**包含继承**，后者含本类所有成员但**不含继承**。
- `setAccessible(true)` 绕的是 **Java 语言层访问检查**，绕不开 JVM 的模块访问限制：Java 9+ 对 JDK 内部类 `setAccessible` 会抛 `InaccessibleObjectException`（见第十一节）。

## 四、反射性能与代价

| 代价 | 说明 |
|---|---|
| 运行开销 | 每次 `invoke` 含方法查找 + 访问检查 + 装箱，JIT 难以内联，比直接调用慢约一个数量级 |
| 类型安全与维护性 | 编译器不再校验方法名/参数/强转；字符串引用（`"getAge"`）不随 IDE 重构改名，错误只在运行时暴露 |
| 破坏封装 | `setAccessible` 使 private 成员事实上对外敞开，内部重构易被打破 |

结论：**框架用、业务代码慎用**，业务优先普通接口与多态。更轻量的替代：`MethodHandle`（`java.lang.invoke`，JIT 对稳定调用点优化良好）与 `LambdaMetafactory`（运行期把方法链接成功能性接口实例，语义如方法引用、调用接近直接速度，适合热点方法缓存复用）。

## 五、动态代理

**静态代理痛点**：加一层计时就要手写实现同接口的包装类，且**每个方法**都抄一遍"记时→转发→打印"模板，横切逻辑完全无法复用。JDK 动态代理在运行期生成代理类，一个 handler 覆盖全部方法（`OrderService` 为普通业务接口）：

```java
public record TimingHandler(Object target) implements InvocationHandler {
    @Override public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.nanoTime();
        try { return method.invoke(target, args); }                     // 反射转发给目标对象
        catch (InvocationTargetException ex) { throw ex.getCause(); }   // 还原业务异常，不外露反射包装
        finally { System.out.printf("%s cost %.3f ms%n", method.getName(), (System.nanoTime() - start) / 1e6); }
    }
    public static void main(String[] args) {
        OrderService proxy = (OrderService) Proxy.newProxyInstance(OrderService.class.getClassLoader(),
                new Class<?>[]{OrderService.class}, new TimingHandler(new OrderServiceImpl())); // (Loader, 接口, handler)
        proxy.query(1);                                                 // 输出: query cost x.xxx ms
    }
}
```

- 生成的 `$Proxy0` 形如 `final class $Proxy0 extends Proxy implements OrderService`；`Proxy` 继承位已被占用且自身 final，故代理对象**无法被二次代理**（CGLIB 也继承不了它）。
- **只能代理接口**：目标类中不属于任何接口的方法拦不到；`equals/hashCode/toString` 同样走 `invoke`。Spring AOP 的 JDK 路线即此机制，`invoke` 内沿拦截器链层层转发。

> 注意：接口 default 方法在代理实例上调用同样转发进 `invoke`，JDK 16+ 可用 `InvocationHandler.invokeDefault(proxy, method, args)` 执行默认实现。

## 六、JDK 动态代理 vs CGLIB vs ByteBuddy

| 维度 | JDK 动态代理 | CGLIB | ByteBuddy |
|---|---|---|---|
| 要求目标实现接口 | 必须 | 不需要 | 不需要 |
| 原理 | 运行期生成 `extends Proxy` 类，`InvocationHandler` 反射转发 | 继承目标类生成子类，用 **FastClass** 方法索引绕开反射调用 | 同样生成子类，基于 `MethodHandles.Lookup.defineClass`，API 现代且类型安全 |
| final 类 / final 方法 | 接口本身无所谓；代理类自身 final 不可再增强 | **都不能代理**（依赖继承与覆写） | final 方法不能代理（同理靠继承） |
| 性能 | 每次调用有反射转发开销 | 生成后调用快于 JDK 反射 | 与 CGLIB 同级，生成代码可调优 |
| Spring 场景 | 传统 Spring 设 `proxyTargetClass=false` 时启用 | **Spring Boot 2.x 起 `spring.aop.proxy-target-class` 默认 `true`，即统一 CGLIB** | Hibernate、Mockito 等生态默认字节码引擎 |

- Java 21 补充：代理只是转发调用，`synchronized` 与**虚拟线程**的行为由目标方法自身决定，与代理机制无特殊冲突。选择建议：目标已实现接口且想零依赖 → JDK 代理；无接口/代理类 → CGLIB（Spring 生态默认）；新库开发需精细控制字节码 → ByteBuddy。

## 七、注解基础

```java
public @interface Meta { String author(); String version() default "1.0"; }  // 元素：无参数列表、无 throws；default 即默认值
```

- 元素类型仅限：**基本类型、String、Class、枚举、注解，及它们的数组**；不能声明任意方法，值不能为 null。注解自身也能携带注解（元注解），如 `@RestController` 是 `@Controller + @ResponseBody` 的组合。
- `@Repeatable`（Java 8+）：同一位置可重复标注，编译后存入容器注解：

```java
@Repeatable(Schedules.class)
public @interface Schedule { String cron(); }
public @interface Schedules { Schedule[] value(); }
```

## 八、四个元注解逐个讲清

### 1. `@Retention` —— 注解存活多久

| 级别 | 作用范围 | 典型用途 |
|---|---|---|
| SOURCE | 编译期丢弃 | `@Override` 等编译器检查 |
| CLASS | **缺省值**；写入 .class 但不加载进运行时 | 注解处理器、字节码扫描工具 |
| RUNTIME | 常驻运行时常量池 | 可被反射读取：Spring/JUnit 全部注解 |

**只有 RUNTIME 级别能被反射读到** —— 这就是 `@Autowired`、`@Test` 必须声明 `@Retention(RetentionPolicy.RUNTIME)` 的原因。

### 2. `@Target` —— 可标注位置

`TYPE / FIELD / METHOD / PARAMETER / CONSTRUCTOR / LOCAL_VARIABLE / ANNOTATION_TYPE / PACKAGE / MODULE（Java 9）/ REPEATABLE_CONTAINER（Java 8）`；不写 `@Target` 则任意位置可用。**`@Documented`** 使注解出现在 javadoc 中，无运行期语义。

### 3. `@Inherited` —— 最易错的一个

只对**标注在类上**的注解生效，且只沿**类继承链**传递（父类的 `@Inherited` 注解，子类 `getAnnotation` 能读到）。高频易错：**不随接口实现传递、接口默认方法上的注解不继承、方法/字段/构造器上的注解一律不继承**。

## 九、注解的读取与处理器：@Table/@Column → INSERT（收官实战）

`Class`/`Method`/`Field` 均实现 `AnnotatedElement`：`isAnnotationPresent`、`getAnnotation`、`getAnnotationsByType`（Java 8+，透明展开可重复注解）。串起二、三、八节做一个迷你 ORM 片段：

```java
@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.TYPE) public @interface Table { String value(); }
@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.FIELD) public @interface Column { String value(); boolean insertable() default true; }

@Table("t_order") public class Order {
    @Column("id") private Long id;  @Column("user_name") private String userName;
    @Column(value = "amount", insertable = false) private BigDecimal amount;
}

public static String toInsert(Object e) throws Exception {
    Table t = e.getClass().getAnnotation(Table.class);                 // 读 RUNTIME 注解
    StringJoiner cols = new StringJoiner(", "), vals = new StringJoiner(", ", "VALUES (", ")");
    for (Field f : e.getClass().getDeclaredFields()) {                 // 本类全部字段（含 private）
        Column col = f.getAnnotation(Column.class);
        if (col == null || !col.insertable()) continue;
        f.setAccessible(true); Object v = f.get(e);                    // 突破 private 读值
        cols.add(col.value()); vals.add(v == null ? "NULL" : "'" + v + "'");  // 真实场景用 PreparedStatement 占位符防注入
    }
    return "INSERT INTO " + t.value() + " (" + cols + ") " + vals;
}
// 输出: INSERT INTO t_order (id, user_name) VALUES ('1', 'Ann') —— 注解=配置、反射=执行，正是 MyBatis/JPA 映射的原型
```

## 十、Spring / MyBatis / JUnit 如何落地这些机制

- **`@Autowired` 字段注入**：`AutowiredAnnotationBeanPostProcessor` 反射发现 RUNTIME 注解后，经 `Field.setAccessible(true)` + `Field.set(bean, dep)` 写入依赖；容器调度侧见 `14-Spring核心IoC与AOP.md`。
- **`@Configuration` 单例保证**：`proxyBeanMethods=true` 时对配置类做 **CGLIB 子类化**，拦截 `@Bean` 方法互调并重定向到容器，故配置类与 `@Bean` 方法不能为 final。
- **MyBatis 结果映射**：`Reflector` 反射缓存属性读写句柄，结合 `@Result`/XML 配置用 `Method.invoke`/`Field.set` 把结果集逐行封装成实体，见 `20-MyBatis.md`。
- **JUnit 5**：Launcher 用 `getDeclaredMethods()` 反射发现 `@Test` 方法并 `Method.invoke` 执行，`@ParameterizedTest` 进一步读 `Parameter` 信息，见 `17-单元测试JUnit与Mockito.md`。

## 十一、Java 9+ 模块系统对反射的限制

- Java 9 模块系统对 JDK 内部实现**强封装**：对未 open 包（如 `java.lang` 私有成员）反射 `setAccessible` 会抛 `InaccessibleObjectException`，老版本 Gson/CGLIB 升级到 JDK 17/21 时常撞上。
- 标准解法是 JVM 参数 `--add-opens java.base/java.lang=ALL-UNNAMED`（把该包开放给所有无名模块/Classpath 代码），仅需编译期可见性用 `--add-exports`，报错信息会给出确切的待加参数照抄即可；Spring Framework 6（Java 17 基线）已大幅削减对 JDK 内部反射的依赖，但老三方库在新 JDK 下仍需此类参数。
