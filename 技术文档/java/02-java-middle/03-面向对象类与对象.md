## 一、类与对象（Classes & Objects）

### 1. 类结构

```java
public class Dog {
    // 字段（成员变量）
    private String name;
    private int age;

    // 构造器
    public Dog(String name, int age) {
        this.name = name;   // this 指向当前实例，用来区分同名的参数
        this.age = age;
    }

    // 方法
    public void bark() { System.out.println(name + " bark"); }

    // 访问器
    public String getName() { return name; }
}
```

- 类的成员有五类：**字段、方法、构造器、初始化块、嵌套类**（JLS §8.1.7）。
- **构造器不是成员，也不被继承**（JLS §8.2）；字段有默认值（`int` → `0`、引用 → `null`），**局部变量没有默认值**，见 `02`。
- 字段与方法的**作用域是整个类体**，所以方法可以先调用后声明；但字段初始化表达式存在「前向引用」限制（JLS §8.3.3），属于 33 篇与 JLS 的细节。

### 2. `new` 一次到底发生了什么（JLS §12.5）

```java
Dog d = new Dog("Buddy", 3);
d.bark();
```

`new` 不是「分配内存 + 调构造器」一句话就完事。JLS §12.5 把实例创建规定为五步：

```text
① 分配内存，容纳本类 + 所有超类的实例字段（包括被隐藏的字段）
② 所有实例字段置默认值：0 / false / null   ← 此时业务逻辑一行都没跑
③ 递归执行 super(...) 或 this(...) 构造器链，一直到 Object
④ 回到本类，按源码文本顺序执行「实例字段初始化式 + 实例初始化块」
⑤ 执行构造器剩余语句体，此后引用才返回给调用方
```

> 注意：**③ 在 ④ 之前**，即父类构造器先于子类字段初始化。这条顺序是后面「构造器里调用可覆写方法」坑的根因，不是实现细节而是规范。

### 3. 访问控制（Access Modifiers）

| 修饰符 | 同类 | 同包 | 子类 | 其他包 |
|---|---|---|---|---|
| `private` | ✅ | | | |
| （默认/包私有） | ✅ | ✅ | | |
| `protected` | ✅ | ✅ | ✅ | |
| `public` | ✅ | ✅ | ✅ | ✅ |

- `private` 成员**不被子类继承**（JLS §8.2）；跨包子类只继承 `public` / `protected` 成员。
- `protected` 在跨包子类中还有一个常被忽略的限制：只能**通过子类自身类型的引用**访问，不能拿父类引用去点（JLS §6.6.2）。类本身（顶层）只能 `public` 或包私有，嵌套类才能用四种修饰符。

### 4. 构造器：默认、重载、`super` / `this`

Oracle 教程《Providing Constructors for Your Classes》给了三条基线：

1. 一个类**不写任何构造器**时，编译器提供一个无参默认构造器，它调用父类的无参构造器；父类若没有无参构造器 → 编译错误。
2. 一旦写了任意构造器，默认构造器就**不再自动生成**（想用 `new User()` 得自己补）。
3. 构造器按参数列表重载，可以有访问修饰符；`private` 构造器意味着外部无法直接 `new`（工具类、单例常用）。

```java
public class User {
    private final String name;
    private int age;

    public User(String name) {
        this(name, 0);            // this(...) 必须是第一条语句
    }

    public User(String name, int age) {
        // super();              // 未显式写时编译器自动插入，也必须最先执行
        this.name = name;
        this.age = age;
    }
}
```

> 注意：`super(...)` 与 `this(...)` **都必须是构造器第一条语句，且二者只能出现一个**。构造器链一定是 `this(...)` → 最终某个构造器 → `super(...)` → 父类构造器，不会绕开父类。

### 5. 初始化块与一次可手算的执行顺序

Oracle 教程《Initializing Fields》：静态初始化块在**类初始化时按文本顺序执行一次**（可替代写法是 `private static` 方法，便于复用）；实例初始化块会被编译器**复制进每一个构造器**，适合在多个构造器之间共享初始化代码。

```java
class Parent {
    static { System.out.println("1 Parent 静态初始化"); }
    { System.out.println("3 Parent 实例初始化块"); }
    Parent() { System.out.println("4 Parent 构造器体"); }
}
class Child extends Parent {
    static { System.out.println("2 Child 静态初始化"); }
    { System.out.println("5 Child 实例初始化块"); }
    Child() { System.out.println("6 Child 构造器体"); }
}
```

首次 `new Child()` 输出 `1 → 2 → 3 → 4 → 5 → 6`；第二次 `new Child()` 只输出 `3 → 4 → 5 → 6`（类初始化只有一次，父类静态先于子类静态，见 JLS §12.4）。

> 注意：教程还建议用 **`final` 方法**做字段初始化（如 `private final var x = init();`）——理由是「在实例初始化期间调用非 final 方法会出问题」，下一小节就是这个问题。

### 6. 构造器里不要调用可覆写方法（JLS 官方示例 + 官方建议）

```java
class Super {
    Super() { printThree(); }                       // 构造器中调用实例方法
    void printThree() { System.out.println("three"); }
}
class Test extends Super {
    int three = (int) Math.PI;                      // 3
    @Override void printThree() { System.out.println(three); }

    public static void main(String[] args) {
        Test t = new Test();
        t.printThree();
    }
}
// 输出：0   然后   3
```

JLS SE 21 Example 12.5-2 明确：**与 C++ 不同，Java 在对象创建期间不改变方法分派规则**——父类构造器调 `printThree()` 时执行的是子类重写版本，而此刻子类字段初始化式还没跑（§12.5 步骤 ④ 未到），所以读到默认值 `0`。Oracle 教程《Writing Final Classes and Methods》给出的对策是：**构造器中调用的方法通常应声明为 `final`**（或用 `private`、静态方法），避免被子类重写。

> 工程实践（非官方规范）：Spring Bean 的 `@PostConstruct`、代理对象初始化等场景出现「字段莫名是 null/0」，排查顺序应当先看「是不是在构造阶段被重写方法提前读了」，再看依赖注入。Spring 侧的创建流程见 `40`。

### 7. 静态成员（`static`）

- `static` 字段/方法属于**类**而非实例，静态字段只有一份；静态方法处于**静态上下文**，不能出现 `this` / `super`，也不能直接访问实例字段（JLS §8.1.3、§8.4.3.2）。
- 静态初始化块：`static { ... }`，类加载初始化时执行一次。
- 常量惯用 `public static final`，命名 `UPPER_SNAKE_CASE`；接口字段天然就是 `public static final`（第四节）。

```java
class Counter {
    private static int created;          // 全类共享
    private final int id;                // 每实例一份

    Counter() { id = ++created; }
    static int created() { return created; }   // 静态方法不能写 this.id
}
```

### 8. 不可变对象（工程实践）

不可变对象是「构造完就再也不变」的对象，天然线程安全、可安全做 `HashMap` 的键。三要素（属业界约定，非 JLS 条文）：

```java
public final class Money {                  // ① 类 final：不许子类改写行为
    private final long cents;               // ② 字段 final + private
    private final java.util.List<String> tags;

    public Money(long cents, java.util.List<String> tags) {
        this.cents = cents;
        this.tags = java.util.List.copyOf(tags);   // ③ 可变入参做防御性拷贝
    }
    public long cents() { return cents; }
    public java.util.List<String> tags() { return tags; }  // 返回只读视图，不外泄可变引用
}
```

`String`、包装类是 JDK 内的典型例子；业务代码直接写 `record Money(long cents)` 更省事，见 `08`。**易错点**：只把字段写成 `final` 但返回内部 `List`/`Date` 引用，仍是可变对象。

### 9. 嵌套类四种（Oracle《Nested Classes》）

官方分类只有两大类：**静态嵌套类**（`static`）与**内部类**（非 static，含局部类、匿名类）。

| 类型 | 写法 | 是否持有外部实例引用 | 能否直接访问外部实例字段 | 典型用途 |
|---|---|---|---|---|
| 静态嵌套类 | `static class Node { }` | ❌ | ❌（须经对象引用） | `Map.Entry`、Builder、链表节点 |
| 内部类（成员） | `class Iterator { }` | ✅ | ✅（含 `private`） | 迭代器、事件处理器 |
| 局部类 | 方法内 `class X { }` | 视声明处上下文 | ✅（捕获的局部变量须 final 或 effectively final） | 方法内一次性实现 |
| 匿名类 | `new X() { ... }` | 视声明处上下文 | ✅ | Lambda 普及前的一次性回调，见 `07` |

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();     // 内部类必须先有外部实例
Outer.StaticNested sn = new Outer.StaticNested();  // 静态嵌套类按普通类方式实例化
```

官方还给了一个**遮蔽（Shadowing）**例子：`x` 同名时，用 `this.x` 指向内部类字段、`Outer.this.x` 指向外部类字段（`x = 23 / this.x = 1 / Outer.this.x = 0`）。

三个版本/工程要点：

- **JDK 8 教程**说「内部类不能定义任何静态成员」；JLS SE 21 §8.1.3 明确「Java SE 16 之前内部类不能声明静态初始化块，静态成员只能是常量变量」——**Java 16 起已放宽**，看旧教程时别背成现行规则。
- 官方明确 **强烈不建议序列化内部类**（含局部类、匿名类）：编译器会生成合成（synthetic）构造，不同编译器产出的 `.class` 可能不兼容。
- 工程实践（非官方规范）：非静态内部类隐式持有外部实例，把它放进静态集合/缓存/异步任务里会让外部对象无法回收，是常见的内存泄漏来源；**能写 `static` 就写 `static`**（Builder、DTO 嵌套类型尤其如此），泄漏排查见 `37`。

## 二、继承（Inheritance）

- 用 `extends`，**类单继承**（一个直接父类），`Object` 是所有类的最终父类；接口可以多实现、多继承。
- 子类继承父类的非 `private` 成员；**`private` 成员与构造器都不继承**（JLS §8.2）。
- `super` 调父类构造器 / 方法；`@Override` 让编译器校验确实重写了父类方法。

```java
public class Animal {
    public void eat() { System.out.println("eat"); }
}
public class Cat extends Animal {
    @Override
    public void eat() { super.eat(); System.out.println("cat eats fish"); }
}
public class Bird extends Animal {           // ← 要放进 Animal[]，类型必须真的继承 Animal
    @Override public void eat() { System.out.println("bird eats seed"); }
}
```

### 1. 重载（overload）与重写（override）别混

| | 重载 | 重写 |
|---|---|---|
| 范围 | 同类或父子类之间 | 子类 / 实现类与父类型之间 |
| 签名 | **必须不同**（参数个数/类型） | **必须相同**（可协变返回） |
| 绑定时机 | 编译期按实参的**声明类型**选定 | 运行期按**实际对象类型**分派 |
| `@Override` | 不能标 | 强烈建议都标 |

JLS §9.6.4.4 给的经典事故：想重写 `equals(Object)` 却写成 `equals(Foo)`，编译完全通过、行为却是重载，`Object.equals` 依旧生效——**`@Override` 一加就立刻报错**。

### 2. 字段隐藏（Hiding Fields）

子类声明同名字段时是**隐藏**而不是重写，对象里同时存在两份字段；字段访问按**引用的声明类型**决定（JLS §8.3，Example 8.3.1.1-3）：

```java
class Base    { int value = 1; int get() { return 10; } }
class Derived extends Base { int value = 2; @Override int get() { return 20; } }

Base ref = new Derived();
System.out.println(ref.value);              // 1 ← 字段：看引用类型
System.out.println(((Derived) ref).value);  // 2
System.out.println(ref.get());              // 20 ← 方法：看实际对象
```

### 3. `final` 的三层语义（Oracle《Writing Final Classes and Methods》）

| 位置 | 效果 |
|---|---|
| `final` 字段 | 只能赋值一次；空白 final 字段必须在每个构造器结束前赋值（JLS §8.3.1.2） |
| `final` 方法 | 不能被子类重写/隐藏；`private` 方法与 `final` 类的所有方法都等价于 final |
| `final` 类 | 不能被继承（`String`、包装类、record 都是 final） |

> 注意：`final` 只锁「引用不能再指向别处」，不锁「引用指向的对象内容不可变」——`final List<String> l` 仍能 `l.add(...)`。`final` 字段在并发下的可见性语义属 JMM，见 `34`。

## 三、多态（Polymorphism）

Oracle 教程《Polymorphism》的定义：**JVM 调用的是「变量所引用对象」对应的方法，而不是「变量声明类型」定义的方法**，这叫**虚拟方法调用（virtual method invocation）**。

```java
Animal[] zoo = { new Cat(), new Bird() };
for (Animal a : zoo) a.eat();   // 一个引用类型，两种运行时行为
```

```text
编译期（静态绑定）          运行期（动态绑定）
Animal a = ...;      →      a.eat() 查 a 实际对象的虚方法表
「能不能调 eat()」          「调的是哪一个 eat()」
由引用类型决定              由实际对象类型决定
```

| 成员 | 是否参与运行时多态 | 依据 |
|---|---|---|
| 非 `private`、非 `static`、非 `final` 的**实例方法** | ✅ | 虚拟方法调用 |
| `static` 方法 | ❌，是**隐藏**，按调用处的类/引用类型决定 | Oracle《Overriding and Hiding Methods》 |
| `private` 方法 / `final` 方法 / 构造器 | ❌，不可重写 | JLS §8.4.3.3 |
| 字段 | ❌，是**隐藏**，按引用类型决定 | JLS §8.3 |
| 重载方法的选择 | ❌，编译期定型 | JLS §8.4.9 |

官方《Overriding and Hiding Methods》的例子可直接推演：`Animal myAnimal = new Cat();` 时，`Animal.testClassMethod()`（静态）走父类版本，而 `myAnimal.testInstanceMethod()` 走 `Cat` 版本。

### 重写的完整规则清单

1. 签名相同；返回类型可**协变**（返回父类方法返回类型的子类型，JLS §8.4.5）。
2. 访问权限**只能放宽不能收窄**（`protected` → `public` 可以，反向不行）。
3. 受检异常**不能比父类更宽**（JLS §8.4.8.3）。
4. 实例方法与静态方法**不能互相覆盖**：父实例 → 子 `static`、父静态 → 子实例都是编译错误（官方教程表格）。
5. 接口静态方法**从不被继承**（官方教程原句），因此也不存在「重写接口静态方法」。
6. 类继承来的实例方法可以顺带实现接口的同名抽象方法（官方 `Mustang extends Horse implements Mammal` 例）。

```java
class Figure { Number area() { return 0; } }
class Round extends Figure {
    @Override Double area() { return 3.14; }   // 协变返回：Double 是 Number 的子类型
}
```

> 注意：**重载的解析发生在编译期**，所以 `void f(Object)` 与 `void f(String)` 在 `Object o = "x"; f(o);` 时选前者——多态只作用于「同一签名的实例方法」，不会帮你在重载之间重新挑一次。

### 向下转型与模式匹配

父类引用要用子类特有方法就得向下转型，转型前需判类型。Java 16 起（JEP 394）`instanceof` 支持模式变量，免掉一次显式强转；Java 21 的 `switch` 穷尽性检查与密封类搭配见 `09`：

```java
if (a instanceof Cat c) {
    c.eat();                  // c 已是 Cat，无需 (Cat) a
}
```

## 四、抽象类与接口（Abstract & Interface）

### 1. 抽象类

```java
public abstract class GraphicObject {          // 官方教程同名示例
    public abstract double area();   // 抽象方法：无方法体
    public void print() { System.out.println("graphic"); }
}
```

Oracle《Abstract Methods and Classes》：**抽象类不可实例化但可被继承**；含抽象方法的类必须声明 `abstract`；子类若没实现全部抽象方法，自身也得是 `abstract`。抽象类可以有非静态非常量字段、`protected` / `private` 具体方法、静态成员，也可以一个抽象方法都没有。

### 2. 接口的隐式修饰符（JLS §9.3 / §9.4）

| 声明 | 隐式修饰符 | 说明 |
|---|---|---|
| 接口字段 | `public static final` | 必须给初始化式，本质是常量 |
| 无修饰符的方法 | `public abstract` | 实现类必须提供实现 |
| `default` 方法 | `public` 实例方法，带方法体 | Java 8 起 |
| `static` 方法 | `public`，**不被继承**，只能用 `接口名.方法()` 调 | Java 8 起 |
| `private` 方法 | 仅在接口内部复用，**不被继承、不可重写** | Java 9 起（现行语法见 JLS §9.4） |

接口方法**不能**用 `protected` / 包私有 / `final` / `synchronized` / `native`（JLS §9.4）；接口里也不能写 `default boolean equals(Object)` 这类重写 `Object` 方法的默认方法（JLS §9.4.1.2 明确编译错误）。

```java
public interface Payable {
    int amount();                                   // public abstract

    static String currency() { return "CNY"; }       // 只能 Payable.currency()

    default String label() { return prefix() + amount(); }

    private String prefix() { return "¥"; }          // Java 9+，接口内部复用
}
```

### 3. `default` 为什么存在：接口演进

Oracle《Default Methods》给出了动机：给已发布的接口加抽象方法，所有旧实现类都会编译失败；用 `default` 提供实现，就能在**保证二进制兼容**的前提下扩展接口。官方举的就是 JDK 8 的 `List.sort`、`Comparator.comparing` / `thenComparing` / `reversed`。子接口拿到 default 方法后有三种选择：**不提（继承）、重新声明成 abstract、重新 default 覆盖**。

### 4. 默认方法冲突的三条解析规则（官方文档确认）

| 优先级 | 规则 |
|---|---|
| 1 | **类优先于接口**：父类（含继承来的）具体实例方法压过接口默认方法 |
| 2 | **更具体者胜**：已被某个子接口重写过的默认方法，忽略其祖先接口版本 |
| 3 | 两个相互独立的默认方法冲突、或 default 与 abstract 冲突 → **编译错误**，必须显式重写 |

```java
interface Flyer  { default String identify() { return "flyer"; } }
interface Runner { default String identify() { return "runner"; } }

class Athlete implements Flyer, Runner {
    @Override
    public String identify() {
        return Flyer.super.identify() + "+" + Runner.super.identify();
    }
}
```

`X.super.m()` 中的 `X` 必须是**直接超接口**（官方教程原句）。规则 1 的官方例子是 `Pegasus extends Horse implements Flyer`，`identifyMyself()` 返回的是 `Horse` 的 `"I am a horse."`。

### 5. 抽象类 vs 接口怎么选（Oracle 官方对照）

| 维度 | 抽象类 | 接口 |
|---|---|---|
| 继承数量 | 只能 `extends` 一个 | 可 `implements` 多个 |
| 状态 | 可有非静态、非 final 字段 | 字段全是 `public static final` 常量 |
| 方法可见性 | `public` / `protected` / `private` 均可 | 方法默认 `public`（Java 9 起可 `private` 辅助方法） |
| 适合 | 一组**强相关**类共享代码与状态 | 给**无关**类约定同一种能力/类型 |
| JDK 例子 | `AbstractMap` → `HashMap` 共享 `get/put` 骨架 | `HashMap implements Serializable, Cloneable, Map` |

官方原话的思路：JDK 里两者常常一起用（`HashMap` 既继承 `AbstractMap` 又实现多个接口），不是二选一。**注意版本差异**：JDK 8 教程写「接口所有方法都是 public」，Java 9 引入 `private` 接口方法后该句需要修正。

### 6. 函数式接口与密封类（只点边界）

- **函数式接口**：只有一个抽象方法的接口（`Runnable`、`Comparator`），可用 Lambda；`@FunctionalInterface` 让编译器帮你校验，完整展开见 `07`。
- **密封类/接口**（JEP 409，JDK 17 定稿）：限制谁能继承/实现，配合模式匹配做穷尽检查（JLS §8.1.6、§9.1.4）：

```java
// 同一包下（可分文件；未命名模块要求同包）
public sealed interface Shape permits Circle, Square { }
final class Circle implements Shape { }
non-sealed class Square implements Shape { }
```

四条规范约束：① `permits` 列出的直接子类必须显式写成 `final` / `sealed` / `non-sealed` 之一；② 命名模块中须与密封类型**同模块**，未命名模块中须**同包**；③ 省略 `permits` 时从**同一编译单元**中推断子类；④ `enum`（隐式 final 或 sealed）与 `record`（隐式 final）可以实现密封接口。完整语法、穷尽 `switch` 见 `09`。

## 五、`Object` 契约与重写红线

所有类（含数组）都继承 `Object`。按 Java SE 21 API 文档：

| 可覆写 | 不可覆写（`final`） |
|---|---|
| `equals` / `hashCode` / `toString` / `clone`（protected）/ `finalize`（protected，已废弃待移除） | `getClass()` / `notify()` / `notifyAll()` / 三个 `wait(...)` |

**契约要点**（`java.lang.Object` API 原文）：`equals` 须满足**自反、对称、传递、一致、`x.equals(null) == false`**；`hashCode` 须满足**同一对象多次调用一致、equals 相等则 hashCode 必须相等、equals 不等不要求 hashCode 不同**；API Note 明确「重写 `equals` 时通常必须同时重写 `hashCode`」。`toString()` 默认 `类名@十六进制hashCode`，建议所有子类重写；`clone()` 默认是**浅拷贝**且要求实现 `Cloneable`，否则抛 `CloneNotSupportedException`；`finalize` 自 Java 9 起 `@Deprecated(forRemoval = true)`，JLS SE 21 §12.6 已允许 JVM 禁用它，资源清理应改用 `AutoCloseable` + try-with-resources（JEP 421，见 `37`）。

一份能直接抄的实现：

```java
import java.util.Objects;

public final class Sku {
    private final String code;
    private final int version;

    public Sku(String code, int version) {
        this.code = Objects.requireNonNull(code);
        this.version = version;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Sku other)) return false;   // Java 16+ 模式匹配；低版本改写强转
        return version == other.version && Objects.equals(code, other.code);
    }

    @Override
    public int hashCode() { return Objects.hash(code, version); }

    @Override
    public String toString() { return "Sku[code=" + code + ", version=" + version + "]"; }
}
```

> 工程实践（非官方规范，Effective Java 经典结论）：在**可继承的类**里用 `instanceof` 写 `equals`，子类新增字段后很容易破坏对称性——`point.equals(colorPoint)` 为 true、`colorPoint.equals(point)` 为 false。两条出路：用 `getClass()` 精确比类型，或干脆用**组合 / `record`** 代替继承（`08` 会看到 record 自动生成这三个方法）。
>
> 本篇只建立「契约 ↔ 重写规则」这条因果；`hashCode` 乘子 31、`String.equals` 流程、哈希容器桶定位、`clone` 三宗罪等底层细节见 `33` 与 `36`；`wait/notify` 的 monitor 语义见 `34`、`35`。

## 六、包（Packages）

- 用 `package com.example.demo;` 声明包，通常与目录结构一致；没有 `package` 声明即在**默认包**（默认包的类无法被有包名的类 import，生产代码不用）。
- `import` 只是**引入名字**，不会把类复制进当前文件；`import java.util.*` 按需解析，不增加运行时开销。
- `java.lang` 自动导入（`String`、`Object`、`System` 等）；`import static java.lang.Math.PI;` 可静态导入成员。
- 包名用反向域名避免冲突；Java 9 起模块（JPMS，JEP 261）在包之上再加了一层**导出/封装**边界——`module-info.java` 里没 `exports` 的包，即使类是 `public` 也无法被其他模块访问。这一层与访问控制是叠加关系，细节见 JLS §7 与 JDK 模块规范。

## 七、常见坑速查

| # | 现象 | 根因 | 对策 |
|---|---|---|---|
| 1 | 加了有参构造器后 `new Xxx()` 报编译错 | 默认无参构造器不再自动生成 | 显式补无参构造器 |
| 2 | 父类没有无参构造器，子类编译失败 | 隐式 `super()` 找不到目标 | 子类显式 `super(args)` |
| 3 | 构造器里读到 `0` / `null` | 构造阶段调用了被子类重写的方法（JLS §12.5） | 该方法设 `final`/`private`/静态，或改用工厂/初始化回调 |
| 4 | 以为重写了 `equals(Object)`，其实没生效 | 参数写成具体类型 → 重载 | 一律加 `@Override` |
| 5 | `HashSet` 里存了对象却 `contains` 不到 | 只重写 `equals` 没重写 `hashCode` | 两个一起重写（见 `33`、`36`） |
| 6 | 子类字段「改了没效果」 | 字段隐藏，访问按引用类型 | 避免父子同名字段，用 getter |
| 7 | `static` 方法被子类「重写」后行为没变 | 静态方法是隐藏，按调用处类型定 | 不要用实例去调静态方法 |
| 8 | 实现两个接口突然编译报错 | 两个独立 `default` 冲突 | 显式重写并用 `X.super.m()` |
| 9 | 内部类放进缓存后外部对象不回收 | 隐式持有外部实例引用 | 改 `static` 嵌套类 |
| 10 | 接口里想写 `default equals(...)` | JLS §9.4.1.2 禁止 | 由实现类重写 `Object` 方法 |
| 11 | 序列化内部类后跨环境反序列化失败 | 合成构造物不跨编译器兼容（官方明确不建议） | 用静态嵌套类/顶层类 |
| 12 | `final List` 内容还是被改了 | `final` 锁引用不锁对象 | 防御性拷贝 + 只读视图 |

## 八、常见面试考点（速答版）

| 问法 | 一句话答法 | 追问方向 |
|---|---|---|
| 重载和重写区别？ | 重载编译期按签名选，重写运行期按实际对象分派 | 协变返回、`@Override`、`equals(Foo)` 陷阱 |
| 多态适用于字段吗？ | 不适用，字段是隐藏，按引用类型 | 对象里其实存了两份同名字段 |
| `static` 方法能被重写吗？ | 不能，只能隐藏 | 父静态 → 子实例是编译错误 |
| 抽象类能有非抽象方法吗？接口呢？ | 都能；抽象类还可有实例字段与非 public 方法 | 接口字段 `public static final` |
| 接口为什么加 `default`？ | 不破坏旧实现类地演进接口（二进制兼容） | 冲突三规则 + `X.super.m()` |
| `equals` 与 `hashCode` 为什么要一起重写？ | equals 相等 ⇒ hashCode 必须相等，否则哈希容器定位错桶 | 五条/三条契约、可变字段做 key |
| 构造器中调可覆写方法会怎样？ | 子类版本先执行，子类字段尚未初始化，读到默认值 | JLS §12.5 五步顺序 |
| 非静态内部类为什么容易泄漏？ | 隐式持有外部实例引用 | Builder 用 `static`、泄漏排查见 `37` |
| `final` 保证对象不可变吗？ | 不保证，只保证引用不再赋值 | 不可变三要素、record |
| 子类能继承父类构造器/private 成员吗？ | 都不能（JLS §8.2） | 默认构造器与 `super()` |

## 十、一句话总结

> 面向对象的难点不在语法，而在**三条分界线**：`new` 时的初始化顺序决定「什么时候字段才可信」，方法重写/字段隐藏决定「一次调用到底落到哪」，`Object` 与接口的契约决定「子类能不能安全替换父类」。把这三条说清，`extends`、`implements`、`@Override`、`default`、`sealed` 都只是它们的语法投影。
