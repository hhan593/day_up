## 一、CAP 定理

- **C（一致性）**：所有节点同一时刻数据相同。
- **A（可用性）**：每个请求都能得到（非错误）响应。
- **P（分区容错）**：网络分区时系统仍能继续工作。
- 结论：分布式系统**必然 P**，只能在 C 与 A 间取舍（CP 或 AP）。
- 例子：ZooKeeper/etcd 偏 CP；Eureka/Nacos(临时实例) 偏 AP。

---

## 二、BASE 与最终一致

- **BA**（基本可用）：故障时降级、响应变慢但仍可用。
- **S**（软状态）：允许中间不一致状态。
- **E**（最终一致）：经过一段时间，数据最终一致。
- 工程实践多用 **AP + 最终一致**（比强一致更可用、性能更好）。

## 三、分布式锁

- 需求：跨进程/跨机器的互斥（如防重复下单、定时任务只跑一次）。
- 方案对比：
  | 方案 | 优点 | 缺点 |
  |------|------|------|
  | Redis（SET NX EX）| 高性能 | 需兜底过期、主从切换可能丢锁 |
  | Redisson 看门狗 | 自动续期 | 仍非强一致 |
  | ZooKeeper/etcd | 强一致、临时节点防死锁 | 性能较低、依赖重 |
  | 数据库唯一约束 | 简单 | 性能差 |
- 关键：**锁必须有超时 + 解锁原子 + 防误删**（详见 `redis/README.md#六分布式锁`）。

## 四、分布式 ID

- 要求：全局唯一、趋势递增、高可用、高性能。
- 方案：
  - **UUID**：简单但不有序、太长、索引不友好（B+树碎片化）。
  - **数据库自增 + 步长**：分库步长，简单但有上限/单点。
  - **Redis INCR**：原子自增，依赖 Redis。
  - **Snowflake（雪花）**：41bit 时间戳 + 10bit 机器 + 12bit 序列，**毫秒级 4096/机**，趋势递增；注意**时钟回拨**问题。
  - **Leaf（美团）/UidGenerator（百度）**：号段/雪花改进，解决时钟回拨。

```java
// 雪花 ID 结构：0|41位时间|10位机器|12位序列
long id = (timestamp << 22) | (workerId << 12) | sequence;
```

## 五、幂等设计

- 定义：同一请求多次执行效果相同。
- 场景：网络重试、MQ 重投、前端重复点击。
- 手段：
  - **唯一索引 / 唯一约束**（DB 层兜底）。
  - **Token 机制**：提交前申请 token，提交时校验并删除（防重复提交）。
  - **状态机**：仅允许合法状态流转。
  - **去重表 / Redis SETNX**。
  - HTTP 语义：`PUT` 天然幂等，`POST` 不幂等。

## 六、分布式事务

- 强一致代价高，工程多用**最终一致**：
  - **2PC**：协调者两阶段，强一致但同步阻塞、单点、数据锁定。
  - **TCC**：Try 预留 / Confirm 提交 / Cancel 补偿，侵入业务，性能好。
  - **Saga**：长事务拆本地事务链 + 补偿，适合跨多服务。
  - **事务消息（RocketMQ）**：本地事务 + 半消息 + 回查（见 `mq/README.md#四可靠投递`）。
  - **最大努力通知**：尽力回调+对账。
- 框架：Seata（AT/TCC/Saga）、RocketMQ 事务消息。
- 原则：**能避免就避免**（聚合根、同库），确需才引入。

---

## 七、一致性协议

- **Raft**：易于理解的共识算法，选主 + 日志复制 + 安全性；etcd/Consul/Nacos(CP) 用之。
- **Paxos**：理论基石，复杂。
- **Zab**：ZooKeeper 原子广播。
- **Quorum（NWR）**：写 W 读 R，W+R>N 保证读到最新（Dynamo/Cassandra）。

---

## 八、限流与熔断

- **限流算法**：
  - 计数器（固定窗口，有临界突刺问题）
  - 滑动窗口（更平滑）
  - **漏桶**（恒定速率流出，平滑）
  - **令牌桶**（匀速放令牌，允许突发，常用，如 Guava `RateLimiter`）
- **熔断**：错误率超阈值则开启，半开试探恢复（Sentinel/Hystrix，见 `microservices/README.md#八服务容错熔断限流降级`）。
- **降级**：非核心功能失败时返回兜底。

## 九、常见面试考点

1. **CAP 怎么选？** → 必选 P，CP（强一致）或 AP（高可用+最终一致）。
2. **BASE 是什么？** → 基本可用+软状态+最终一致。
3. **分布式锁有哪些？** → Redis/Redisson/ZK/DB，各有取舍。
4. **雪花 ID 结构？** → 时间戳+机器+序列；时钟回拨怎么办？
5. **幂等怎么保证？** → 唯一索引、Token、状态机、去重表。
6. **分布式事务方案？** → 2PC/TCC/Saga/事务消息，优先最终一致。
7. **Raft 做什么？** → 共识选主+日志复制，保证 CP。
8. **限流算法？** → 令牌桶/漏桶/滑动窗口及其区别。
