# 15 - 触发器

> 目标：理解触发器的概念，掌握 INSERT / UPDATE / DELETE 触发器与 NEW/OLD 的使用。

---

## 15.1 什么是触发器

触发器（Trigger）是**在增删改之前或之后自动执行**的一段 SQL，用于日志记录、数据校验、自动同步等。

```sql
create trigger 触发器名
before | after  insert | update | delete
on 表名 for each row
begin
    -- 触发逻辑
end;
```

| 要素 | 说明 |
|------|------|
| `before` / `after` | 在操作前 / 后执行 |
| `insert/update/delete` | 触发事件 |
| `for each row` | 行级触发 |

---

## 15.2 NEW 与 OLD

| 事件 | `NEW` | `OLD` |
|------|-------|-------|
| `INSERT` | 插入的新数据 | — |
| `UPDATE` | 修改后的数据 | 修改前的数据 |
| `DELETE` | — | 删除前的数据 |

```sql
-- 只能在行级触发器中使用 NEW / OLD
new.name      -- 新行的 name
old.score     -- 旧行的 score
```

---

## 15.3 案例：用户操作日志

```sql
-- 日志表
create table tb_user_log (
    id        bigint primary key auto_increment,
    user_id   bigint,
    action    varchar(10),
    log_time  datetime default current_timestamp
);

-- INSERT 触发器：新增用户时记日志
delimiter $$
create trigger trg_user_insert
after insert on tb_user for each row
begin
    insert into tb_user_log (user_id, action)
    values (new.id, 'insert');
end $$
delimiter ;

-- DELETE 触发器
delimiter $$
create trigger trg_user_delete
after delete on tb_user for each row
begin
    insert into tb_user_log (user_id, action)
    values (old.id, 'delete');
end $$
delimiter ;

-- 测试
insert into tb_user (name) values ('张三');
delete from tb_user where name = '张三';
select * from tb_user_log;   -- 有两条日志
```

## 15.4 案例：更新前校验（BEFORE）

```sql
-- 修改年龄前校验，非法则报错
delimiter $$
create trigger trg_user_age_check
before update on tb_user for each row
begin
    if new.age < 0 or new.age > 150 then
        signal sqlstate '45000' set message_text = '年龄不合法';
    end if;
end $$
delimiter ;

update tb_user set age = 200 where id = 1;   -- ❌ 报错：年龄不合法
```

> `signal sqlstate '45000'` 是 MySQL 中主动抛错的写法。

---

## 15.5 查看与删除

```sql
-- 查看
show triggers;
select * from information_schema.triggers
where trigger_schema = 'study';

-- 删除
drop trigger if exists trg_user_insert;
```

## 15.6 优缺点

| 优点 | 缺点 |
|------|------|
| 自动执行，保证一致性 | **难调试、隐式逻辑** |
| 集中业务规则在 DB | 影响性能（每次操作都执行） |
| 记录日志省事 | 业务逻辑分散、难维护 |

> **实战建议**：触发器在互联网项目**很少用**。日志、审计一般由应用层（AOP/中间件）或 binlog 实现。但触发器是面试常见概念题。

---

## 15.7 与存储过程的区别

| 对比 | 触发器 | 存储过程 |
|------|--------|---------|
| 调用方式 | **自动**（事件触发） | 手动 `call` |
| 参数 | 无参数 | 支持参数 |
| 控制 | 无法直接调用 | 可显式调用 |
| 典型用途 | 日志、校验、同步 | 业务逻辑批处理 |

---

## 小结

- 触发器在增删改前后**自动执行**，行级 `for each row`。
- `NEW` 指新数据，`OLD` 指旧数据（依事件而定）。
- 用 `signal sqlstate '45000'` 主动抛错。
- `show triggers` 查看，`drop trigger` 删除。
- 实战少用，面试常考。
