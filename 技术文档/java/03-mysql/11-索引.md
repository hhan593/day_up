# 11 - 索引

> 目标：理解索引原理（B+Tree），掌握索引分类、创建、失效场景与 EXPLAIN。**面试最核心章节**。

---

## 11.1 什么是索引

索引是**帮助 MySQL 高效获取数据的数据结构**（类似书的目录）。

- 优点：**大幅加快查询速度**、加速排序与分组。
- 缺点：**占磁盘空间**、增删改时要**维护索引**（变慢）。

> 一句话：**索引是以空间和写入性能换查询性能**。

---

## 11.2 索引的数据结构

| 结构 | 说明 | 是否常用 |
|------|------|---------|
| **B+Tree** | MySQL 索引的**默认结构** | ✅ |
| Hash | 等值查询快，不支持范围查询 | 少数场景（Memory） |
| 全文索引 | 文本检索 | 特定场景 |
| R-Tree | 空间数据 | 极少 |

### 为什么用 B+Tree

| 对比 | B+Tree 优势 |
|------|------------|
| vs 二叉树 | 树矮（3~4 层可存千万级），IO 次数少 |
| vs B-Tree | 非叶子只存索引不存数据 → 单节点能放更多 key，树更矮；叶子有双向链表，**范围查询快** |
| vs Hash | 支持范围查询、排序、最左前缀 |

> B+Tree 特点：**非叶子节点只存键，数据全在叶子节点，叶子间是双向链表**。

### 聚簇索引 vs 二级索引

| 对比 | 聚簇索引（主键） | 二级索引（普通/唯一） |
|------|-----------------|---------------------|
| 叶子存什么 | **整行数据** | 索引列 + **主键值** |
| 数量 | 一张表只有一个 | 可以有多个 |
| 查询 | 直接拿到数据 | 需**回表**（拿主键再查聚簇索引） |

## 11.3 索引分类

| 分类 | 说明 |
|------|------|
| **主键索引** | 主键自动创建，唯一且非空 |
| **唯一索引** | `UNIQUE`，值不重复 |
| **普通索引** | 最基础，无限制 |
| **联合索引** | 多列组合，遵循**最左前缀** |
| **全文索引** | 文本检索（`FULLTEXT`） |

按物理存储分：
- **聚簇索引**：主键索引。
- **二级索引（辅助索引）**：普通/唯一/联合索引。

## 11.4 创建与管理索引

```sql
-- 建表时创建
create table tb_user (
    id       int primary key,               -- 主键索引（自动）
    phone    varchar(11) unique,            -- 唯一索引（自动命名）
    name     varchar(20),
    age      int,
    index idx_name (name),                  -- 普通索引
    index idx_age_name (age, name)          -- 联合索引
);

-- 建表后添加
create index idx_name on tb_user(name);
create unique index uk_phone on tb_user(phone);
alter table tb_user add index idx_age (age);

-- 查看索引
show index from tb_user;

-- 删除索引
drop index idx_name on tb_user;
alter table tb_user drop index idx_age;
```

> **建议**：索引命名规范 `idx_字段名` / `uk_字段名` / `pk_字段名`。

## 11.5 最左前缀原则（重点）

**联合索引 `(a, b, c)` 能命中的查询条件**：

```sql
index idx_abc (a, b, c)

✅ where a = 1
✅ where a = 1 and b = 2
✅ where a = 1 and b = 2 and c = 3
✅ where a = 1 and c = 3          -- 只用到 a
❌ where b = 2                    -- 跳过 a，不命中
❌ where b = 2 and c = 3
❌ where c = 3
```

规律：**从左到右连续匹配**，中间断了就只用前面的部分。

> 建立联合索引时，**区分度高的字段放左边**（如 `(user_id, status)` 优于 `(status, user_id)`）。

---

## 11.6 索引失效场景（重点）

| 场景 | 例子 | 原因 |
|------|------|------|
| 对索引列做运算 | `where id + 1 = 10` | 索引列被计算 |
| 函数作用于索引列 | `where substring(name,1,2)='张'` | 同上 |
| 隐式类型转换 | `where phone = 13800138000`（phone 是 varchar） | 类型不一致 |
| `like` 以 `%` 开头 | `where name like '%三'` | 无法用前缀 |
| `or` 连接非索引列 | `where name='a' or age=1`（age 无索引） | 需全表 |
| `!=` / `<>` | `where age != 18` | 优化器可能放弃 |
| `is null` / `is not null` | 视情况 | 数据分布决定 |
| 不符合最左前缀 | `where b=2`（联合索引 a,b） | 跳过最左列 |

```sql
-- ❌ 失效：函数
select * from tb_user where year(create_time) = 2026;
-- ✅ 改写：范围
select * from tb_user where create_time >= '2026-01-01' and create_time < '2027-01-01';

-- ❌ 失效：以 % 开头
select * from tb_user where name like '%张';
-- ✅ 前缀匹配
select * from tb_user where name like '张%';
```

## 11.7 覆盖索引与回表

**回表**：二级索引查到主键后，再回聚簇索引取整行，多一次查找。

**覆盖索引**：查询的列**都在索引里**，无需回表。

```sql
-- 建立联合索引
index idx_name_age (name, age)

-- ✅ 覆盖索引：select 的列都在索引中，不用回表
select name, age from tb_user where name = '张三';

-- ❌ 需回表：需要 gender，索引里没有
select name, age, gender from tb_user where name = '张三';
```

> **优化技巧**：`select` 只查索引包含的列，避免回表。

## 11.8 EXPLAIN 执行计划

```sql
explain select * from tb_user where name = '张三';
```

| 字段 | 关注点 |
|------|--------|
| `type` | 访问类型：`system > const > eq_ref > ref > range > index > ALL`，**最好到 range 及以上，避免 ALL（全表）** |
| `key` | 实际使用的索引（NULL 表示没走索引） |
| `key_len` | 索引使用长度（判断联合索引用了几列） |
| `rows` | 预估扫描行数（越小越好） |
| `Extra` | `Using index`（覆盖索引，好）、`Using where`、`Using filesort`（需优化）、`Using temporary`（需优化） |

```sql
-- 典型：避免 type=ALL 和 Extra=Using filesort
explain select name, age from tb_user where name = '张三' order by age;
```

## 11.9 索引设计建议

| 建议 | 说明 |
|------|------|
| 主键用**自增整数** | 避免页分裂，写入快 |
| 频繁作为 WHERE 条件的列建索引 | |
| 联合索引**区分度高的放左边** | |
| 长字符串用**前缀索引** | `index(name(10))` |
| 避免过多索引 | 每个索引都拖慢写入 |
| 尽量用**覆盖索引** | 减少回表 |
| 频繁更新的列慎建索引 | 维护成本高 |

---

## 小结

- 索引是 B+Tree 结构，以空间/写入换查询。
- 主键索引是聚簇索引（叶子存整行），二级索引叶子存主键（可能回表）。
- 联合索引遵循**最左前缀**。
- 索引失效常见：函数/运算、隐式转换、`%` 开头 like、`or`、不符合最左。
- `EXPLAIN` 看 `type` / `key` / `rows` / `Extra`。
- 覆盖索引可避免回表。
