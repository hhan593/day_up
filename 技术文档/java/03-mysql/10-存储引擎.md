# 10 - 存储引擎

> 目标：理解存储引擎概念，掌握 InnoDB 与 MyISAM 的区别与选型。

---

## 10.1 什么是存储引擎

存储引擎是 MySQL 中**真正负责数据存取**的组件（「表的类型」）。

MySQL 的核心特点是**插件式存储引擎**：同一数据库中不同表可以用不同引擎。

```sql
-- 查看支持的引擎
show engines;

-- 查看表的引擎
show create table tb_user;      -- 看 ENGINE= 部分
show table status like 'tb_user';

-- 建表时指定引擎
create table t (
    id int primary key
) engine = InnoDB;

-- 修改已有表的引擎
alter table t engine = MyISAM;
```

---

## 10.2 三种常见引擎

### InnoDB（默认，重点）

- MySQL 5.5 起的**默认引擎**。
- 支持**事务**、**行级锁**、**外键**。
- 支持崩溃恢复（redo log）。
- 索引结构为**聚簇索引**（数据挂在主键 B+Tree 叶子上）。

### MyISAM（老引擎）

- MySQL 5.5 之前的默认引擎。
- **不支持事务、不支持行锁、不支持外键**。
- 只有**表级锁**。
- 访问速度快（读多写少场景）。
- 索引为**非聚簇索引**（索引与数据分离）。

### Memory

- 数据存**内存**，速度极快，但**重启丢失**。
- 常用于临时表、缓存表。

---

## 10.3 InnoDB vs MyISAM 对比（重点）

| 对比项 | InnoDB | MyISAM |
|--------|--------|--------|
| 事务 | ✅ 支持 | ❌ 不支持 |
| 锁粒度 | **行级锁** | 表级锁 |
| 外键 | ✅ 支持 | ❌ 不支持 |
| 崩溃恢复 | ✅（redo log） | ❌ 较差 |
| 索引结构 | 聚簇索引 | 非聚簇索引 |
| 全文索引 | 8.0 支持 | 支持 |
| 适用场景 | **增删改多、需事务** | 读多写少、不需事务 |

> **结论**：99% 的场景用 **InnoDB**。MyISAM 主要出现在老项目和面试对比题中。

---

## 10.4 存储引擎的选择

| 场景 | 推荐 |
|------|------|
| 一般业务表（需事务） | **InnoDB** |
| 需要外键 | InnoDB |
| 高并发写入 | InnoDB（行锁） |
| 只读缓存表（可丢） | Memory |
| 日志/归档表（老系统） | MyISAM |

---

## 10.5 案例：查看与切换引擎

```sql
-- 1. 查看所有引擎及其是否默认、是否支持事务
show engines;
-- 关注：InnoDB (DEFAULT, YES/YES)，MyISAM (YES/NO)

-- 2. 建两张不同引擎的表对比
create table t_innodb (id int primary key, name varchar(20)) engine = InnoDB;
create table t_myisam (id int primary key, name varchar(20)) engine = MyISAM;

-- 3. 在 t_myisam 上测事务（无效）
start transaction;
insert into t_myisam (id, name) values (1, 'a');
rollback;
select * from t_myisam;    -- 仍然有数据！MyISAM 不支持回滚

-- 4. 在 t_innodb 上测事务（有效）
start transaction;
insert into t_innodb (id, name) values (1, 'a');
rollback;
select * from t_innodb;    -- 空，回滚成功
```

> 这是理解「MyISAM 不支持事务」最直观的实验。

---

## 小结

- 存储引擎 = 表的底层数据存取实现，MySQL 支持插件式引擎。
- **InnoDB**：默认，支持事务/行锁/外键/崩溃恢复，用聚簇索引。
- **MyISAM**：不支持事务/行锁/外键，只有表锁，读多写少场景。
- **Memory**：存内存，重启丢失。
- 生产默认选 **InnoDB**。
