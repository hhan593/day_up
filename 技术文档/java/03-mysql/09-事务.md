# 09 - 事务

> 目标：理解事务与 ACID，掌握隔离级别与并发问题。**面试必考章节**。

---

## 9.1 什么是事务

事务（Transaction）是一组**要么全部成功、要么全部失败**的 SQL 操作。

经典案例：**转账**——A 扣钱和 B 加钱必须同时成功或同时失败。

```sql
-- 开启事务
start transaction;      -- 或 begin;

update account set balance = balance - 100 where name = 'A';
update account set balance = balance + 100 where name = 'B';

-- 提交（生效）
commit;

-- 或回滚（撤销所有改动）
-- rollback;
```

> MySQL 默认**自动提交**（`autocommit = 1`），每条 SQL 立即生效。开启事务后需手动 `commit`。

```sql
select @@autocommit;          -- 1 表示自动提交
set @@autocommit = 0;         -- 关闭自动提交（当前会话）
```

## 9.2 ACID 四大特性

| 特性 | 含义 | 实现机制 |
|------|------|---------|
| **A** 原子性 Atomicity | 要么全成功，要么全失败 | **undo log** |
| **C** 一致性 Consistency | 事务前后数据完整性一致 | 由其他三者共同保证 |
| **I** 隔离性 Isolation | 并发事务互不干扰 | **锁 + MVCC** |
| **D** 持久性 Durability | 提交后永久保存 | **redo log** |

> 记忆：原子靠 undo，持久靠 redo，隔离靠锁+MVCC，一致是目的。

---

## 9.3 并发事务问题

多事务并发时可能出现：

| 问题 | 现象 | 例子 |
|------|------|------|
| **脏读** | 读到其他事务**未提交**的数据 | A 改了但没提交，B 读到了；A 回滚，B 读到假数据 |
| **不可重复读** | 同一事务内**两次读同一条**结果不同 | B 第一次读 100，A 改成 200 提交，B 再读变 200 |
| **幻读** | 同一事务内**两次查询行数**不同 | B 查「有 3 条」，A 插入 1 条提交，B 再查变 4 条 |

> 区别：不可重复读针对**单行的修改**，幻读针对**行数的增减**。

---

## 9.4 隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|------|-----------|------|------|
| `READ UNCOMMITTED` | ❌ 会 | ❌ 会 | ❌ 会 | 最低，几乎不用 |
| `READ COMMITTED` | ✅ 避免 | ❌ 会 | ❌ 会 | Oracle 默认 |
| **`REPEATABLE READ`** | ✅ | ✅ | ✅* | **MySQL 默认**（*靠间隙锁基本避免幻读） |
| `SERIALIZABLE` | ✅ | ✅ | ✅ | 最高，串行执行，性能差 |

```sql
-- 查看当前隔离级别（8.0）
select @@transaction_isolation;

-- 设置隔离级别
set session transaction isolation level read committed;
set global transaction isolation level repeatable read;
```

> **重点**：MySQL 默认 `REPEATABLE READ`，且通过 **MVCC + 间隙锁**在大多数场景下也避免了幻读。隔离级别越高越安全但并发性能越差。

---

## 9.5 MVCC 简介

MVCC（Multi-Version Concurrency Control，多版本并发控制）：

- 通过 **undo log 版本链 + ReadView** 实现「读写不阻塞」。
- **快照读**（普通 `select`）：读历史版本，不加锁，走 MVCC。
- **当前读**（`select ... for update` / `lock in share mode`、`insert`、`update`、`delete`）：读最新版本，加锁。

```sql
-- 快照读（MVCC，不加锁）
select * from account where id = 1;

-- 当前读（加锁）
select * from account where id = 1 for update;
select * from account where id = 1 lock in share mode;
```

| 对比 | 快照读 | 当前读 |
|------|--------|--------|
| 语句 | 普通 select | for update / lock in share mode |
| 读的内容 | 历史版本（MVCC） | 最新版本 |
| 加锁 | 不加锁 | 加锁 |

> 详细原理见 [17-InnoDB引擎](./17-InnoDB引擎.md)。

## 9.6 两种提交方式对比

### 手动提交

```sql
set @@autocommit = 0;
update ...;
commit;      -- 或 rollback;
```

### 显式开启事务

```sql
start transaction;
update ...;
savepoint s1;         -- 设置保存点
update ...;
rollback to s1;       -- 回滚到保存点（不是全部回滚）
commit;
```

## 9.7 案例：转账并验证回滚

```sql
drop table if exists account;
create table account (
    id      int primary key auto_increment,
    name    varchar(20),
    balance decimal(10,2) check (balance >= 0)
);
insert into account (name, balance) values ('A', 1000), ('B', 1000);

-- 转账 200
start transaction;
update account set balance = balance - 200 where name = 'A';
update account set balance = balance + 200 where name = 'B';
-- 检查
select * from account;
commit;

-- 模拟失败回滚
start transaction;
update account set balance = balance - 5000 where name = 'A';  -- 余额不足
rollback;      -- 撤销
select * from account;   -- 数据未变
```

---

## 小结

- 事务 = 一组原子操作，`start transaction` → `commit`/`rollback`。
- ACID：原子(undo)、一致、隔离(锁+MVCC)、持久(redo)。
- 并发问题：脏读、不可重复读、幻读。
- MySQL 默认隔离级别 **REPEATABLE READ**。
- MVCC 实现「快照读不加锁」，当前读加锁。
