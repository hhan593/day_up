# 10. NestJS 认证鉴权实战（JWT + Refresh Token 完整方案）

> 来源可信度：**官方文档确认 + 标准实践**（基于 NestJS 官方 Security 章节、`@nestjs/jwt`、`@nestjs/passport`、`passport-jwt` 公开 API）
> 关联：`03-security/`（分散主题）、`01-fundamentals/guards.md`、`01-fundamentals/custom-decorators.md`
> 本目录子文档 `09-recipes/authentication.md` 讲基础概念，**本文聚焦生产级完整实现**（含 Refresh Token 轮换、注销、多端登出）。

## 1. 整体架构

```
┌────────┐  ① POST /auth/login (用户名+密码)
│ Client │ ─────────────────────────────────►  验证凭据
└────────┘                                       │
     ▲                                           ▼
     │  ② 返回 accessToken(15min) + refreshToken(7d, httpOnly cookie)
     │                                           │
     │  ③ 请求带 Authorization: Bearer <access>
     │     ─────────────────────────────────►   JwtAuthGuard 校验
     │                                           │
     │  ④ access 过期 → POST /auth/refresh (带 refresh cookie)
     │     ─────────────────────────────────►   轮换 refresh，发新 access
     │                                           │
     └─── ⑤ POST /auth/logout → 清除 cookie + 加入黑名单
```

**要点**：

- **Access Token**：短寿命（15 分钟），放内存/`Authorization` 头。
- **Refresh Token**：长寿命（7 天），存 **httpOnly + Secure + SameSite** Cookie（防 XSS 窃取），并**在服务端记录**（Redis/DB）以便吊销。

## 3. 核心实现

### 3.1 Jwt 模块注册（异步配置）

```ts
// auth.module.ts
import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule,
    PassportModule,
    JwtModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        secret: config.get<string>('JWT_ACCESS_SECRET'),
        signOptions: {
          expiresIn: config.get('JWT_ACCESS_EXPIRES', '15m'),
          issuer: 'myapp',
        },
      }),
    }),
  ],
  controllers: [AuthController],
  providers: [AuthService, LocalStrategy, JwtStrategy, RefreshStrategy],
  exports: [AuthService],
})
export class AuthModule {}
```

### 3.2 签发与校验（AuthService）

```ts
// auth.service.ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { ConfigService } from '@nestjs/config';
import * as bcrypt from 'bcrypt';
import { RedisService } from '../redis/redis.service';

type TokenPayload = { sub: string; email: string; roles: string[] };

@Injectable()
export class AuthService {
  constructor(
    private jwt: JwtService,
    private config: ConfigService,
    private redis: RedisService,
  ) {}

  // ① 校验用户凭据
  async validateUser(email: string, password: string) {
    const user = await this.users.findByEmail(email);   // 伪代码
    if (!user) throw new UnauthorizedException('凭据错误');
    // bcrypt 校验（永远用慢哈希，见 Rust 52 篇同一原则）
    const ok = await bcrypt.compare(password, user.passwordHash);
    if (!ok) throw new UnauthorizedException('凭据错误');
    return user;
  }

  // ② 签发一对令牌
  async login(user: User, deviceId: string) {
    const payload: TokenPayload = {
      sub: user.id,
      email: user.email,
      roles: user.roles,
    };

    const accessToken = this.jwt.sign(payload);   // 用 JwtModule 的 secret

    // refresh 用**独立 secret**，防止 access 反过来当 refresh 用
    const refreshToken = this.jwt.sign(
      { ...payload, deviceId, type: 'refresh' },
      {
        secret: this.config.get('JWT_REFRESH_SECRET'),
        expiresIn: this.config.get('JWT_REFRESH_EXPIRES', '7d'),
      },
    );

    // 服务端记录 refresh（用于吊销 / 多端管理）
    await this.redis.set(
      `refresh:${user.id}:${deviceId}`,
      refreshToken,
      'EX',
      7 * 24 * 3600,
    );

    return { accessToken, refreshToken };
  }

  // ③ 轮换 refresh（关键安全设计）
  async refresh(oldToken: string, deviceId: string) {
    let payload: any;
    try {
      payload = this.jwt.verify(oldToken, {
        secret: this.config.get('JWT_REFRESH_SECRET'),
      });
    } catch {
      throw new UnauthorizedException('refresh token 无效');
    }
    if (payload.type !== 'refresh') throw new UnauthorizedException('令牌类型错误');

    // 对比服务端记录，防止已吊销的 refresh 继续使用
    const stored = await this.redis.get(`refresh:${payload.sub}:${deviceId}`);
    if (!stored || stored !== oldToken) {
      throw new UnauthorizedException('refresh token 已失效，请重新登录');
    }

    const user = await this.users.findById(payload.sub);
    if (!user) throw new UnauthorizedException('用户不存在');

    // ★ 轮换：签发新的 refresh 并覆盖旧的（Replay 检测）
    return this.login(user, deviceId);
  }

  // ④ 登出：删除服务端记录
  async logout(userId: string, deviceId: string) {
    await this.redis.del(`refresh:${userId}:${deviceId}`);
  }

  // ⑤ 全端登出（改密码/安全风险时）
  async logoutAll(userId: string) {
    const keys = await this.redis.keys(`refresh:${userId}:*`);
    if (keys.length) await this.redis.del(...keys);
  }
}
```

> **轮换（Rotation）的意义**：每次 refresh 都换发新 token 并作废旧的。若旧 token 被重放（说明泄漏），服务端检测到不匹配 → 立即失效整条链。

### 3.3 JWT Strategy

```ts
// strategies/jwt.strategy.ts
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy, 'jwt') {
  constructor(config: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: config.get<string>('JWT_ACCESS_SECRET'),
    });
  }

  // 校验通过后，返回值挂到 request.user
  async validate(payload: any) {
    if (!payload?.sub) throw new UnauthorizedException();
    // 可在此查库/查缓存，确认用户仍有效
    return { userId: payload.sub, email: payload.email, roles: payload.roles ?? [] };
  }
}
```

### 3.4 全局守卫 + @Public 免鉴权

```ts
// decorators/public.decorator.ts
import { SetMetadata, applyDecorators } from '@nestjs/common';
export const IS_PUBLIC_KEY = 'isPublic';
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);

// guards/jwt-auth.guard.ts —— 支持 @Public 跳过
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  constructor(private reflector: Reflector) {
    super();
  }

  canActivate(ctx: ExecutionContext) {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      ctx.getHandler(),
      ctx.getClass(),
    ]);
    if (isPublic) return true;
    return super.canActivate(ctx);
  }
}

// main.ts 全局启用
app.useGlobalGuards(new JwtAuthGuard(app.get(Reflector)));
```

```ts
// 使用
@Public()
@Post('login')
login(@Body() dto: LoginDto) { /* ... */ }

@Get('profile')       // 默认需鉴权
getProfile(@Req() req) { return req.user; }
```

### 3.5 角色/权限守卫

```ts
// decorators/roles.decorator.ts
export const ROLES_KEY = 'roles';
export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);

// guards/roles.guard.ts
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(ctx: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      ctx.getHandler(), ctx.getClass(),
    ]);
    if (!required?.length) return true;          // 未声明则放行

    const { user } = ctx.switchToHttp().getRequest();
    return required.some((role) => user?.roles?.includes(role));
  }
}
```

```ts
@Roles('admin')
@Delete('users/:id')
remove(@Param('id') id: string) { /* ... */ }
```

> 顺序：`JwtAuthGuard`（认证）→ `RolesGuard`（授权）。用 `@UseGuards(JwtAuthGuard, RolesGuard)` 或全局 + 局部组合。

## 4. Controller（含 Cookie 处理）

```ts
// auth.controller.ts
import { Controller, Post, Body, Res, Req, UseGuards, HttpCode } from '@nestjs/common';
import { Response, Request } from 'express';

@Controller('auth')
export class AuthController {
  constructor(private auth: AuthService) {}

  @Public()
  @Post('login')
  @HttpCode(200)
  async login(
    @Body() dto: LoginDto,
    @Res({ passthrough: true }) res: Response,
  ) {
    const user = await this.auth.validateUser(dto.email, dto.password);
    const deviceId = randomUUID();

    const { accessToken, refreshToken } = await this.auth.login(user, deviceId);

    // refresh token 存 httpOnly cookie（JS 读不到 → 防 XSS）
    res.cookie('refresh_token', refreshToken, {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',   // 生产必须 HTTPS
      sameSite: 'lax',
      maxAge: 7 * 24 * 3600 * 1000,
      path: '/auth',                                    // 只在 /auth 路径发送
    });

    return { accessToken, deviceId };
  }

  @Public()
  @Post('refresh')
  async refresh(
    @Req() req: Request,
    @Body('deviceId') deviceId: string,
  ) {
    const token = req.cookies?.refresh_token;
    if (!token) throw new UnauthorizedException('缺少 refresh token');
    return this.auth.refresh(token, deviceId);
  }

  @Post('logout')
  @HttpCode(204)
  async logout(
    @Req() req,
    @Res({ passthrough: true }) res: Response,
  ) {
    await this.auth.logout(req.user.userId, req.body.deviceId);
    res.clearCookie('refresh_token', { path: '/auth' });
  }
}
```

## 5. 安全加固清单

| 措施 | 说明 |
|------|------|
| **httpOnly Cookie** | refresh token 不放 localStorage（防 XSS） |
| **Secure + SameSite** | 生产环境强制 HTTPS；`SameSite` 防 CSRF |
| **独立 secret** | access 与 refresh 用不同密钥 |
| **轮换 refresh** | 每次刷新换发新 token，旧 token 立即失效 |
| **服务端记录** | Redis 存 refresh，支持吊销与重放检测 |
| **短 access 寿命** | 15 分钟，泄漏影响窗口小 |
| **bcrypt/argon2 存密码** | 绝不明文或 SHA |
| **限流** | `@nestjs/throttler` 限制登录尝试 |
| **CSRF 防护** | SameSite cookie + 必要时 csurf |
| **密钥管理** | 从环境变量/密钥管理服务读取，不进代码库 |

### 登录限流

```ts
// app.module.ts
ThrottlerModule.forRoot({ throttlers: [{ ttl: 60000, limit: 10 }] }),

// controller
@Public()
@Throttle({ default: { limit: 5, ttl: 60000 } })   // 1 分钟最多 5 次
```

## 7. 常见坑

| 坑 | 解决 |
|----|------|
| Guard 里拿不到 `user` | 确认 strategy 的 `validate()` 有返回值 |
| `@Public()` 不生效 | 全局守卫需用 `Reflector.getAllAndOverride` 读元数据 |
| Cookie 前端读不到 | httpOnly 是**故意**的，refresh 不该被 JS 读 |
| 跨域带不上 cookie | 前端 `withCredentials: true` + 后端 CORS `credentials: true` |
| 刷新后旧 token 还能用 | 必须做轮换 + 服务端校验（见 3.2 ③） |
| 角色校验失效 | RolesGuard 需在 JwtAuthGuard **之后**执行 |

## 8. 一句话总结

> 生产级 Nest 认证 = **短命 access（Bearer 头） + 长命 refresh（httpOnly Cookie + 服务端 Redis 记录 + 轮换）**；用 `PassportStrategy` 校验、全局 `JwtAuthGuard` 配 `@Public()` 放行、`RolesGuard` 做授权；安全要点是 httpOnly/Secure/SameSite、独立 secret、轮换防重放、`@nestjs/throttler` 限流、bcrypt 存密码。
