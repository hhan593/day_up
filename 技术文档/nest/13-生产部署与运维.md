## 1. 构建产物

```bash
npm run build
# 产物在 dist/（Nest 默认输出到 dist，单项目）
# 生产只装依赖（不含 devDependencies）
npm ci --omit=dev
node dist/main
```

### 生产检查清单

| 项 | 建议 |
|----|------|
| 依赖 | `npm ci --omit=dev`，锁版本（提交 package-lock.json） |
| 环境变量 | 用 `@nestjs/config` + 校验（`validate`） |
| 日志 | 生产级别 `warn/error`，结构化 JSON（pino） |
| 错误处理 | 全局异常过滤器，不泄漏堆栈 |
| 优雅关停 | `enableShutdownHooks()` |
| 健康检查 | `/health` 端点 |
| 资源限制 | 内存/CPU limit |

## 2. 环境变量与配置校验（启动即失败）

```ts
// config/validation.schema.ts
import * as Joi from 'joi';

export const validationSchema = Joi.object({
  NODE_ENV: Joi.string().valid('development', 'production', 'test').default('production'),
  PORT: Joi.number().default(3000),
  DATABASE_URL: Joi.string().required(),          // 缺失直接启动失败
  REDIS_URL: Joi.string().required(),
  JWT_ACCESS_SECRET: Joi.string().min(32).required(),
  JWT_REFRESH_SECRET: Joi.string().min(32).required(),
  CORS_ORIGIN: Joi.string().default('*'),
}).unknown(true);
```

```ts
// app.module.ts
ConfigModule.forRoot({
  isGlobal: true,
  validationSchema,
  validationOptions: { abortEarly: true },     // 第一个错误就停
  cache: true,                                   // 缓存 process.env 读取
}),
```

> **原则**：配置错误应在**启动时**暴露，而非运行中炸。

## 3. 优雅关停（Graceful Shutdown）

```ts
// main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // ★ 监听 SIGTERM（K8s/Docker 停止容器时发出）
  app.enableShutdownHooks();

  await app.listen(process.env.PORT ?? 3000);
}
```

```ts
// 在服务里处理清理逻辑
@Injectable()
export class DatabaseService implements OnModuleDestroy {
  private pool: Pool;

  async onModuleDestroy() {
    // 关闭 DB 连接池、Redis 连接、停止定时任务
    await this.pool.end();
    console.log('cleanup done');
  }
}
```

**生命周期钩子**：`onModuleInit` → `onApplicationBootstrap`（监听后）→ `onModuleDestroy` → `beforeApplicationShutdown`（收到信号）→ `onApplicationShutdown`（连接关闭后）。

### 配合 K8s 时序

```
K8s 发 SIGTERM
  → 从 Service 摘除 Endpoint（不再接新流量）
  → beforeApplicationShutdown（等待进行中的请求完成）
  → onApplicationShutdown（关闭 DB/Redis）
  → 进程退出（超过 terminationGracePeriodSeconds 则 SIGKILL）
```

## 4. 健康检查

```bash
npm i @nestjs/terminus
```

```ts
// health/health.controller.ts
import { Controller, Get } from '@nestjs/common';
import { HealthCheck, HealthCheckService, TypeOrmHealthIndicator, RedisHealthIndicator } from '@nestjs/terminus';

@Controller('health')
export class HealthController {
  constructor(
    private health: HealthCheckService,
    private db: TypeOrmHealthIndicator,
    private redis: RedisHealthIndicator,
  ) {}

  @Get()
  @HealthCheck()
  check() {
    return this.health.check([
      () => this.db.pingCheck('database'),
      () => this.redis.pingCheck('redis'),
    ]);
  }

  // 轻量存活探针（不查依赖，仅确认进程活着）
  @Get('live')
  live() { return { status: 'ok' }; }

  // 就绪探针（依赖就绪才能接流量）
  @Get('ready')
  @HealthCheck()
  ready() {
    return this.health.check([() => this.db.pingCheck('database')]);
  }
}
```

> 区分 **liveness**（不查依赖，挂了就重启）与 **readiness**（查依赖，失败只摘流量不重启）。与 `技术文档/java/29-kubernetes.md` 同一模式。

## 5. 日志

```bash
npm i nestjs-pino pino-http
```

```ts
// main.ts
import { LoggerModule } from 'nestjs-pino';

LoggerModule.forRoot({
  pinoHttp: {
    level: process.env.NODE_ENV === 'production' ? 'info' : 'debug',
    transport: process.env.NODE_ENV !== 'production'
      ? { target: 'pino-pretty' }                 // 开发环境美化
      : undefined,                                 // 生产输出 JSON
    // 生产：结构化 JSON 便于 ELK/Loki 采集
    redact: ['req.headers.authorization', 'req.body.password'],  // 脱敏
    autoLogging: { ignore: (req) => req.url === '/health' },      // 健康检查不打日志
  },
}),
```

## 6. 进程管理：PM2（单机/裸机）

```bash
npm i -g pm2
```

```js
// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'api',
    script: 'dist/main.js',
    instances: 'max',            // 或数字：用满 CPU 核（cluster 模式）
    exec_mode: 'cluster',
    max_memory_restart: '1G',    // 内存超限自动重启
    env: { NODE_ENV: 'development' },
    env_production: {
      NODE_ENV: 'production',
      PORT: 3000,
    },
    error_file: './logs/err.log',
    out_file: './logs/out.log',
  }],
};
```

```bash
pm2 start ecosystem.config.js --env production
pm2 reload ecosystem.config.js      # 零停机重载
pm2 monit
pm2 logs
pm2 save && pm2 startup             # 开机自启
```

> 与 `技术文档/node/14-pm2-deploy.md` / `18-cluster` 配合。集群模式下注意：多进程需外部存储 session/缓存（Redis）。

## 7. Docker 部署

```dockerfile
# ---- 多阶段构建 ----
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
# 只保留生产依赖
RUN npm ci --omit=dev && npm cache clean --force

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production

# 用非 root 用户（安全）
RUN addgroup -g 1001 -S nodejs && adduser -S nestjs -u 1001
COPY --from=builder --chown=nestjs:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nestjs:nodejs /app/dist ./dist
COPY --from=builder --chown=nestjs:nodejs /app/package*.json ./

USER nestjs
EXPOSE 3000

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3000/health/live',r=>process.exit(r.statusCode===200?0:1)).on('error',()=>process.exit(1))"

# ★ 用 dumb-init 处理 PID 1 信号转发
ENTRYPOINT ["dumb-init", "--"]
CMD ["node", "dist/main"]
```

```dockerfile
# 装 dumb-init（alpine）
RUN apk add --no-cache dumb-init
```

> **PID 1 陷阱**：Node 作为 PID 1 不会正确处理 SIGTERM，导致 K8s 停容器时无法优雅关停。用 `dumb-init` 或 `tini` 解决。

`.dockerignore`：

```
node_modules
dist
coverage
.git
*.md
.env
```

## 8. Kubernetes 部署

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nest-api
spec:
  replicas: 3
  selector:
    matchLabels: { app: nest-api }
  template:
    metadata:
      labels: { app: nest-api }
    spec:
      containers:
        - name: api
          image: myregistry/nest-api:1.0.0
          ports:
            - containerPort: 3000
          envFrom:
            - secretRef: { name: nest-api-secrets }    # JWT_SECRET 等
            - configMapRef: { name: nest-api-config }  # NODE_ENV 等
          resources:
            requests: { cpu: 100m, memory: 256Mi }
            limits:   { cpu: 500m, memory: 512Mi }
          livenessProbe:
            httpGet: { path: /health/live, port: 3000 }
            initialDelaySeconds: 15
            periodSeconds: 20
          readinessProbe:
            httpGet: { path: /health/ready, port: 3000 }
            initialDelaySeconds: 10
            periodSeconds: 10
          startupProbe:               # 启动慢时用，避免被 liveness 杀掉
            httpGet: { path: /health/live, port: 3000 }
            failureThreshold: 30
            periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: nest-api
spec:
  selector: { app: nest-api }
  ports:
    - port: 80
      targetPort: 3000
```

```yaml
# HPA 自动扩缩
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: nest-api }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: nest-api }
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 70 } }
```

> Node 内存：容器 `limits.memory` 需 ≥ 应用峰值，并可用 `--max-old-space-size` 对齐（避免 OOMKill）。

## 11. 常见坑

| 坑 | 解决 |
|----|------|
| K8s 停容器请求被截断 | `enableShutdownHooks()` + `dumb-init` + terminationGracePeriod |
| 滚动更新期间 502 | readinessProbe + `preStop` sleep |
| 内存缓慢增长 | 排查泄漏；设 `max_memory_restart` 兜底 |
| 镜像过大 | 多阶段构建 + `--omit=dev` + alpine |
| 时区不对 | 镜像设 `TZ=Asia/Shanghai` |
| 多副本 session 丢失 | session/缓存外置 Redis |
| 构建缓存失效 | 先 COPY package*.json 再 COPY 源码（利用 Docker 层缓存） |

## 12. 一句话总结

> Nest 生产部署：多阶段 Docker（alpine + 非 root + `--omit=dev` + `dumb-init`）→ 配置 Joi 校验（启动即失败）→ `@nestjs/terminus` 分 liveness/readiness → `enableShutdownHooks` 优雅关停 → pino 结构化日志 + Prometheus 指标 → K8s Deployment（resources/probe/HPA + Secret）；PM2 适合裸机集群。核心是**探针正确、关停优雅、密钥外置、观测到位**。
