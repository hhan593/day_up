# 从零搭建 NestJS 全栈骨架（step-by-step）

> 本文档说明如何**从空目录一步步搭出** `docs/project/01-blog`（以及 02-todo / 03-shop / 04-chat）里那套「NestJS 后端 + React 前端 + pnpm workspace」标准骨架。
> 你照着搭好后，再按 `docs/project/0X-*.md` 各方案计划书填充业务代码即可。
> 本文所有命令与配置均与实际骨架一致，可直接复制使用。

---

## 0. 最终目录结构（目标）

```
nest-blog/                         # 方案根目录，可改名 nest-todo / nest-shop / nest-chat
├── pnpm-workspace.yaml            # 声明 packages/* 为工作区
├── package.json                   # 根：concurrently 一条命令并行起前后端
├── .gitignore
├── README.md
└── packages/
    ├── server/                    # NestJS 11 后端
    │   ├── package.json
    │   ├── nest-cli.json
    │   ├── tsconfig.json
    │   ├── .env.example
    │   └── src/
    │       ├── main.ts           # 全局 ValidationPipe + Swagger
    │       └── app.module.ts     # 占位根模块
    └── web/                       # React 19 + Vite 6 前端

        ├── index.html
        └── src/
```

> 本文以 **blog（MySQL + TypeORM）** 为基准。其他方案的差异见文末「§8 四个方案的骨架差异」。

## 1. 初始化根工作区

```bash
# 建方案目录并进入
mkdir nest-blog && cd nest-blog

# 根 package.json：用 concurrently 并行起前后端
cat > package.json <<'EOF'
{
  "name": "nest-blog",
  "version": "0.0.1",
  "private": true,
  "scripts": {
    "dev": "concurrently -n server,web -c blue,green \"pnpm --filter server dev\" \"pnpm --filter web dev\"",
    "dev:server": "pnpm --filter server dev",
    "dev:web": "pnpm --filter web dev",
    "build": "pnpm -r build",
    "start:server": "pnpm --filter server start"
  },
  "devDependencies": {
    "concurrently": "^9.1.0"
  }
}
EOF

# 声明 pnpm workspace（关键：让 -filter 生效）
cat > pnpm-workspace.yaml <<'EOF'
packages:
  - 'packages/*'
EOF

# .gitignore
cat > .gitignore <<'EOF'
node_modules/
dist/
.env
*.log
.DS_Store
EOF
```

> 根目录**不要**装业务依赖，`-filter server` / `-filter web` 会把命令转发到对应子包。

### 2.2 入口与根模块（占位骨架）

`src/main.ts`：

```ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  // 全局校验管道：配合 class-validator / class-transformer，DTO 自动校验
  app.useGlobalPipes(
    new ValidationPipe({ whitelist: true, transform: true, forbidNonWhitelisted: true }),
  );

  // Swagger：访问 /api/docs 查看交互式 API 文档
  const config = new DocumentBuilder()
    .setTitle('Blog API')
    .setDescription('个人博客系统 01 接口文档')
    .setVersion('1.0')
    .addBearerAuth()
    .build();
  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('api/docs', app, document);

  await app.listen(process.env.PORT ?? 3000);
  console.log(`Blog server running on http://localhost:${process.env.PORT ?? 3000}`);
}
bootstrap();
```

`src/app.module.ts`（占位，业务模块后续补）：

```ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

/**
 * 根模块占位骨架。照 01-个人博客系统.md 第 2 节补全：
 *  - ConfigModule.forRoot({ isGlobal: true, load: [configuration] })
 *  - TypeOrmModule.forRootAsync(...) 连真实 MySQL（库名 nest_blog）
 *  - 逐步 imports: UsersModule / AuthModule / ArticlesModule
 */
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
  ],
})
export class AppModule {}
```

> 至此后端骨架可空跑：`pnpm --filter server dev` 会启动在 3000，访问 `/api/docs` 能看到空 Swagger。

## 7. 排错小贴士

- **`pnpm dev` 报 `-filter` 找不到包** → 检查根 `pnpm-workspace.yaml` 是否 `packages: ['packages/*']`，且子包 `name` 是 `server` / `web`。
- **后端启动报 `Cannot find module 'reflect-metadata'`** → 确认 `tsconfig.json` 有 `emitDecoratorMetadata` + `experimentalDecorators`，且 `main.ts` 顶部没漏（Nest 11 已内置，无需手动 import）。
- **前端调用 `/api/xxx` 404** → 确认 `vite.config.ts` 的 proxy 的 `rewrite` 把 `/api` 前缀去掉了（后端路由不带 `/api` 前缀，Swagger 文档路径 `/api/docs` 是例外，已被 nest 自身处理）。
- **MySQL 连接失败** → 先 `forRootAsync` 之前别急着跑业务；本地用 Docker 起 MySQL：`docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 mysql:8`。

## 8. 四个方案的骨架差异

骨架结构完全一致，复制后只需改这几处：

| 项 | 01-blog | 02-todo | 03-shop | 04-chat |
| --- | --- | --- | --- | --- |
| 根 `name` | nest-blog | nest-todo | nest-shop | nest-chat |
| `.env` 库名 | nest_blog | nest_todo | nest_shop | nest_chat |
| Swagger 标题 | Blog API | Todo API | Shop API | Chat API |
| 前端框架 | React 19 | React 19 | React 19 | React 19 |
| 额外后端依赖 | — | `@nestjs/mapped-types` | `@nestjs/mapped-types` | `@nestjs/websockets` + `@nestjs/platform-socket.io` + `socket.io` |
| 额外前端依赖 | — | — | — | `socket.io-client` |
| vite 额外代理 | `/uploads`（封面图） | — | — | —（WS 走 socket，不走 /api 代理） |

> 复制命令参考：`cp -r docs/project/01-blog docs/project/02-todo` 后改 `name` / 库名 / 标题即可，再按 `02-任务管理Todo.md` 填业务。

## 9. 小结

这套骨架解决的是**工程基础设施**：monorepo 组织、前后端热重载、全局校验、Swagger、DB/鉴权依赖就绪、跨域代理。剩下的是「按计划书把实体、模块、页面一个个写进去」的纯业务工作，可以安心照 `0X-*.md` 推进，不必再纠结工程配置。
