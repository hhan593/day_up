# 方案 01：个人博客系统（Blog）

> 复杂度：⭐⭐　适合初学巩固，重点练手守卫、管道、模块共享、全局中间件。

## 1. 项目目标

一个最小可用的个人博客：访客可浏览文章、按分类/标签筛选；作者登录后可发布、编辑、删除自己的文章。后端覆盖本项目已学的中介软件、守卫、管道、模块共享等知识点。

## 2. 功能清单

- **公开端**
  - 文章列表（分页、按分类/标签筛选）
  - 文章详情
  - 文章搜索（关键字）
- **作者端（需登录）**
  - 注册 / 登录（JWT）
  - 发布文章（标题、正文、分类、标签）
  - 编辑 / 删除自己的文章
- **横切关注点**
  - 全局日志中间件记录请求耗时
  - JWT 守卫保护写接口
  - `ParseIntPipe` / DTO 校验管道
  - 统一异常过滤器返回标准错误体

## 3. 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | NestJS 10、TypeORM、SQLite、JWT、class-validator |
| 前端 | Vue 3 + Vite + TS（或 React 18 + Vite + TS） |
| 共享 | pnpm workspace monorepo |

## 4. 目录结构（server）

```
src/
├── main.ts
├── app.module.ts
├── common/
│   ├── middleware/logger.middleware.ts   # 复用本项目函数式中间件思路
│   ├── guards/jwt-auth.guard.ts          # 基于本项目 AuthGuard
│   ├── pipes/                            # ParseIntPipe / 校验管道
│   └── filters/http-exception.filter.ts  # 统一异常过滤器
├── modules/
│   ├── auth/        # 注册/登录，JWT 签发
│   ├── users/       # UserEntity，UserService 共享给 auth
│   └── articles/    # ArticleEntity，CRUD
└── shared/          # 共享模块（@Global 导出 UserService）
```

## 5. 数据库设计

- **User**：id, username, passwordHash, role, createdAt
- **Article**：id, title, content, category, tags(JSON), authorId, createdAt, updatedAt

## 6. API 设计（示例）

| 方法 | 路径 | 守卫 | 说明 |
| --- | --- | --- | --- |
| POST | /auth/register | - | 注册 |
| POST | /auth/login | - | 登录，返回 token |
| GET | /articles?page=&category= | - | 列表 |
| GET | /articles/:id | - | 详情（ParseIntPipe） |
| POST | /articles | JwtAuthGuard | 发布 |
| PATCH | /articles/:id | JwtAuthGuard | 编辑（仅作者） |
| DELETE | /articles/:id | JwtAuthGuard | 删除（仅作者） |

## 7. NestJS 知识点映射

- **全局中间件**：`logger.middleware` 记录请求耗时（复用 `02-中间件` 文档）
- **守卫**：`JwtAuthGuard` 校验 token，保护写接口（复用 `03-守卫`）
- **管道**：`ParseIntPipe` 解析 `:id`；`ValidationPipe` + DTO 校验（复用 `04-管道`）
- **异常过滤器**：统一错误响应（复用 `05-过滤器`）
- **模块共享**：`UsersModule` 导出 `UserService`，`AuthModule` / `ArticlesModule` 导入（复用 `09-模块共享`）

## 8. 前端要点

- 路由：公开页（列表/详情）、登录页、编辑器页
- Axios 拦截器自动附带 JWT，统一处理 401 跳转登录
- 列表分页、标签筛选组件

## 9. 详细实现步骤（命令优先，按优先级分步）

> 约定：所有命令在 `packages/server` 目录下执行（除非说明在根目录）。能用 `nest g` 生成器的一律用命令生成，避免手写文件。每步给出「目标 → 命令 → 改动文件 → 验收」。

### 步骤 0：初始化 monorepo + Nest 后端

```bash
# 根目录
mkdir nest-fullstack && cd nest-fullstack
pnpm init
# 新建 pnpm-workspace.yaml：
# packages:
#   - 'packages/*'

# 生成后端骨架（在 packages/server 下）
pnpm dlx @nestjs/cli new server --package-manager pnpm --strict
cd packages/server

# 安装基础依赖
pnpm add @nestjs/config class-validator class-transformer
pnpm add -D @nestjs/schematics   # 确保 nest g 可用
```
- **验收**：`pnpm start` 能启动，访问 `GET /` 返回 `Hello World!`。

### 步骤 1：全局日志中间件（知识点：中间件）

```bash
# 生成中间件（Nest 生成器会自动建文件并留 TODO）
nest g middleware common/middleware/logger
```
- **改动**：`src/common/middleware/logger.middleware.ts` 实现 `use(req,res,next)` 打印耗时；`src/app.module.ts` 的 `configure(consumer)` 中 `consumer.apply(LoggerMiddleware).forRoutes('*')`。
- **验收**：访问任意接口，控制台出现 `GET /xxx Nms`。

### 步骤 2：UsersModule + 实体 + 服务（知识点：模块共享）

```bash
nest g module modules/users
nest g service modules/users
nest g class modules/users/users.entity --flat   # 实体类（-d 标记 @Entity 手写）
```
- **改动**：`users.entity.ts` 写 `User`（id/username/passwordHash/role/createdAt）；`users.module.ts` 末尾加 `exports: [UsersService]`（共享关键）；装 `pnpm add bcrypt` 用于密码哈希。
- **验收**：`UsersModule` 可被其它模块 `imports` 后注入 `UsersService`。

### 步骤 3：AuthModule + JWT（知识点：守卫 / JWT）

```bash
nest g module modules/auth
nest g service modules/auth
nest g guard modules/auth/jwt-auth        # 生成守卫
pnpm add @nestjs/jwt @nestjs/passport passport passport-jwt
```
- **改动**：
  - `auth.module.ts`：`imports: [UsersModule, JwtModule.register({ secret: 'dev-secret', signOptions:{expiresIn:'1d'} })]`（生产用 ConfigModule 注入 secret）。
  - `auth.service.ts`：`register()` 用 `bcrypt.hash` 存密码；`login()` 校验后 `jwtService.sign({sub:user.id})` 返回 token。
  - `jwt-auth.guard.ts`：继承 `AuthGuard('jwt')` 或手写校验 `Authorization` 头。
- **验收**：`POST /auth/register` 后能 `POST /auth/login` 拿到 token。

### 步骤 4：ArticlesModule CRUD（知识点：管道 / 模块共享）

```bash
nest g module modules/articles
nest g service modules/articles
nest g controller modules/articles
nest g class modules/articles/article.entity --flat
nest g class modules/articles/article.dto --flat
```
- **改动**：
  - `articles.module.ts`：`imports: [TypeOrmModule.forFeature([Article]), UsersModule]`。
  - `article.dto.ts`：用 `class-validator` 装饰（`@IsString() title`、`@IsArray() @IsString({each:true}) tags`）。
  - `articles.controller.ts`：
    - `GET /articles?page=&category=` 公开列表；
    - `GET /articles/:id` 用 `@Param('id', ParseIntPipe)`（非数字自动 400）；
    - `POST/PATCH/DELETE /articles[/:id]` 加 `@UseGuards(JwtAuthGuard)`，PATCH/DELETE 比对 `article.authorId === req.user.id` 防越权。
  - `main.ts`：`app.useGlobalPipes(new ValidationPipe({ transform: true }))`。
- **验收**：无 token 调 `POST /articles` 返回 401；`:id` 传 `abc` 返回 400。

### 步骤 5：统一异常过滤器（知识点：过滤器协作）

```bash
nest g filter common/filters/http-exception
```
- **改动**：过滤器返回标准 `{ code, message, data:null }`；`main.ts` 中 `app.useGlobalFilters(new HttpExceptionFilter())`。
- **验收**：故意 404，响应体结构统一为上述格式。

### 步骤 6：前端 + 联调

```bash
# 前端（选一种）
pnpm dlx create-vite@latest packages/web --template vue-ts
# 或：pnpm dlx create-vite@latest packages/web --template react-ts
cd packages/web && pnpm i && pnpm add axios
```
- **要点**：Axios 拦截器附带 JWT、401 跳登录；列表分页 + 标签筛选组件；编辑器页调 `POST /articles`。
- **验收**：端到端跑通「浏览→登录→发文章→编辑→删除」，补 `README.md` 与 `.env.example`。

> 完成 01 后建议直接进入 **02**，把"自定义装饰器 `@User()`"补上，替代本方案手动从 `req.user` 取值。

## 10. 验收标准

- [ ] `:id` 非数字返回 400 校验错误
- [ ] 请求日志中间件打印耗时
- [ ] 前端可完成「浏览→登录→发文章→编辑→删除」闭环
