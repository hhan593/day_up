# 11. NestJS 性能优化与缓存体系

> 来源可信度：**官方文档确认 + 标准实践**（基于 NestJS 官方 Caching / Compression / Performance 章节、`@nestjs/cache-manager`、`cache-manager` 公开 API）

> 本文聚焦**整合方案**：多级缓存设计、序列化优化、数据库与并发优化、监控指标。

## 1. 优化层次

```
请求 ──► ① CDN / 反向代理缓存
      ──► ② HTTP 缓存头（Cache-Control / ETag）
      ──► ③ 应用层缓存（Redis / 内存）
      ──► ④ 数据库查询缓存 + 索引
      ──► ⑤ 连接池 / 并发控制
```

**原则**：越靠前拦截越省资源。先看能不能不查库（CDN/HTTP 缓存），再考虑应用层缓存。

## 2. 应用层缓存（@nestjs/cache-manager）

```bash

```

### 2.1 内存缓存（单机）

```ts
// app.module.ts
import { CacheModule } from '@nestjs/cache-manager';

CacheModule.register({
  ttl: 5000,        // 默认 5 秒（毫秒）
  max: 1000,        // 最多 1000 条（LRU）
  isGlobal: true,   // 全局可用，无需每个模块 import
}),
```

### 2.2 Redis 缓存（多实例共享，生产推荐）

```ts
import { CacheModule } from '@nestjs/cache-manager';
import { redisStore } from 'cache-manager-ioredis-yet';

CacheModule.registerAsync({
  isGlobal: true,
  useFactory: async () => ({
    store: await redisStore({
      host: process.env.REDIS_HOST,
      port: +process.env.REDIS_PORT,
      password: process.env.REDIS_PASSWORD,
      ttl: 60_000,      // 默认 60 秒
    }),
  }),
}),
```

### 2.3 使用方式

```ts
// 方式一：手动注入
@Injectable()
export class UserService {
  constructor(@Inject(CACHE_MANAGER) private cache: Cache) {}

  async findById(id: string) {
    const key = `user:${id}`;

    const cached = await this.cache.get<User>(key);
    if (cached) return cached;

    const user = await this.repo.findOne({ where: { id } });
    await this.cache.set(key, user, 300_000);     // 缓存 5 分钟
    return user;
  }

  // 更新时要失效缓存
  async update(id: string, dto: UpdateDto) {
    const user = await this.repo.save({ id, ...dto });
    await this.cache.del(`user:${id}`);           // ★ 关键
    return user;
  }
}
```

```ts
// 方式二：自动拦截（CacheInterceptor）
import { CacheInterceptor, CacheTTL, CacheKey } from '@nestjs/cache-manager';

@Controller('users')
@UseInterceptors(CacheInterceptor)        // 自动缓存 GET 响应
export class UserController {
  @Get()
  findAll() { return this.service.findAll(); }   // 自动按 URL 缓存

  @Get(':id')
  @CacheKey('user_detail')                // 自定义 key
  @CacheTTL(60_000)                       // 自定义 TTL
  findOne(@Param('id') id: string) { /* ... */ }
}
```

> ⚠️ `CacheInterceptor` 只缓存 **GET**，且 key 基于 URL。带用户态的接口（如 `/me`）**不能**用，否则串号——此时用手动方式并把 userId 拼进 key。

### 2.4 缓存失效策略

| 策略 | 适用 | 实现 |
|------|------|------|
| **TTL 过期** | 容忍短暂陈旧 | `set(key, val, ttl)` |
| **写时删除** | 一致性要求高 | 更新后 `del(key)` |
| **写时更新** | 读多写少 | 更新后 `set(key, newVal)` |
| **延迟双删** | 高并发防脏读 | 更新前 del → 更新 → sleep → 再 del |
| **Cache-Aside** | 通用 | 读：命中返回，未命中查库回填 |

**经典坑**：缓存穿透（查不存在的 key）、击穿（热点 key 过期瞬间大量打到 DB）、雪崩（大量 key 同时过期）。

```ts
// 防穿透：缓存空值（短期）
if (!user) {
  await this.cache.set(key, null, 60_000);   // 缓存"不存在"
  return null;
}

// 防击穿：互斥锁（单飞）
async getWithLock<T>(key: string, loader: () => Promise<T>, ttl: number) {
  const cached = await this.cache.get<T>(key);
  if (cached !== undefined) return cached;

  const lockKey = `lock:${key}`;
  const acquired = await this.redis.set(lockKey, '1', 'NX', 'EX', 10);
  if (!acquired) {
    await new Promise((r) => setTimeout(r, 50));
    return this.getWithLock(key, loader, ttl);   // 重试
  }
  try {
    const data = await loader();
    await this.cache.set(key, data, ttl);
    return data;
  } finally {
    await this.redis.del(lockKey);
  }
}

// 防雪崩：TTL 加随机抖动
const ttl = 300_000 + Math.floor(Math.random() * 60_000);
```

## 4. 序列化优化

Nest 的 `ClassSerializerInterceptor` 用 `class-transformer` 自动排除 `@Exclude()` 字段，避免手写 DTO 映射。

```ts
// entity
import { Exclude, Expose } from 'class-transformer';

export class User {
  id: string;
  email: string;

  @Exclude()                    // 永不返回给客户端
  passwordHash: string;

  @Expose()                     // 计算属性
  get displayName() {
    return this.email.split('@')[0];
  }
}

// controller
@UseInterceptors(ClassSerializerInterceptor)
@Get()
findAll(): User[] { return this.service.findAll(); }
```

> 与 `02-techniques/serialization.md` 配合。**注意**：`ClassSerializerInterceptor` 有反射开销，极高性能场景可手写 DTO 映射换取速度。

## 5. 数据库优化

| 手段 | 说明 |
|------|------|
| **索引** | 为查询条件、`JOIN` 字段建索引；用 `EXPLAIN` 验证 |
| **避免 N+1** | ORM 用 `relations` / `leftJoinAndSelect` 一次性取关联 |
| **只查需要的字段** | `select: ['id', 'name']` 而非 `find()` 全字段 |
| **分页** | 游标分页优于 `OFFSET`（大数据量时 OFFSET 慢） |
| **连接池** | 配 `poolSize`（TypeORM `extra.max`） |
| **读写分离** | 读走从库 |
| **批量操作** | `insert(values)` 批量而非循环 save |

```ts
// ❌ N+1：每篇文章单独查作者
const posts = await postRepo.find();
for (const p of posts) p.author = await userRepo.findOne(p.authorId);

// ✅ 一次 JOIN
const posts = await postRepo
  .createQueryBuilder('post')
  .leftJoinAndSelect('post.author', 'author')
  .select(['post.id', 'post.title', 'author.name'])   // 只取需要字段
  .take(20)
  .getMany();
```

## 6. 并发与异步

```ts
// ❌ 串行：总耗时 = 各项之和
const a = await fetchA();
const b = await fetchB();
const c = await fetchC();

// ✅ 并行：总耗时 = 最慢的一项（无依赖时用）
const [a, b, c] = await Promise.all([fetchA(), fetchB(), fetchC()]);

// 有依赖的部分仍串行
const user = await getUser(id);
const [orders, profile] = await Promise.all([
  getOrders(user.id),
  getProfile(user.id),
]);
```

> Node 是单线程事件循环（见 `技术文档/node/02-event-loop-async.md`）：**不要在请求路径里做同步 CPU 密集计算**（大 JSON 解析、加密、图像处理）——会阻塞所有请求。重计算交给 `worker_threads` 或独立服务。

## 8. 监控与度量

```bash
npm i prom-client
```

```ts
// metrics.service.ts
import { collectDefaultMetrics, Counter, Histogram } from 'prom-client';

@Injectable()
export class MetricsService {
  private httpDuration: Histogram;

  constructor() {
    collectDefaultMetrics();
    this.httpDuration = new Histogram({
      name: 'http_request_duration_seconds',
      help: 'HTTP 请求耗时',
      labelNames: ['method', 'route', 'status'],
      buckets: [0.01, 0.05, 0.1, 0.5, 1, 2],
    });
  }

  observe(method: string, route: string, status: number, seconds: number) {
    this.httpDuration.labels(method, route, String(status)).observe(seconds);
  }
}

// 拦截器统一埋点
@Injectable()
export class MetricsInterceptor implements NestInterceptor {
  constructor(private metrics: MetricsService) {}

  intercept(ctx: ExecutionContext, next: CallHandler): Observable<any> {
    if (ctx.getType() !== 'http') return next.handle();

    const start = performance.now();
    const http = ctx.switchToHttp();
    const req = http.getRequest();
    const res = http.getResponse();

    return next.handle().pipe(
      tap(() => {
        const seconds = (performance.now() - start) / 1000;
        this.metrics.observe(
          req.method,
          req.route?.path ?? req.url,
          res.statusCode,
          seconds,
        );
      }),
    );
  }
}

// 暴露 /metrics
@Controller('metrics')
export class MetricsController {
  constructor(private registry: Registry) {}
  @Get()
  @Header('Content-Type', register.contentType)
  async get() { return register.metrics(); }
}
```

## 9. 优化检查清单

| 层次 | 检查 |
|------|------|
| 网络 | CDN、gzip/brotli 压缩、HTTP 缓存头 |
| 应用 | 热点数据缓存（Redis）、避免 N+1、并行化无依赖调用 |
| 序列化 | 只返回必要字段、避免深层嵌套 |
| 数据库 | 索引、分页、批量、连接池、读写分离 |
| 运行时 | 无阻塞 CPU 计算、Fastify 平台、限流 |
| 监控 | 埋点 P50/P95/P99、慢查询日志、错误率 |

## 10. 一句话总结

> Nest 性能优化分五层：**CDN/HTTP 缓存 → 应用层缓存（`@nestjs/cache-manager` + Redis，注意穿透/击穿/雪崩）→ 序列化裁剪 → 数据库（索引/避免 N+1/批量/连接池）→ 运行时（并行化、无阻塞计算、Fastify、限流）**；用 `ClassSerializerInterceptor` 脱敏、`prom-client` 埋 P95 指标。先测量再优化，避免过早优化。
