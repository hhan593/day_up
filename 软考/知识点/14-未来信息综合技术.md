# 14 — 未来信息综合技术

## 1. 人工智能与机器学习

### 1.1 人工智能概述

**人工智能（AI）三大流派**：

| 流派 | 核心思想 | 代表 |
|------|---------|------|
| **符号主义（Symbolism）** | 基于逻辑推理和知识表示 | 专家系统、知识图谱 |
| **连接主义（Connectionism）** | 基于神经网络模拟人脑 | 深度学习、神经网络 |
| **行为主义（Behaviorism）** | 基于感知-行为反馈 | 强化学习、进化算法 |

**AI 发展三阶段**：
- **ANI（弱AI/窄AI）**：擅长单一领域（当前所处阶段 → 图像识别、对话、推荐）
- **AGI（强AI/通用AI）**：达到人类级别多领域能力（尚未实现）
- **ASI（超AI）**：超越人类智能（远未实现）

### 1.2 机器学习（Machine Learning）

**机器学习分类**：

| 类型 | 数据要求 | 核心问题 | 典型算法 |
|------|---------|---------|---------|
| **监督学习** | 带标签数据 (x, y) | 学习 f: x → y | 线性回归、决策树、SVM、随机森林 |
| **无监督学习** | 无标签数据 | 发现数据内在结构 | K-means、DBSCAN、PCA、自动编码器 |
| **半监督学习** | 少量标签 + 大量无标签 | 利用无标签数据提升 | 自训练、协同训练、图半监督 |
| **强化学习** | 环境反馈（奖励/惩罚） | 学习最优策略 | Q-Learning、DQN、PPO |
| **自监督学习** | 从数据自身生成监督信号 | 生成式预训练 | BERT、GPT、MAE |

#### 经典模型速查

| 算法 | 类型 | 核心思想 | 特点 |
|------|------|---------|------|
| **线性回归** | 回归 | 拟合线性关系 y = wx + b | 简单、可解释、假设线性 |
| **逻辑回归** | 分类 | Sigmoid映射到[0,1] | 二分类基础、概率输出 |
| **决策树** | 分类/回归 | 按信息增益/基尼系数分裂 | 可解释、易过拟合 |
| **随机森林** | 分类/回归 | 多个决策树的集成（Bagging） | 抗过拟合、特征重要性 |
| **SVM** | 分类 | 寻找最大间隔超平面 | 核技巧处理非线性、高维有效 |
| **K-means** | 聚类 | 交替更新聚类中心和分配 | 简单、需预设K、对初始值敏感 |
| **KNN** | 分类/回归 | 近邻投票 | 懒惰学习、计算开销大 |
| **朴素贝叶斯** | 分类 | 贝叶斯公式 + 条件独立假设 | 快速、文本分类基准 |
| **XGBoost/LightGBM** | 分类/回归 | 梯度提升集成（Boosting） | 结构化数据首选、竞赛常用 |

#### 模型评估指标

| 指标 | 公式/含义 | 适用场景 |
|------|----------|---------|
| **精确率（Precision）** | TP / (TP + FP) | 预测为阳中真正的比例（宁缺毋滥） |
| **召回率（Recall）** | TP / (TP + FN) | 真正的阳被检出的比例（宁漏毋错） |
| **F1-Score** | 2 × P × R / (P + R) | 精确率和召回率的调和平均 |
| **准确率（Accuracy）** | (TP + TN) / Total | 样本均衡时适用 |
| **AUC-ROC** | ROC曲线下面积 | 分类器整体排序能力 |
| **MAE** | Σ\|y - ŷ\| / n | 回归，对异常值不敏感 |
| **RMSE** | √(Σ(y - ŷ)² / n) | 回归，对大误差惩罚更重 |

**混淆矩阵**：
```
             预测阳    预测阴
实际阳        TP       FN
实际阴        FP       TN
```

**偏差 vs 方差**：
| | 偏差（Bias） | 方差（Variance） |
|------|------|------|
| 含义 | 模型预测与真实值的偏离 | 训练集变化导致的预测变化 |
| 高→ | **欠拟合** | **过拟合** |
| 解决 | 更复杂模型、更多特征 | 更多数据、正则化、集成 |

### 1.3 深度学习（Deep Learning）

**核心网络架构对比**：

| 架构 | 核心组件 | 擅长领域 | 代表模型 |
|------|---------|---------|---------|
| **CNN**（卷积神经网络） | 卷积层 + 池化层 + 全连接 | 图像识别/分类/检测 | ResNet、VGG、YOLO |
| **RNN/LSTM/GRU** | 循环连接 + 门控机制 | 序列建模、时间序列 | — |
| **Transformer** | 自注意力（Self-Attention） | NLP/多模态（当前主流） | BERT、GPT、ViT |
| **GAN**（生成对抗网络） | 生成器 + 判别器对抗 | 图像生成、风格迁移 | StyleGAN、CycleGAN |
| **AutoEncoder** | 编码器 + 解码器 | 降维、去噪、异常检测 | VAE |
| **Diffusion Model** | 逐步去噪生成 | 高质量图像生成 | Stable Diffusion、DALL·E |
| **GNN**（图神经网络） | 在图结构上传递消息 | 分子预测、社交网络、推荐 | GCN、GAT |

**CNN 关键概念**：

| 概念 | 含义 |
|------|------|
| **卷积核（Kernel/Filter）** | 滑动窗口提取局部特征 |
| **步长（Stride）** | 卷积核每次滑动的像素数 |
| **填充（Padding）** | 边缘补0以控制输出尺寸 |
| **池化（Pooling）** | 降采样，降低参数量（Max/Average Pooling） |
| **感受野（Receptive Field）** | 输出单元能看到输入区域的大小 |
| **通道（Channel）** | 特征图的数量（输入3通道RGB） |

**Transformer 核心机制——自注意力**：
```
Self-Attention(Q, K, V) = softmax(Q·K^T / √d_k) × V

Q (Query)：查询，当前词
K (Key)：键，所有词（用于匹配）
V (Value)：值，所有词（用于加权聚合）
```

**Transformer vs RNN/LSTM**：
| | RNN/LSTM | Transformer |
|------|----------|-------------|
| 计算方式 | 串行（逐时间步） | 并行（一次性处理全部序列） |
| 长距离依赖 | 弱（梯度消失） | 强（自注意力直接连接） |
| 训练速度 | 慢 | 快（可并行） |
| 位置信息 | 隐式（在时序中） | 显式（位置编码） |

**预训练大模型范式**：
```
预训练（Pre-training）               微调（Fine-tuning）
大量无标注数据                     少量标注数据
      ↓                                  ↓
学习通用语言/视觉特征      →      适配特定任务
      ↓                                  ↓
  基础模型（Foundation Model）    下游任务模型
```

**激活函数**：

| 函数 | 公式 | 特点 |
|------|------|------|
| **ReLU** | max(0, x) | 计算快、缓解梯度消失、死神经元问题 |
| **Sigmoid** | 1/(1+e^(-x)) | 输出[0,1]、两端梯度饱和 |
| **Tanh** | (e^x-e^(-x))/(e^x+e^(-x)) | 输出[-1,1]、零中心 |
| **Softmax** | e^xi/Σe^xj | 多分类输出概率分布 |
| **GELU** | x·Φ(x) | Transformer常用 |

### 1.4 大语言模型（LLM）

**LLM 关键概念**：

| 概念 | 说明 |
|------|------|
| **参数规模** | 模型可学习的参数数量（GPT-3: 175B, GPT-4: ~1.8T 估计） |
| **上下文窗口** | 模型一次能处理的Token数（GPT-4o: 128K, Gemini: 2M） |
| **Token** | 文本的最小处理单元（≈0.75个英文单词，中文约1-2字符） |
| **涌现能力** | 规模大到一定程度后突然具备的能力（推理、思维链） |
| **Scaling Law** | 模型性能与参数量、数据量、计算量成幂律关系 |

**Transformer 解码器 vs 编码器**：

| | Encoder（编码器） | Decoder（解码器） |
|------|-----|------|
| 代表 | BERT | GPT系列 |
| 注意力 | 双向（看到上下文） | 单向/因果（只看上文） |
| 适合任务 | 理解（分类、NER、QA） | 生成（对话、创作） |
| 预训练 | MLM（掩码语言模型） | CLM（因果语言模型/Next Token Prediction） |

**提示工程（Prompt Engineering）**：

| 技术 | 说明 | 示例 |
|------|------|------|
| **Zero-shot** | 不提供示例，直接提问 | "请分类：这个产品不错 →" |
| **Few-shot** | 提供2-3示例再提问 | 先给2个分类示例，再输入待分类文本 |
| **思维链（CoT）** | 让模型展示推理步骤 | "请一步步思考，列出推理过程" |
| **角色设定** | 给模型设定人设 | "你是一位资深架构师，请评审以下设计" |
| **结构化输出** | 指定输出格式（JSON/XML等） | "请以JSON格式输出，包含name和type字段" |

**RAG（检索增强生成）**：
```
用户问题 → 检索相关文档（向量数据库） → 将检索结果注入Prompt → LLM生成答案
```

RAG 解决了 LLM 的知识截止和幻觉问题，让模型能基于外部最新知识回答。

**Agent（智能体）**：
```
LLM Agent = LLM（大脑） + 工具使用（Tool Use）+ 记忆（Memory）+ 规划（Planning）
```

Agent 能自主分解任务、使用工具、多步推理并以目标导向方式执行。

**大模型架构演进趋势**：
- MoE（混合专家）：每次只激活部分参数，提高效率
- 多模态：统一处理文本/图像/音频/视频
- 长上下文：从4K → 128K → 1M Token
- 端侧部署：量化（INT8/INT4）、蒸馏、剪枝

## 2. 大数据技术

> 部分内容与 [11-数据库设计基础知识.md](11-数据库设计基础知识.md) 第9节互补

### 2.1 大数据特征

**经典4V + 新2V**：

| 特征 | 含义 |
|------|------|
| **Volume（大量）** | 数据量巨大，从TB到PB、EB级 |
| **Velocity（高速）** | 数据产生和处理速度极快（实时流） |
| **Variety（多样）** | 结构化、半结构化、非结构化（文本/图像/视频/日志） |
| **Value（价值）** | 价值密度低，需要从海量数据中挖掘 |
| **Veracity（真实性）** | 数据质量参差，需要清洗和验证 |
| **Variability（可变性）** | 数据的含义会随时间变化 |

### 2.2 大数据处理架构

#### Lambda 架构

```
数据源 → [批处理层]（Hadoop/Spark）→ 批处理视图 →┐
     → [速度层]（Flink/Storm）──→ 实时视图 ──→ 服务层/查询 → 用户
```

- **批处理层**：处理全量数据，保证准确性（延迟高）
- **速度层**：处理增量数据，保证低延迟（可能不准确）
- **服务层**：合并批处理和实时结果

#### Kappa 架构

```
数据源 → 消息队列（Kafka） → 流处理（Flink） → 服务层 → 用户
```

- Lambda 的简化版，**一切用流处理**
- 批处理 = 从Kafka重放历史数据做流处理
- 更简单、维护成本更低

### 2.3 大数据技术栈

| 层次 | 技术 | 说明 |
|------|------|------|
| **数据采集** | Flume, Logstash, Filebeat | 日志采集 |
| | Sqoop, DataX | 数据库同步 |
| **消息队列** | Kafka, Pulsar | 高吞吐消息系统 |
| **批处理计算** | Hadoop MapReduce | 经典分布式批处理 |
| | Spark | 内存计算引擎（比MR快100x） |
| **流处理** | Flink | 真正的实时流处理（事件级） |
| | Storm, Spark Streaming | 微批/流处理 |
| **OLAP分析** | ClickHouse, Doris, StarRocks | 实时OLAP |
| | Presto, Impala | SQL on Hadoop查询 |
| **数据湖** | Hudi, Iceberg, Delta Lake | 数据湖表格式 |
| **资源调度** | YARN, Kubernetes | 资源管理与调度 |
| **任务调度** | DolphinScheduler, Airflow, Azkaban | 工作流编排 |

**数据处理模式**：

| 模式 | 延迟 | 计算引擎 | 场景 |
|------|------|---------|------|
| **批处理** | 分钟-小时级 | Hadoop/Spark | 日报、离线分析 |
| **微批处理** | 秒-分钟级 | Spark Streaming | 准实时报表 |
| **流处理** | 毫秒-秒级 | Flink/Storm | 实时风控、监控告警 |

### 2.4 数据湖 vs 数据仓库

| 维度 | 数据仓库 | 数据湖 |
|------|---------|--------|
| 数据格式 | 结构化（清洗后） | 任意格式（原始数据） |
| 处理模式 | Schema-on-Write（先定义后写入） | Schema-on-Read（读取时定义） |
| 用户 | 业务分析师、BI | 数据科学家、数据工程师 |
| 灵活性 | 低（写入时定型） | 高（随时可换分析角度） |
| 成本 | 高（专用硬件） | 相对低（通用存储+对象存储） |
| 代表 | Teradata, Snowflake | S3/HDFS + Iceberg/Hudi |

**数据湖仓一体（Lakehouse）**：融合数据湖的灵活性和数据仓库的事务/管理能力（Databricks, 阿里MaxCompute）。

### 3.2 虚拟化技术

**虚拟化分类**：

| 类型 | 说明 | 代表 |
|------|------|------|
| **全虚拟化** | 完整模拟硬件，GuestOS无需修改 | VMware ESXi、KVM |
| **半虚拟化** | GuestOS需修改，与Hypervisor协作 | Xen（半虚拟化模式） |
| **硬件辅助虚拟化** | CPU提供虚拟化指令支持 | Intel VT-x/AMD-V |

**Hypervisor 分类**：

| 类型 | 说明 | 代表 |
|------|------|------|
| **Type 1（裸机型）** | 直接运行在硬件上，无宿主OS | VMware ESXi、KVM、Hyper-V、Xen |
| **Type 2（宿主型）** | 运行在宿主OS上 | VMware Workstation、VirtualBox |

### 3.3 容器技术

**容器 vs 虚拟机**：

| 维度 | 容器 | 虚拟机 |
|------|------|--------|
| 隔离级别 | 进程级（共享OS内核） | OS级（独立OS） |
| 启动速度 | 秒级 | 分钟级 |
| 镜像大小 | MB级 | GB级 |
| 资源开销 | 低 | 高 |
| 密度 | 单机可数百个 | 单机可几十个 |
| 隔离强度 | 较弱（共享内核） | 强（独立内核） |
| 跨OS能力 | 不能跨OS（Linux容器需Linux宿主机） | 可跨OS |

**容器核心技术**：

| 技术 | 说明 |
|------|------|
| **Namespace** | 进程隔离（PID/Net/IPC/Mount/User等7种namespace） |
| **Cgroup** | 资源限制和监控（CPU、内存、IO） |
| **Union FS** | 联合文件系统，实现镜像分层（Overlay2、AUFS） |

**容器镜像分层概念**：
```
只读层（Layers）：
  Layer 4: 应用代码
  Layer 3: 依赖库
  Layer 2: 运行时
  Layer 1: 基础OS镜像

可写层（Container Layer）：
  容器运行时写入（删除容器后丢失）
```

**容器运行时标准**：
- **OCI（Open Container Initiative）**：容器镜像格式和运行时的开放标准
- **CRI（Container Runtime Interface）**：Kubernetes的容器运行时接口
- runc / containerd / CRI-O 等实现

## 4. 区块链技术

### 4.1 区块链核心概念

**区块链**：去中心化的分布式账本技术，由按时间顺序串联的区块组成，通过密码学保证不可篡改和不可伪造。

**区块链数据结构**：
```
区块N-1（前一哈希）←────── 区块N ──────→ 区块N+1（下一哈希）
   │                         │
 ├─ 区块头                  ├─ 区块头
 │  ├─ 前一区块哈希          │  ├─ 前一区块哈希
 │  ├─ Merkle根             │  ├─ Merkle根
 │  ├─ 时间戳                │  ├─ 时间戳
 │  └─ Nonce（随机数）       │  └─ Nonce
 └─ 交易列表                 └─ 交易列表
```

**区块链六大核心特征**：

| 特征 | 说明 |
|------|------|
| **去中心化** | 无中心节点，节点间平等 |
| **不可篡改** | 已确认数据不可修改（链式哈希保证） |
| **可追溯** | 所有交易记录永久保存可查询 |
| **透明性** | 交易记录对所有参与者可见（公有链） |
| **共识机制** | 各节点通过算法达成一致 |
| **智能合约** | 自动化执行的合约代码 |

### 4.2 共识机制

| 共识算法 | 原理 | 特点 | 代表链 |
|----------|------|------|--------|
| **PoW（工作量证明）** | 计算哈希难题（挖矿），先解出者记账 | 去中心化最强、能耗极高 | Bitcoin |
| **PoS（权益证明）** | 按持币量和时间选记账者 | 能耗低、可能有富者愈富 | Ethereum 2.0 |
| **DPoS（委托权益证明）** | 持币者投票选出记账节点 | 效率高、偏中心化 | EOS |
| **PBFT（实用拜占庭容错）** | 三阶段投票共识（Pre-prepare/Prepare/Commit） | 低延迟、节点数受限 | Hyperledger Fabric |
| **Raft** | 领导者选举+日志复制 | 简单、非拜占庭容错 | 联盟链 |

**PoW vs PoS**：
| 维度 | PoW | PoS |
|------|-----|-----|
| 资源消耗 | 极高（电力） | 低 |
| 51%攻击成本 | 需要51%算力 | 需要51%代币（市场买入会推高价格） |
| 出块速度 | 慢（Bitcoin ~10分钟） | 快（秒级） |
| 去中心化 | 高 | 中（持币大户控制力强） |

### 4.3 区块链分类

| 类型 | 准入机制 | 代表 | 典型应用 |
|------|---------|------|---------|
| **公有链（Public）** | 任何人可加入 | Bitcoin、Ethereum | 加密货币、DeFi、NFT |
| **联盟链（Consortium）** | 授权组织可加入 | Hyperledger Fabric、FISCO BCOS | 供应链金融、政务 |
| **私有链（Private）** | 单一组织控制 | 企业内部链 | 内部审计、溯源 |

### 4.4 智能合约

**智能合约**：部署在区块链上的自动化程序代码，条件满足时自动执行。

**以太坊智能合约特点**：
- 图灵完备（Solidity语言）
- Gas机制（每步计算需付费，防止死循环）
- 不可修改（一旦部署，代码不可更改）

**智能合约典型应用**：DeFi（去中心化金融）、NFT（非同质化代币）、DAO（去中心化自治组织）。

### 4.5 区块链应用场景

| 场景 | 说明 |
|------|------|

## 6. 量子计算

### 6.1 量子计算基础

**量子比特（Qubit）**：与经典比特（仅0或1）不同，量子比特可同时处于0和1的叠加态。

**三大核心量子特性**：

| 特性 | 说明 |
|------|------|
| **叠加（Superposition）** | 量子比特可同时处于多个状态 |ψ⟩ = α|0⟩ + β|1⟩ |
| **纠缠（Entanglement）** | 两个量子比特状态瞬间关联，无论距离多远 |
| **干涉（Interference）** | 叠加态的概率幅可相长或相消，提高正确结果的概率 |

**量子计算优势**：
- 量子比特数n，经典计算可表示2^n种组合但要逐个处理
- 量子计算通过叠加同时处理2^n种组合

**量子计算机技术路线**：

| 路线 | 代表公司 | 特点 |
|------|---------|------|
| **超导量子比特** | Google、IBM、本源量子 | 最主流、需极低温 |
| **离子阱** | IonQ、Quantinuum、启科量子 | 量子比特品质好、速度较慢 |
| **光量子** | Xanadu、图灵量子 | 室温运行 |
| **拓扑量子** | Microsoft | 理论容错性强、研制中 |
| **中性原子** | QuEra、Pasqal | 扩展性好 |

### 6.2 量子计算应用

| 应用场景 | 量子优势 |
|----------|---------|
| **密码破解** | Shor算法可破解RSA（大数分解），需数百万高质量量子比特 |
| **优化问题** | 量子退火/QAOA解决组合优化（物流路径、投资组合） |
| **量子化学** | 精确模拟分子结构、新药研发、材料设计 |
| **机器学习** | 量子特征空间、量子神经网络 |
| **金融建模** | 蒙特卡洛模拟加速 |

**当前阶段**：NISQ（Noisy Intermediate-Scale Quantum，含噪声中等规模量子），距通用容错量子计算仍有距离。

**后量子密码（PQC）**：即使没有量子计算机，也可设计抵抗量子攻击的密码算法。NIST 2024年已标准化首批PQC算法。

## 7. 隐私计算

> 系统架构设计师新考点

**隐私计算**：在保障数据不对外泄露的前提下，实现数据共享和分析的技术体系。

**四种主流技术**：

| 技术 | 原理 | 安全性 | 性能 | 适用 |
|------|------|--------|------|------|
| **联邦学习（FL）** | 数据不动模型动，各参与方本地训练，仅共享梯度 | 中高 | 较好 | 跨机构数据协作 |
| **安全多方计算（MPC/SMPC）** | 多参与方共同计算函数，各自数据不泄露 | 极高 | 较低 | 联合统计、联合查询 |
| **可信执行环境（TEE）** | 基于CPU硬件可信区隔离计算 | 中（依赖硬件） | 高 | 云上可信计算 |
| **同态加密（HE）** | 密文上直接计算，结果解密后等于明文计算 | 极高 | 极低 | 外包计算 |

**联邦学习三种模式**：

| 模式 | 特点 |
|------|------|
| **横向联邦** | 数据特征相同但样本不同（不同银行的用户征信数据） |
| **纵向联邦** | 样本相同但特征不同（同一用户的银行+电商数据） |
| **联邦迁移学习** | 样本和特征都差异大，借助迁移学习 |

**联邦学习架构**：
```
中央协调服务器
    ↙  ↓  ↘
 客户端A 客户端B 客户端C
(数据不出本地)  (数据不出本地)  (数据不出本地)

每轮迭代：
1. 服务器下发模型 → 客户端
2. 客户端本地训练 → 上传梯度/模型更新（不传原始数据）
3. 服务器聚合（联邦平均 FedAvg）→ 更新全局模型 → 下一轮
```

**安全多方计算核心思想**（以百万富翁问题为例）：
- 两个富翁想知道谁更有钱，但互不透露具体财富
- MPC可以通过密码协议计算出比较结果而不泄露各自输入

**联邦学习 vs MPC vs TEE**：

| 维度 | 联邦学习 | MPC | TEE |
|------|---------|-----|-----|
| 主要保护 | 训练数据 | 任意计算输入 | 执行过程 |
| 安全假设 | 半诚实（梯度可能泄露信息） | 恶意参与方 | 硬件可信 |
| 计算开销 | 中等 | 高 | 低（近似原生） |
| 通信开销 | 中等 | 高 | 低 |

**隐私计算典型应用**：医疗数据联合分析、金融联合风控建模、政务数据跨部门核验。

## 8. 绿色计算与可持续发展

### 8.1 绿色计算定义

**绿色计算**：在信息系统从设计到退役的全生命周期中，以环境友好为目标的系统实践。

### 8.2 绿色计算策略

| 策略 | 层面 | 具体措施 |
|------|------|---------|
| **节能设计** | 硬件 | 低功耗芯片、DVFS、异构计算 |
| **资源优化** | 调度 | 弹性伸缩、资源超售、混部 |
| **算法优化** | 软件 | 算法复杂度降低、模型剪枝量化 |
| **数据中心** | 设施 | 自然冷却、液冷、PUE < 1.2、新能源 |
| **碳排放感知** | 调度 | 碳感知调度（将工作负载调度到清洁能源时段/地区） |
| **循环经济** | 全生命周期 | 服务器延长使用、拆解回收、减少电子垃圾 |

**PUE（电源使用效率）** = 数据中心总能耗 / IT设备能耗
- 理想值1.0，行业均值1.5-2.0，先进水平 < 1.1

**算力网络**：通过高速网络调度不同数据中心的算力，让计算任务在可再生能源富余的地区（时区）执行。
