# 09 — 信息安全技术基础知识

## 1. 信息安全基础概念

### 1.1 信息安全的定义

信息安全是保护信息和信息系统免受未授权访问、使用、泄露、中断、修改或破坏的学科。

### 1.2 信息安全五要素（CIA三性 + 补充）

| 要素 | 英文 | 含义 |
|------|------|------|
| **机密性** | Confidentiality | 信息不被未授权者获取 |
| **完整性** | Integrity | 信息不被未授权篡改 |
| **可用性** | Availability | 授权用户可及时可靠访问 |
| **可控性** | Controllability | 对信息和系统有控制能力 |
| **不可抵赖性** | Non-repudiation | 行为发生后无法否认 |

### 1.3 信息安全威胁分类

| 威胁类型 | 说明 |
|----------|------|
| 信息泄露 | 信息被未授权获取（破坏机密性） |
| 完整性破坏 | 信息被未授权篡改（破坏完整性） |
| 拒绝服务（DoS） | 系统无法提供服务（破坏可用性） |
| 非法使用 | 未授权使用系统资源 |
| 假冒 | 冒充合法用户身份 |
| 旁路控制 | 利用系统缺陷绕过安全机制 |
| 授权侵犯 | 合法用户越权操作 |
| 特洛伊木马 | 伪装成合法程序的恶意代码 |
| 陷阱门 | 系统设计预留的隐蔽入口 |
| 抵赖 | 否认已执行的操作 |

## 2. 密码学基础

### 2.1 密码学基本概念

- **明文（Plaintext）**：原始可读信息
- **密文（Ciphertext）**：加密后的不可读信息
- **加密（Encryption）**：明文 → 密文
- **解密（Decryption）**：密文 → 明文
- **密钥（Key）**：控制加解密算法的参数
- **密码算法（Cipher）**：加解密使用的数学函数

### 2.2 对称加密（私钥加密）

加解密使用**相同密钥**，速度快，适合大数据量加密。

| 算法 | 密钥长度 | 分组长度 | 特点 |
|------|---------|---------|------|
| **DES** | 56位 | 64位 | 已淘汰，易暴力破解 |
| **3DES** | 112/168位 | 64位 | DES的增强版，性能较低 |
| **AES** | 128/192/256位 | 128位 | 当前主流标准，替代DES |
| **RC4** | 可变 | 流密码 | 流密码，用于SSL/TLS历史版本 |
| **SM4** | 128位 | 128位 | 中国国密标准 |
| **IDEA** | 128位 | 64位 | 用于PGP |

**对称加密典型应用**：文件加密、数据库加密、VPN隧道加密。

### 2.3 非对称加密（公钥加密）

使用**密钥对**：公钥加密，私钥解密（或私钥签名，公钥验签）。

| 算法 | 安全性基础 | 典型应用 |
|------|-----------|---------|
| **RSA** | 大整数分解难题 | 数字签名、密钥交换、HTTPS |
| **ECC（椭圆曲线）** | 椭圆曲线离散对数 | 移动设备、物联网 |
| **SM2** | 椭圆曲线 | 中国国密标准，替代RSA |
| **ElGamal** | 离散对数 | 数字签名基础 |
| **DSA** | 离散对数 | 仅用于数字签名 |

**非对称加密特点**：安全性高但速度慢（比对称加密慢100-1000倍），通常用于加密对称密钥。

### 2.4 哈希函数（消息摘要）

**特性**：单向不可逆、定长输出、雪崩效应、抗碰撞。

| 算法 | 输出长度 | 安全性 | 状态 |
|------|---------|--------|------|
| **MD5** | 128位 | 已破解 | 不推荐 |
| **SHA-1** | 160位 | 已破解 | 已淘汰 |
| **SHA-256/384/512** | 256/384/512位 | 安全 | 当前标准 |
| **SM3** | 256位 | 安全 | 中国国密标准 |

**哈希函数应用**：数据完整性校验、数字签名（先哈希再签名）、口令存储（加盐哈希）、区块链。

### 2.5 数字签名

基于非对称加密，私钥签名（加密摘要），公钥验签。实现**不可抵赖性**和**完整性验证**。

**数字签名过程**：
```
发送方：明文 → 哈希 → 摘要 → 私钥加密 → 数字签名 → 附在明文后发送
接收方：收到（明文+签名） → 明文做哈希得摘要1 → 公钥解密签名得摘要2 → 对比摘要1和摘要2
```

### 2.6 数字证书与PKI

**PKI（公钥基础设施）** 四大组成部分：
- **CA（认证中心）**：签发和管理数字证书
- **RA（注册中心）**：受理证书申请和身份审核
- **证书库**：存储已签发的证书和CRL
- **密钥备份与恢复系统**

**X.509数字证书内容**：版本号、序列号、签名算法、颁发者、有效期、主体（拥有者）、主体公钥信息、扩展字段、CA数字签名。

**CRL（证书吊销列表）**：列出在有效期内被吊销的证书。

**OCSP（在线证书状态协议）**：实时查询证书是否有效，替代CRL的实时性方案。

**信任模型**：
- **层次信任模型**：单一根CA，严格层级
- **网状信任模型**：CA之间交叉认证
- **桥CA信任模型**：通过桥CA连接不同信任域

## 3. 访问控制

### 3.1 访问控制模型

| 模型 | 全称 | 核心思想 | 典型应用 |
|------|------|---------|---------|
| **DAC** | 自主访问控制 | 资源所有者决定谁能访问 | Windows/Linux文件权限 |
| **MAC** | 强制访问控制 | 系统根据安全标签强制控制 | 军事/政府系统（SELinux） |
| **RBAC** | 基于角色的访问控制 | 权限授予角色，角色授予用户 | 企业应用系统 |

### 3.2 访问控制实现方式

- **访问控制矩阵（ACM）**：行=主体，列=客体，交叉=权限
- **访问控制列表（ACL）**：每个客体关联可访问的主体列表
- **能力表（Capability）**：每个主体关联可访问的客体及权限

### 3.3 身份认证

**三种认证因素**：
1. **所知**（Something you know）：口令、PIN
2. **所有**（Something you have）：智能卡、U-Key、数字证书
3. **所是**（Something you are）：指纹、虹膜、人脸

**多因素认证（MFA）**：同时使用两种及以上认证因素。

**常见认证协议**：
- **Kerberos**：基于对称密钥的第三方认证（AS + TGS，票据机制）
- **CHAP**：挑战-应答认证协议
- **OAuth 2.0**：授权框架，不是认证协议
- **OIDC（OpenID Connect）**：基于OAuth 2.0的身份认证层

**Kerberos 认证流程**：
```
用户 → AS（认证服务器）：认证请求
AS → 用户：TGT（票据授予票据）
用户 → TGS（票据授予服务器）：TGT + 服务请求
TGS → 用户：ST（服务票据）
用户 → 应用服务器：ST
应用服务器 → 用户：服务访问
```

## 4. 网络安全

### 4.1 OSI安全体系架构

**五大安全服务（ISO 7498-2 / GB/T 9387.2）**：
| 安全服务 | 说明 |
|---------|------|
| 认证（Authentication） | 对等实体认证 + 数据源认证 |
| 访问控制（Access Control） | 防止未授权使用资源 |
| 数据机密性（Data Confidentiality） | 连接机密性、无连接机密性、流量机密性 |
| 数据完整性（Data Integrity） | 带恢复、不带恢复的连接/无连接完整性 |
| 抗抵赖（Non-repudiation） | 发送证明 + 接收证明 |

**八大安全机制**：加密、数字签名、访问控制、数据完整性、认证交换、流量填充、路由控制、公证。

**安全服务与OSI层次映射**：

| 服务 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|------|---|---|---|---|---|---|---|
| 对等实体认证 | | | ✓ | ✓ | | | ✓ |
| 数据源认证 | | | ✓ | ✓ | | | ✓ |
| 访问控制 | | | ✓ | ✓ | | | ✓ |
| 连接机密性 | ✓ | ✓ | ✓ | ✓ | | ✓ | |
| 无连接机密性 | | ✓ | ✓ | ✓ | | | ✓ |
| 流量机密性 | ✓ | | ✓ | | | | ✓ |
| 数据完整性 | | | ✓ | ✓ | | | ✓ |
| 抗抵赖 | | | | | | | ✓ |

### 4.2 防火墙

**防火墙分类**：

| 类型 | 工作层级 | 特点 |
|------|---------|------|
| **包过滤防火墙** | 网络层/传输层 | 基于IP、端口、协议过滤，性能高但无法检测应用层攻击 |
| **状态检测防火墙** | 网络层-传输层 | 记录连接状态（含状态表），比简单包过滤更安全 |
| **应用代理防火墙** | 应用层 | 完全隔离内外网，安全性最高但性能最低 |
| **NGFW（下一代防火墙）** | 1-7层 | 集成IPS、应用识别、用户身份感知 |

**防火墙部署架构**：
- **屏蔽子网（DMZ）**：外网 ↔ 外部防火墙 ↔ DMZ ↔ 内部防火墙 ↔ 内网
- DMZ放置对外服务的服务器（Web、邮件、DNS）

### 4.3 入侵检测与防御

| 系统 | 全称 | 部署方式 | 功能 |
|------|------|---------|------|
| **IDS** | 入侵检测系统 | 旁路镜像 | 检测并告警，不阻断 |
| **IPS** | 入侵防御系统 | 串联在线 | 检测并主动阻断 |

**IDS检测方法**：
- **误用检测（特征检测）**：基于已知攻击特征库匹配，低误报但无法检测未知攻击
- **异常检测**：基于正常行为基线，可检测未知攻击但误报率较高

**HIDS vs NIDS**：
- **HIDS**（主机IDS）：部署在单台主机，监控文件、进程、日志
- **NIDS**（网络IDS）：部署在网络关键节点，分析网络流量

### 4.4 VPN（虚拟专用网络）

| 协议 | 层次 | 特点 |
|------|------|------|
| **IPSec** | 网络层 | 站点到站点，AH认证+ESP加密，隧道/传输模式 |
| **SSL VPN** | 传输层/应用层 | 远程接入，客户端免安装，基于浏览器 |
| **L2TP** | 数据链路层 | 通常配合IPSec使用 |
| **PPTP** | 数据链路层 | 安全性弱，已不建议使用 |
| **MPLS VPN** | 2.5层 | 运营商级VPN，标签交换 |

**IPSec 两大协议**：
- **AH（认证头）**：提供完整性+认证+抗重放，不加密
- **ESP（封装安全载荷）**：提供完整性+认证+加密+抗重放

**IPSec 两种模式**：
- **传输模式**：只加密IP数据报的载荷部分，用于端到端通信
- **隧道模式**：加密整个原始IP数据报，用于网关到网关通信

### 4.5 网络攻击与防护

**常见网络攻击**：

| 攻击类型 | 说明 | 防护措施 |
|----------|------|---------|
| **ARP欺骗** | 伪造ARP响应，劫持通信 | 静态ARP、DAI |
| **IP欺骗** | 伪造源IP地址 | 入口/出口过滤、RPF检查 |
| **DNS劫持** | 篡改DNS解析结果 | DNSSEC |
| **SYN Flood** | TCP半连接耗尽服务器资源 | SYN Cookie、连接限制 |
| **DDoS** | 分布式拒绝服务 | 流量清洗、CDN、Anycast |
| **中间人攻击（MITM）** | 拦截并可能篡改通信 | 加密、证书校验 |
| **SQL注入** | 注入恶意SQL语句 | 参数化查询、输入校验 |
| **XSS（跨站脚本）** | 注入恶意脚本到网页 | 输出编码、CSP |
| **CSRF** | 跨站请求伪造 | CSRF Token、SameSite Cookie |

## 5. 系统与应用安全

### 5.1 操作系统安全

**安全操作系统基本要素**：
- 用户标识与认证（UID/GID、口令策略）
- 强制访问控制（MAC）
- 最小特权原则（Least Privilege）
- 安全审计（Audit Log）
- 可信路径（Trusted Path）

**Windows安全机制**：活动目录域认证、组策略、EFS加密文件系统、BitLocker磁盘加密、UAC用户账户控制。

**Linux安全机制**：SELinux/AppArmor（MAC实现）、能力（Capabilities）拆分root权限、namespace和cgroups实现隔离。

### 5.2 数据库安全

**数据库安全特性**：
- **用户认证与授权**：数据库用户、角色、权限（GRANT/REVOKE）
- **访问控制粒度**：表级、列级、行级
- **审计**：操作日志、审计追踪
- **加密**：透明数据加密（TDE）、列级加密
- **备份与恢复**：全量/增量备份，PITR（时间点恢复）
- **推理控制**：防止通过汇总数据推断个体数据

**数据库安全威胁**：
- SQL注入（No.1 Web应用安全风险）
- 权限提升（Privilege Escalation）
- 弱口令与默认口令
- 未打补丁的漏洞

### 5.3 Web应用安全

**OWASP Top 10（2021）核心条目**：
1. **A01-访问控制失效**：越权访问
2. **A02-加密机制失效**：敏感数据明文传输/存储
3. **A03-注入**：SQL注入、命令注入等
4. **A04-不安全的设计**：缺少安全设计模式
5. **A05-安全配置错误**：默认配置、错误信息泄露
6. **A06-脆弱和过时的组件**：已知漏洞的依赖库
7. **A07-身份识别和认证失败**：弱口令、会话管理问题
8. **A08-软件和数据完整性失效**：不安全的反序列化
9. **A09-安全日志记录和监控失效**：缺乏检测和响应
10. **A10-服务器端请求伪造（SSRF）**

## 6. 安全协议与标准

### 6.1 网络安全协议

| 协议 | 全称 | 层次 | 作用 |
|------|------|------|------|
| **SSL/TLS** | 安全套接层/传输层安全 | 传输层 | 通信加密、服务器认证 |
| **HTTPS** | HTTP over SSL/TLS | 应用层 | Web安全通信 |
| **SSH** | 安全外壳协议 | 应用层 | 安全远程登录 |
| **IPSec** | IP安全协议 | 网络层 | VPN加密通信 |
| **S/MIME** | 安全多用途互联网邮件扩展 | 应用层 | 电子邮件加密和签名 |
| **PGP** | 优良保密协议 | 应用层 | 电子邮件和文件加密 |
| **Kerberos** | 第三方认证协议 | 应用层 | 网络身份认证 |

| **802.1X** | 基于端口的网络访问控制 | 数据链路层 | 网络准入控制 |

### 6.2 TLS握手流程（简化）

```
客户端 → 服务器：ClientHello（支持的密码套件、TLS版本、随机数）
服务器 → 客户端：ServerHello + 证书 + ServerHelloDone
客户端 → 服务器：（验证证书）生成Pre-Master Secret，用服务器公钥加密发送
客户端 → 服务器：ChangeCipherSpec + Finished
服务器 → 客户端：ChangeCipherSpec + Finished

后续通信使用协商的对称密钥加密
```

**TLS 1.3 改进**：握手从2-RTT减为1-RTT，移除不安全算法，0-RTT快速重连。

### 6.3 安全评估标准

| 标准 | 全称 | 范围 | 说明 |

| **ITSEC** | 信息技术安全评估标准 | 欧洲 | 功能+保证分离评估 |

| 标准 | 说明 |

| **等保2.0（GB/T 22239）** | 网络安全等级保护，五级：用户自主→系统审计→安全标记→结构化→访问验证 |
| **GB/T 25069** | 信息安全技术术语 |

**等保2.0 核心要求维度**（"一个中心、三重防护"）：

- **安全区域边界**：边界防护、访问控制、入侵防范
- **安全通信网络**：通信加密、网络隔离
- **安全管理中心**：集中管控、审计、态势感知

## 7. 物理安全与环境安全

### 7.1 物理安全防护

- **机房选址**：避开顶层、地下室、水源附近
- **门禁系统**：刷卡、生物识别、尾随检测
- **监控系统**：视频监控、红外探测
- **环境控制**：温湿度（温度22±2℃, 湿度45%-65%）、防静电、防尘
- **电力保障**：双路供电 + UPS + 柴油发电机
- **消防**：气体灭火（FM200/IG541）、烟感/温感探测

### 7.2 容灾与业务连续性

**容灾等级（国家标准）**：

| 等级 | RPO | RTO | 说明 |
|------|-----|-----|------|
| 第1级 | 天级 | 2天以上 | 磁带备份异地存放 |
| 第2级 | 天级 | 24小时以上 | 备用场地+备份恢复 |
| 第3级 | 小时级 | 小时级 | 电子传输+数据备份 |
| 第4级 | 分钟级 | 分钟级 | 活动备用站点 |
| 第5级 | 秒级 | 分钟级 | 双活数据中心 |
| 第6级 | 0（零数据丢失） | 分钟级 | 数据零丢失、自动切换 |

**RPO**（Recovery Point Objective）：恢复点目标（能容忍丢失多少数据）
**RTO**（Recovery Time Objective）：恢复时间目标（能容忍多久恢复服务）

## 8. 安全管理与法律法规

### 8.1 信息安全管理体系（ISMS）

**ISO/IEC 27001**：信息安全管理体系要求（可认证）
**ISO/IEC 27002**：信息安全控制实践指南

**PDCA 持续改进模型**：
```
Plan（规划ISMS） → Do（实施运行ISMS） → Check（监视评审ISMS） → Act（保持改进ISMS）
```

### 8.2 安全策略与管理

**安全策略层次**：
- **总体安全方针**：组织对信息安全的总体态度和方向
- **具体安全策略**：针对特定领域的具体规则（密码策略、访问控制策略、备份策略）
- **安全标准和基线**：技术实现的最低安全配置要求
- **安全流程和指南**：操作规程和作业指导书

**人员安全管理**：
- 背景审查
- 安全教育培训
- 安全协议签署（保密协议）
- 岗位分离（SoD：操作岗与审计岗分离、开发与运维分离）
- 离职管理（权限回收）

### 8.3 风险评估

**风险评估方法**：

| 方法 | 特点 |
|------|------|
| **定量评估** | 用数值计算（ALE = SLE × ARO），精确但数据获取难 |
| **定性评估** | 用等级描述（高/中/低），简单灵活但主观性强 |
| **半定量评估** | 结合定量与定性 |

**风险评估要素**：资产（Asset）+ 威胁（Threat）+ 脆弱性（Vulnerability）+ 影响（Impact）+ 可能性（Likelihood）

**风险计算公式**：风险值 R = f(A, T, V) = f(I, L)

**风险处置策略**：
- **规避**：消除风险源（放弃高风险活动）
- **降低**：实施安全措施降低风险
- **转移**：购买保险或外包（不改变风险本身）
- **接受**：承认并接受残余风险

### 8.5 安全事件响应

**事件响应六阶段（NIST SP 800-61）**：
1. **准备**：组建CSIRT团队、制定应急预案
2. **检测与分析**：识别安全事件、评估影响范围
3. **遏制**：隔离受影响系统、阻止事态扩大
4. **根除**：清除恶意代码、修复漏洞
5. **恢复**：系统恢复、数据恢复、逐步上线
6. **事后总结**：经验教训、改进措施、更新预案

## 10. 信息安全常考计算与考点

### 10.1 对称与非对称密钥数量

- n个实体两两通信，对称加密需要 C(n,2) = n(n-1)/2 个密钥
- n个实体两两通信，非对称加密需要 n 对密钥（2n个密钥）

### 10.2 安全要素判别

- **截获** → 破坏**机密性**
- **篡改** → 破坏**完整性**
- **伪造** → 破坏**真实性**
- **中断** → 破坏**可用性**
- **否认** → 破坏**不可抵赖性**

### 10.3 国密算法速查

| 算法 | 用途 | 对标国际算法 |
|------|------|-------------|
| SM1 | 对称加密（商密，未公开） | AES |
| SM2 | 非对称加密/签名 | RSA/ECC |
| SM3 | 哈希/摘要 | SHA-256 |
| SM4 | 对称加密 | AES |
| SM9 | 基于标识的密码 | IBE |

### 10.4 等保2.0 五级速查

| 等级 | 名称 | 侵害对象 | 监管 |
|------|------|---------|------|
| 第一级 | 用户自主保护级 | 公民、法人合法权益 | 自主保护 |
| 第二级 | 系统审计保护级 | 公民、法人严重损害 或 社会秩序 | 指导 |
