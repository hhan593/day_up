# 01 — 软件工程基础

## 1. 软件工程核心概念

### 1.1 软件的定义与特点

软件 = 程序 + 数据 + 文档。

软件四大特性：
- **复杂性**：软件是逻辑产品而非物理产品，复杂度随规模指数级增长
- **一致性**：软件必须与现有系统、接口、规范保持一致
- **可变性**：软件易于修改，导致持续变更的预期成为常态
- **不可见性**：软件不可视化，难以用几何模型表达

### 1.2 软件工程的定义

软件工程是将系统化的、规范的、可量化的方法应用于软件的开发、运行和维护，即将工程化方法应用于软件。

**软件工程三要素**：方法 + 工具 + 过程。

### 1.3 软件生命周期

各模型对阶段的划分略有差异，核心阶段包括：

```
问题定义 → 可行性研究 → 需求分析 → 概要设计 → 详细设计
→ 编码实现 → 测试 → 部署 → 运行维护 → 退役
```

**各阶段核心产出：**
| 阶段 | 主要产出物 |
|------|-----------|
| 可行性研究 | 可行性分析报告 |
| 需求分析 | 需求规格说明书（SRS） |
| 概要设计 | 概要设计说明书、架构文档 |
| 详细设计 | 详细设计说明书、类/模块设计 |
| 编码实现 | 源代码、单元测试报告 |
| 测试 | 测试计划、测试用例、缺陷报告 |
| 部署 | 部署方案、运维手册 |
| 维护 | 变更记录、升级文档 |

## 2. 软件过程模型

### 2.1 瀑布模型

- **特点**：严格的线性顺序，阶段间有文档驱动的里程碑
- **适用**：需求稳定、规模中小、安全关键系统（航天、医疗、银行核心）
- **变体**：带反馈环的瀑布模型

### 2.2 V模型

- **核心思想**：开发与测试一一对应
- **左侧（开发）**：需求分析 → 概要设计 → 详细设计 → 编码
- **右侧（测试）**：单元测试 ← 集成测试 ← 系统测试 ← 验收测试
- **关键对应关系**：
  - 需求分析 ↔ 验收测试
  - 概要设计 ↔ 系统测试
  - 详细设计 ↔ 集成测试
  - 编码 ↔ 单元测试

### 2.3 增量模型

- **核心**：将系统划分为多个增量构件，每个增量独立开发测试后集成
- **特点**：第一个增量通常是核心功能，后续增量逐步添加能力
- **优势**：核心功能快速交付，每个增量都是一次学习机会
- **适用**：需求基本稳定、工期紧张的项目

### 2.4 螺旋模型

- **核心循环**：制定计划 → 风险分析 → 实施工程 → 客户评估
- **关键特征**：以**风险驱动**为核心
- **风险分析活动**：识别风险、分析风险、制定缓解策略、监控风险
- **适用**：大型、高风险、需求不确定的项目（航天、国防）

### 2.5 敏捷开发

**敏捷宣言四条价值观：**
1. 个体和互动 > 流程和工具
2. 工作的软件 > 详尽的文档
3. 客户合作 > 合同谈判
4. 响应变化 > 遵循计划

**12条原则要点：** 尽早持续交付、欢迎需求变化、频繁交付、业务与开发协作、面对面交流、可持续开发等。

**Scrum 角色与仪式：**
- **三角色**：Product Owner（定义需求优先级）、Scrum Master（保障流程）、开发团队（自组织）
- **五仪式**：Sprint计划会、每日站会、Sprint评审会、Sprint回顾会、Product Backlog梳理
- **三工件**：Product Backlog、Sprint Backlog、可工作增量

**极限编程（XP）五大价值观**：沟通、简单、反馈、勇气、尊重

**XP 核心实践**：
- 计划游戏、小型发布、隐喻
- 简单设计、测试驱动开发（TDD）、重构
- 结对编程、代码集体所有、持续集成
- 每周40小时工作制、现场客户、编码标准

## 3. 软件过程能力成熟度模型

### 3.1 CMMI 成熟度等级

| 等级 | 名称 | 特征 |
|------|------|------|
| 1级 | 初始级 | 过程无序，成功依赖个人能力 |
| 2级 | 已管理级 | 项目级管理，需求、计划、配置、质量有管理 |
| 3级 | 已定义级 | 组织级标准过程，过程标准化 |
| 4级 | 量化管理级 | 过程度量、量化控制 |
| 5级 | 优化级 | 持续改进，缺陷预防 |

### 3.2 CMMI 过程域

CMMI 3级覆盖22个过程域，分为四类：
- **过程管理**（5个）：OPF、OPD、OT、OPP、OID
- **项目管理**（6个）：PP、PMC、SAM、IPM、RSKM、QPM
- **工程**（5个）：RD、TS、PI、VER、VAL
- **支持**（6个）：CM、PPQA、MA、CAR、DAR

## 4. 软件开发方法对比

| 维度 | 结构化方法 | 面向对象方法 | 敏捷方法 |
|------|-----------|-------------|----------|
| 核心思想 | 自顶向下分解 | 对象+消息传递 | 迭代增量+持续反馈 |
| 分析工具 | DFD、ER图、状态图 | 用例图、类图、时序图 | User Story |
| 设计 | 模块化、高内聚低耦合 | 类设计、设计模式 | 简单设计、持续重构 |
| 变更响应 | 较差 | 一般 | 优秀 |
| 文档程度 | 高 | 中高 | 够用就好 |

**其他方法**：
- **原型法**：快速构建原型验证需求，适用于需求模糊的前端项目
- **面向服务方法**：以服务为基本单元，强调松耦合和互操作性
- **领域驱动设计（DDD）**：聚焦核心域模型，战略设计+战术设计
- **模型驱动架构（MDA）**：CIM → PIM → PSM → 代码，模型变换驱动

## 5. 软件重用

### 5.1 重用级别

- **代码级重用**：函数库、类库、组件
- **设计级重用**：设计模式、架构风格、框架
- **分析级重用**：领域模型、需求模式
- **测试级重用**：测试用例、测试脚本

### 5.2 重用形式

- **黑盒重用**：不修改，直接使用（如第三方库）
- **白盒重用**：可修改内部实现（如开源框架定制）
- **组合重用**：组合多个已有组件形成新系统

## 6. 逆向工程与再工程

| 概念 | 定义 |
|------|------|
| 逆向工程 | 从代码和可执行程序提取设计信息，恢复设计模型 |
| 再工程 | 对现有系统进行改造，提高可维护性或迁移到新技术栈 |
| 重构 | 在不改变外部行为的前提下优化内部结构 |
| 软件维护分类 | 纠错性、适应性、完善性、预防性 |

## 7. 软件项目管理基础

### 7.1 COCOMO 成本估算模型

- **基本COCOMO**：仅用代码行数（KLOC）估算
- **中级COCOMO**：引入15个成本驱动因子（产品属性、硬件属性、人员属性、项目属性）
- **详细COCOMO**：按开发阶段分别考虑成本因子

### 7.2 项目进度管理

**关键路径法（CPM）**：
- 总时差（Total Float）= 最晚开始 - 最早开始
- 关键路径上的活动总时差为0，是决定项目最短工期的路径

**Gantt图**：直观展示任务开始/结束时间和依赖关系

**PERT估算**：
- 期望时间 t = (乐观 + 4×最可能 + 悲观) / 6
- 标准差 σ = (悲观 - 乐观) / 6

### 7.3 团队组织模式

| 模式 | 特点 | 适用场景 |
|------|------|---------|
| 主程序员团队 | 1个主程序员+n个辅助 | 小团队、技术强依赖 |
| 民主团队 | 平等无领导 | 研究型、创新项目 |
| 层级团队 | 分层管理 | 大型项目 |

## 8. 软件配置管理（SCM）

**配置管理活动**：配置标识、配置控制（变更控制）、配置状态报告、配置审计

**基线（Baseline）**：通过正式评审后作为后续工作基础的配置项快照。

**版本控制工具**：Git、SVN。

**变更控制流程**：提交变更请求 → 评审 → 批准/拒绝 → 实施 → 验证 → 更新基线

---

## 9. 软件风险管理

**风险管理过程**：风险识别 → 风险分析（概率×影响） → 风险计划 → 风险监控

**风险类别**：
- **项目风险**：进度、资源、预算
- **技术风险**：技术方案不可行、性能不达标
- **商业风险**：市场变化、政策法规
- **外部风险**：供应商、合作方

**十大常见风险（Boehm）**：需求变更、进度紧张、人员不足、技术方案不合理、性能问题等。
