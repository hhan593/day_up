# 02 — 需求工程与项目管理

## 1. 需求工程概述

### 1.1 需求工程的过程

```
需求获取 → 需求分析 → 需求规格说明 → 需求验证 → 需求管理
```

### 1.2 需求的层次

| 层次 | 名称 | 内容 | 关注者 |
|------|------|------|--------|
| 业务需求 | Business Requirement | 组织的高层目标，为什么做 | 管理层、投资人 |
| 用户需求 | User Requirement | 用户使用系统要完成的任务 | 最终用户 |
| 系统需求 | System Requirement | 系统必须具备的功能和约束 | 开发团队 |
| 功能需求 | Functional Requirement | 系统必须做什么 | 开发团队 |
| 非功能需求 | Non-Functional Requirement | 系统必须满足的质量属性 | 架构师、运维 |

---

## 2. 需求获取技术

| 技术 | 说明 | 适用场景 |
|------|------|---------|
| 访谈 | 与干系人一对一交流 | 深入了解特定领域 |
| 问卷调查 | 大规模收集信息 | 用户群体大、地理分散 |
| 焦点小组 | 有主持的主题讨论会 | 需求冲突时寻求共识 |
| 头脑风暴 | 自由提出想法 | 创新项目、新产品 |
| 联合需求计划(JRP) | 集中各干系人开会确定需求 | 大型项目启动阶段 |
| 观察法 | 观察用户实际操作 | 现有系统改进 |
| 原型法 | 构造系统原型供用户试评估 | 需求模糊的项目 |
| 文档分析 | 分析现有文档、表单 | 替换/升级现有系统 |

## 3. 需求分析

### 3.1 结构化分析方法

**数据流图（DFD）**：
- **处理（圆角矩形）**：数据变换/加工
- **数据流（箭头）**：数据的流向
- **数据存储（两条平行线或开口矩形）**：数据的存储
- **外部实体（矩形）**：系统外的交互对象

**分层原则**：0层（上下文图）→ 1层（子系统级）→ 2层（功能级），每层 7±2 个加工。

**数据字典（DD）**：定义所有数据元素，包括数据项、数据结构、数据流、数据存储、加工逻辑。

### 3.2 面向对象分析方法

**核心活动**：
1. 识别用例（Use Case）
2. 构建领域模型（Domain Model）
3. 定义系统行为（交互图/状态图）

**分析类三分类（MVC/边界-实体-控制）**：
- **边界类（Boundary）**：系统与外部的接口
- **实体类（Entity）**：持久化数据对象
- **控制类（Control）**：业务逻辑和流程控制

## 4. 需求规格说明书（SRS）

### 4.1 良好的SRS特征

- **正确性**：描述的每个需求都是系统应满足的
- **无歧义性**：每个需求只有一种解释
- **完整性**：包含所有必要需求，响应所有输入
- **一致性**：需求之间不冲突
- **可验证性**：存在成本可行的验证方法
- **可跟踪性**：需求来源和演变可追溯
- **可修改性**：结构清晰，易于增删改

### 4.2 SRS典型结构（IEEE 830）

1. 引言（目的、范围、定义、参考、概述）
2. 综合描述（产品视角、功能、用户特征、约束、假设）
3. 具体需求（功能需求、非功能需求、接口需求）
4. 附录、索引

## 5. 需求验证

| 技术 | 说明 |
|------|------|
| 需求评审 | 同行和干系人正式/非正式评审SRS |
| 原型验证 | 用户通过操作原型确认需求理解 |
| 测试用例设计 | 基于需求设计测试用例，验证可测试性 |
| 需求跟踪矩阵 | 检查每个需求是否能追溯到来源和设计/测试 |

## 6. 需求管理

### 6.1 需求变更管理

```
提交变更请求 → 变更评估（影响分析） → 变更决策（批准/拒绝/延期）
→ 实施变更 → 验证变更 → 更新基线
```

### 6.2 需求跟踪

- **正向跟踪**：需求 → 设计 → 编码 → 测试
- **逆向跟踪**：测试 → 编码 → 设计 → 需求
- **需求跟踪矩阵**：建立需求与设计、代码、测试用例的映射

### 6.3 需求优先级

- **MoSCoW法则**：Must have、Should have、Could have、Won't have
- **Kano模型**：基本型需求、期望型需求、兴奋型需求

## 7. 软件项目估算

### 7.1 功能点法（Function Point）

**5类信息域计数：**
- 外部输入（EI）：来自外部实体的数据输入
- 外部输出（EO）：向外部实体输出的数据
- 外部查询（EQ）：交互式查询
- 内部逻辑文件（ILF）：系统内部维护的数据
- 外部接口文件（EIF）：系统引用的外部数据

**计算步骤**：计数 → 按复杂度赋权值 → 求和得未调整功能点(UFP) → 乘以技术复杂度调整因子(VAF) → 得到最终功能点数

### 7.2 COCOMO II 模型

三个层次：
- **应用组合模型**：适用于原型开发，使用对象点
- **早期设计模型**：适用于需求/设计阶段，使用功能点
- **后体系结构模型**：适用于详细设计后，使用源代码行数

## 8. 项目进度管理

### 8.1 活动排序与关键路径法

**PDM（前导图法）四种依赖关系**：
- FS（完成-开始）：A完成B才能开始（最常见）
- FF（完成-完成）：A完成B才能完成
- SS（开始-开始）：A开始B才能开始
- SF（开始-完成）：A开始B才能完成

**关键路径的特性**：
- 是网络图中最长的路径
- 决定项目最短工期
- 关键路径上的活动总浮动时间为零
- 一个项目可能有多条关键路径

**时间参数**：
- ES（最早开始）、EF（最早完成）
- LS（最晚开始）、LF（最晚完成）
- TF（总浮动时差）= LF - EF = LS - ES
- FF（自由浮动时差）= 不影响紧后活动最早开始的最大延迟

### 8.2 进度压缩技术

| 技术 | 说明 | 风险 |
|------|------|------|
| 赶工（Crashing） | 增加资源以缩短工期 | 成本增加、资源边际效应 |
| 快速跟进（Fast Tracking） | 并行执行原本串行的活动 | 返工风险增加 |

## 9. 软件质量管理

### 9.1 软件质量模型

**McCall模型三个维度**：
- **产品运行**：正确性、可靠性、效率、完整性、可用性
- **产品修正**：可维护性、灵活性、可测试性
- **产品转移**：可移植性、可重用性、互操作性

**ISO/IEC 25010（SQuaRE替代9126）质量模型**：

| 质量特性 | 子特性 |
|---------|--------|
| 功能适用性 | 功能完整性、功能正确性、功能适合性 |
| 性能效率 | 时间特性、资源利用率、容量 |
| 兼容性 | 共存性、互操作性 |
| 可用性 | 可辨识性、易学性、可操作性、用户错误保护、界面美观、可访问性 |
| 可靠性 | 成熟性、可用性、容错性、易恢复性 |
| 安全性 | 保密性、完整性、不可抵赖性、可审计性、真实性 |
| 可维护性 | 模块化、可复用性、易分析性、易修改性、易测试性 |
| 可移植性 | 适应性、易安装性、易替换性 |

### 9.2 软件质量保证（SQA）

**SQA活动**：
- 制定质量计划
- 实施过程审计
- 产品评审与测试监控
- 缺陷分析与预防
- 质量度量与报告

### 9.3 技术评审

**评审类型**：
- **走查（Walkthrough）**：作者主导，非正式
- **技术评审（Technical Review）**：同行评审，正式程度中等
- **正式审查（Inspection）**：严格流程，角色分工（主持人、作者、评审员、记录员、经理）

## 10. 软件过程改进

### 10.1 IDEAL模型

```
Initiating（启动） → Diagnosing（诊断） → Establishing（建立）
→ Acting（行动） → Learning（学习）
```

### 10.2 CMMI 过程域的能力等级

每个过程域可按能力等级评估：
- 0级：未完成
- 1级：已执行
- 2级：已管理
- 3级：已定义

### 10.3 CMMI 连续式与阶段式表示

- **阶段式**：按成熟度等级1-5评估整个组织
- **连续式**：按过程域能力等级分别评估，灵活选择改进方向

## 11. 软件项目管理核心要点

### 11.1 项目三角形

```
        范围(质量)
        /\
       /  \
      /    \
     /      \
    /________\
  成本        时间
```

范围、时间、成本三者相互制约，质量是三角的核心。一个变了，至少另一个要跟着变。

### 11.2 团队管理

**Tuckman团队发展阶段**：形成期 → 震荡期 → 规范期 → 执行期 → 解散期

**沟通渠道数** = n×(n-1)/2，其中n为团队人数。

**激励理论**：
- **马斯洛需求层次**：生理 → 安全 → 社交 → 尊重 → 自我实现
- **赫兹伯格双因素**：保健因素（不满足会不满）+ 激励因素（满足有动力）
- **麦克利兰成就动机**：成就需求、权力需求、归属需求
