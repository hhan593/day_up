# 11 — 数据库设计基础知识

## 1. 数据库系统基本概念

### 1.1 数据库系统组成

数据库系统（DBS）= 数据库（DB）+ 数据库管理系统（DBMS）+ 应用系统 + 数据库管理员（DBA）+ 用户。

**DBMS 核心功能**：
- **数据定义**：DDL（CREATE/ALTER/DROP）
- **数据操纵**：DML（SELECT/INSERT/UPDATE/DELETE）
- **数据控制**：DCL（GRANT/REVOKE）
- **事务管理**：ACID保证
- **存储管理**：索引、缓存、文件组织

### 1.2 三级模式两级映像

```
外部层  ┌──── 外模式1 ──── 外模式2 ──── ... ──── 外模式n ────┐
        │          ↕ 外模式/概念模式映像                        │
概念层  │              概念模式（逻辑模式）                      │
        │          ↕ 概念模式/内模式映像                        │
内部层  │              内模式（存储模式）                       │
        └─────────────────────────────────────────────────────┘
```

| 层次 | 别称 | 说明 | 示例 |
|------|------|------|------|
| **外模式** | 用户模式/子模式 | 用户视角的数据视图 | 视图（View） |
| **概念模式** | 逻辑模式/模式 | 所有数据的全局逻辑结构 | 表定义、约束 |
| **内模式** | 存储模式 | 数据的物理存储方式和结构 | 索引、文件组织、压缩 |

**两级映像**：
- **外模式/概念模式映像**：保证逻辑独立性——概念模式变化不影响外模式
- **概念模式/内模式映像**：保证物理独立性——内模式变化不影响概念模式

### 1.3 数据模型的三个层次

| 层次 | 抽象级别 | 代表 |
|------|---------|------|
| **概念数据模型** | 最高抽象，面向用户 | E-R模型 |
| **逻辑数据模型** | 中间抽象，面向DBMS | 关系模型（主流）、层次模型、网状模型、面向对象模型 |
| **物理数据模型** | 最低抽象，面向存储 | 索引、聚簇、分区 |

## 2. 关系数据库基础

### 2.1 关系模型核心概念

| 术语 | 含义 | 类比 |
|------|------|------|
| **关系（Relation）** | 一张二维表 | 表（Table） |
| **元组（Tuple）** | 表中的一行 | 行（Row）/ 记录 |
| **属性（Attribute）** | 表中的一列 | 列（Column）/ 字段 |
| **域（Domain）** | 属性的取值范围 | 数据类型+约束 |
| **候选码（Candidate Key）** | 能唯一标识元组的属性组 | — |
| **主码（Primary Key）** | 选定的候选码 | 主键 |
| **外码（Foreign Key）** | 参照另一关系主码的属性 | 外键 |
| **主属性** | 属于任一候选码的属性 | — |
| **非主属性** | 不属于任何候选码的属性 | — |
| **全码（All-Key）** | 所有属性一起构成候选码 | — |

### 2.2 关系代数

**基本运算**（5种）：

| 运算 | 符号 | 含义 |
|------|------|------|
| **并（Union）** | R ∪ S | 属于R或S的元组（需兼容） |
| **差（Difference）** | R - S | 属于R但不属于S的元组 |
| **笛卡尔积（Cartesian Product）** | R × S | 所有元组的组合（n×m个元组） |
| **选择（Selection）** | σ_条件(R) | 选取满足条件的行（水平切割） |
| **投影（Projection）** | π_属性列表(R) | 选取指定的列（垂直切割，自动去重） |

**扩展运算**（4种，可由基本运算推导）：

| 运算 | 符号 | 等价关系代数 | 含义 |
|------|------|-------------|------|
| **交（Intersection）** | R ∩ S | R - (R - S) | 同时属于R和S的元组 |
| **θ连接（θ-Join）** | R ⋈_θ S | σ_θ(R × S) | 满足条件θ的笛卡尔积子集 |
| **等值连接** | R ⋈_A=B S | σ_A=B(R × S) | θ连接的θ为"=" |
| **自然连接** | R ⋈ S | π(σ_R.B=S.B(R × S)) | 公共属性等值且去重 |
| **外连接** | ⟕ / ⟖ / ⟗ | 自然连接 + 悬浮元组补NULL | 左外/右外/全外连接 |
| **除（Division）** | R ÷ S | — | R中与S中所有元组都有关的元组 |

**除运算理解**：R ÷ S = { t | 对S中每个元组, t与它的连接结果都在R中 }。典型用途："选了全部课程的学生"。

### 2.3 关系完整性约束

| 约束类型 | 规则 | 说明 |
|----------|------|------|
| **实体完整性** | 主码不能为空(NULL) | 保证每个实体可唯一标识 |
| **参照完整性** | 外码要么为空，要么等于被参照关系的主码值 | 保证关联的有效性 |
| **用户定义完整性** | 业务规则约束 | 如年龄范围 CHECK(age BETWEEN 0 AND 150) |

**违反完整性的操作处理**（参照完整性）：
| 操作 | 处理方式 |
|------|---------|
| 向参照关系中插入/修改外码值 | 检查被参照关系中是否存在对应主码 |
| 删除被参照关系元组 | 级联删除 / 置空 / 拒绝删除 |
| 修改被参照关系主码 | 级联更新 / 置空 / 拒绝修改 |

## 3. 关系数据库规范化理论

> 系统架构设计师高频考点：函数依赖判断、范式判定与分解

### 3.1 函数依赖

| 依赖类型 | 符号 | 含义 | 示例（关系R: 学号,姓名,系号,系名,课程号,成绩） |
|----------|------|------|------|
| **函数依赖** | X → Y | X确定后Y唯一确定 | 学号 → 姓名 |
| **完全函数依赖** | X →_F Y | Y依赖于整个X，而非X的子集 | (学号,课程号) →_F 成绩 |
| **部分函数依赖** | X →_P Y | Y只依赖于X的一部分 | (学号,课程号) →_P 姓名（只依赖学号） |
| **传递函数依赖** | X →_T Z | X → Y 且 Y → Z（Y不是X的子集，Z不是Y的子集） | 学号 → 系号 → 系名 |

**Armstrong 公理系统**（用于推导函数依赖）：
1. **自反律**：若 Y ⊆ X ⊆ U，则 X → Y
2. **增广律**：若 X → Y，则 XZ → YZ
3. **传递律**：若 X → Y 且 Y → Z，则 X → Z

**推论**：合并律、分解律、伪传递律。

**属性闭包**（X⁺）：给定属性集X，从函数依赖集F能推导出的所有属性的集合。用于判断X是否为候选码（X⁺ = U）。

### 3.2 范式（Normal Form）

| 范式 | 满足条件 | 消除的问题 |
|------|---------|-----------|
| **1NF** | 属性不可再分（原子性） | 消除多值字段 |
| **2NF** | 满足1NF + 每个非主属性完全函数依赖于候选码 | 消除部分函数依赖 |
| **3NF** | 满足2NF + 每个非主属性不传递函数依赖于候选码 | 消除传递函数依赖 |
| **BCNF** | 每个函数依赖的决定因素都包含码 | 消除主属性对码的部分和传递依赖 |
| **4NF** | 满足BCNF + 不存在非平凡的多值依赖 | 消除多值依赖 |
| **5NF** | 满足4NF + 不存在不包含码的连接依赖 | 消除连接依赖 |

**范式关系**：1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF ⊃ 4NF ⊃ 5NF

**范式的"不够好"本质**：
- 1NF问题：数据冗余 + 插入异常 + 删除异常 + 更新异常（因为部分依赖）
- 2NF问题：插入异常 + 删除异常 + 更新异常（因为传递依赖）
- 3NF/BCNF问题：信息冗余（因为多值依赖）

### 3.3 模式分解

**无损连接分解**：将R分解为R₁, R₂, ..., Rₙ后，通过自然连接能完全恢复原始关系R。

**无损连接判定（Chase算法）**：
- 二元分解 R → {R₁, R₂}，无损连接 ⇔ (R₁ ∩ R₂) → (R₁ - R₂) 或 (R₁ ∩ R₂) → (R₂ - R₁)

**保持函数依赖分解**：分解后所有子关系的函数依赖集的闭包等于原函数依赖集的闭包。

**分解目标**：达到3NF或BCNF，同时保持**无损连接**和**保持函数依赖**。

| 目标 | 可达性 |
|------|--------|
| 无损连接 + BCNF | 总是可以 |
| 无损连接 + 保持函数依赖 + BCNF | 不一定能同时满足 |
| 无损连接 + 保持函数依赖 + 3NF | 总是可以 |

> 实际工程中通常达到3NF即可，既消除了大部分异常又不丢失函数依赖。

## 4. 数据库设计方法

### 4.1 数据库设计六阶段

```
需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 数据库实施 → 运行维护
```

| 阶段 | 输入 | 输出 | 核心任务 |
|------|------|------|---------|
| **需求分析** | 用户需求 | 需求说明书、数据流图(DFD)、数据字典(DD) | 了解数据和业务需求 |
| **概念结构设计** | 需求说明书 | E-R图（概念模型） | 抽象为不依赖DBMS的概念数据模型 |
| **逻辑结构设计** | E-R图 | 关系模式（表结构） | E-R图→关系模式；模式规范化 |
| **物理结构设计** | 关系模式 | 物理存储结构 | 选索引、存贮结构、分区方案 |
| **数据库实施** | 物理设计 | 可运行数据库 | DDL建表、数据加载、程序编写 |
| **运行维护** | 运行数据库 | 优化与调整 | 性能调优、备份恢复、重构 |

### 4.2 E-R图（实体-联系图）

**E-R图构成要素**：

| 要素 | 图形表示 | 说明 |
|------|---------|------|
| **实体（Entity）** | 矩形框 | 客观存在并可相互区分的事物 |
| **属性（Attribute）** | 椭圆 | 实体或联系的特征 |
| **联系（Relationship）** | 菱形框 | 实体之间的关联 |
| **连线** | 无向边 | 连接实体与属性、实体与联系 |

**联系类型（按参与实体数）**：

| 类型 | 符号 | 示例 |
|------|------|------|
| 1:1（一对一） | 1 — 1 | 系 ↔ 系主任 |
| 1:N（一对多） | 1 — N | 系 ↔ 教师 |
| M:N（多对多） | M — N | 学生 ↔ 课程 |

**弱实体**（Weak Entity）：没有足够属性形成主码，依赖另一个强实体（标识实体）存在。用双线矩形表示。

**E-R图冲突**（多个局部E-R图合并时产生）：
- **属性冲突**：同名异义、同义异名
- **命名冲突**：同一对象不同名称
- **结构冲突**：同一对象在不同视图中抽象级别不同（实体 vs 属性）

### 4.3 E-R图 → 关系模型的转换规则

| 转换对象 | 转换规则 |
|----------|---------|
| **实体** | 每个实体 → 一个关系（表），实体属性 → 关系的列 |
| **1:1 联系** | 两种方式：① 任选一方加入对方主码作为外码；② 合并为一个关系 |
| **1:N 联系** | 在 N 端加入 1 端的主码作为外码 |
| **M:N 联系** | 单独建立一个关系（中间表），包含两端实体的主码（联合主码）+ 联系自身属性 |
| **多元联系** | 单独建立一个关系，包含所有参与实体的主码 |
| **弱实体** | 建立独立关系，包含标识实体的主码（构成联合主码） |

## 5. 事务管理

> 系统架构设计师考点：ACID、隔离级别、封锁协议、死锁

### 5.1 ACID 特性

| 特性 | 含义 | 破坏因素 | 保障机制 |
|------|------|---------|---------|
| **A 原子性** | 事务全做或全不做 | 系统故障 | 日志+回滚（Undo） |
| **C 一致性** | 事务执行前后数据库保持一致状态 | 并发操作 | 完整性约束+隔离性 |
| **I 隔离性** | 并发事务间互不干扰 | 并发访问 | 封锁/多版本/时间戳 |
| **D 持久性** | 已提交事务的结果永久保存 | 存储故障 | 日志+写入确认（Redo） |

### 5.2 并发控制

**并发操作带来的问题**：

| 问题 | 说明 | 示例 |
|------|------|------|
| **丢失修改** | T1修改被T2覆盖，T1修改"丢失" | T1写A=5，T2写A=10，T1提交后A=10（T1的5丢失） |
| **不可重复读** | T1两次读同一数据，期间T2修改并提交，T1两次读到不同值 | T1读A=5，T2改A=10并提交，T1再读A=10 |
| **脏读** | T1读到了T2未提交的修改，T2回滚后T1读到的数据无效 | T2改A=10（未提交），T1读A=10，T2回滚，恢复A=5 |

### 5.3 封锁（Locking）

**锁的类型**：

| 锁类型 | 符号 | 说明 | 兼容性 |
|--------|------|------|--------|
| **共享锁（S锁/读锁）** | S | 可读不可写 | 与S兼容，与X不兼容 |
| **排他锁（X锁/写锁）** | X | 可读可写，独占 | 与任何锁都不兼容 |

**封锁协议**：

| 协议 | 规则 | 能防止的问题 |
|------|------|-------------|
| **一级封锁协议** | 修改前加X锁，事务结束释放 | 丢失修改 |
| **二级封锁协议** | 一级 + 读前加S锁，读完释放 | 丢失修改 + 脏读 |
| **三级封锁协议** | 一级 + 读前加S锁，事务结束释放 | 丢失修改 + 脏读 + 不可重复读 |

**两段锁协议（2PL）**：所有事务分两阶段——① 加锁/增长阶段（只能加锁不能解锁）② 解锁/收缩阶段（只能解锁不能加锁）。

> 遵守2PL的并发调度一定是可串行化的，但可串行化不一定遵守2PL。

**封锁粒度**：越大并发度越低、开销越小；越小并发度越高、开销越大。常见粒度：表级、页级、行级。

**死锁**：
- **死锁预防**：一次封锁法（一次申请全部所需锁）、顺序封锁法（按预定顺序加锁）
- **死锁检测**：等待图（Wait-for Graph），检测环
- **死锁解除**：选择代价最小的事务回滚（撤销）

### 5.4 隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|----------|------|-----------|------|---------|
| **READ UNCOMMITTED** | ✓ | ✓ | ✓ | 不加读锁 |
| **READ COMMITTED** | ✗ | ✓ | ✓ | 读后立即释放S锁 |
| **REPEATABLE READ** | ✗ | ✗ | ✓ | 读S锁持有到事务结束 |
| **SERIALIZABLE** | ✗ | ✗ | ✗ | 全串行化执行 |

> MySQL InnoDB 默认隔离级别：REPEATABLE READ；Oracle/PostgreSQL 默认：READ COMMITTED。

### 5.5 多版本并发控制（MVCC）

**核心思想**：写操作创建新版本，读操作读取合适版本，读写互不阻塞。

**实现机制**：每行数据维护多个版本，通过事务ID（XID）和可见性规则判断哪个版本对当前事务可见。

## 6. 数据库性能优化

### 6.1 索引

**索引的物理存储方式**：

| 索引类型 | 结构 | 特点 | 适用场景 |
|----------|------|------|---------|
| **B+树索引** | B+树 | 有序、范围查询高效、增删改维护成本低 | 等值 & 范围查询（最常用） |
| **哈希索引** | 哈希表 | O(1)单值定位、不支持范围查询 | 等值查询 |
| **位图索引** | 位图（Bitmap） | 压缩存储、适合低基数列 | 数据仓库（性别/状态等） |
| **全文索引** | 倒排索引 | 文本分词检索 | 模糊搜索/关键词检索 |

**聚集索引 vs 非聚集索引**：

| | 聚集索引（Clustered） | 非聚集索引（Non-Clustered） |
|------|------|------|
| **数据存储** | 叶子节点即数据页（数据按索引顺序物理存储） | 叶子节点存指针指向数据行 |
| **数量限制** | 每表只能有一个 | 每表可以有多个 |
| **查找效率** | 一次找到数据（覆盖查询更快） | 需回表查询（除非覆盖索引） |
| **适用场景** | 主键、频繁范围查询的列 | 一般查询条件 |

**索引设计原则**：
- WHERE/JOIN/ORDER BY/GROUP BY 的列建索引
- 高选择性的列建索引（值区分度高）
- 避免过多索引（降低写入性能）
- 复合索引遵循最左前缀规则
- 避免对索引列使用函数或计算

### 6.2 SQL 查询优化

| 优化策略 | 说明 |
|----------|------|
| **避免 SELECT *** | 只查需要的列，减少I/O |
| **使用 LIMIT** | 限制返回行数 |
| **WHERE 条件优化** | 将过滤性最强的条件放前面 |
| **避免在WHERE中使用函数** | WHERE YEAR(date) = 2024 无法使用索引，改为 WHERE date BETWEEN '2024-01-01' AND '2024-12-31' |
| **EXISTS 替代 IN** | 子查询结果集大时 EXISTS 更高效 |
| **JOIN 代替子查询** | 多数情况下 JOIN 比子查询快 |
| **UNION ALL 替代 UNION** | UNION 自动去重有排序开销，不需要去重用 ALL |
| **分页优化** | 大偏移量不用 LIMIT N, M，用游标(WHERE id > X LIMIT M) |
| **批量操作** | 批量INSERT代替逐条INSERT |

### 6.3 数据库架构优化

| 技术 | 说明 | 适用场景 |
|------|------|---------|
| **读写分离** | 主库写 + 从库读，从库通过主从复制同步 | 读多写少 |
| **分库（垂直拆分）** | 按业务模块将不同表分布到不同库 | 业务耦合度低的模块 |
| **分表（水平拆分）** | 按某字段将同一表数据分布到多个表 | 单表数据量大（通常 > 1000万行） |
| **缓存** | Redis/Memcached 缓存热点数据 | 高频读取的数据 |
| **数据库连接池** | 复用连接减少创建开销 | 高并发场景 |

### 6.4 执行计划与EXPLAIN

**EXPLAIN关键输出字段**：
| 字段 | 含义 |
|------|------|
| type | 访问类型（ALL→全表扫描 < index→索引全扫 < range→范围 < ref→非唯一索引 < eq_ref→唯一索引 < const→主键） |
| key | 实际使用的索引 |
| rows | 预估扫描行数（越小越好） |
| Extra | Using filesort（需额外排序，不好）、Using temporary（用临时表，不好）、Using index（覆盖索引，好） |

## 7. 分布式数据库

### 7.1 分布式数据库特征

| 特征 | 说明 |
|------|------|
| **分布性** | 数据分布在多个网络节点上 |
| **逻辑整体性** | 对用户呈现为单一逻辑数据库 |
| **节点自治性** | 每个节点有自己的DBMS，能独立处理本地事务 |
| **协作性** | 各节点通过网络协作完成全局事务 |

### 7.2 数据分片（Fragmentation）

| 分片方式 | 说明 | 示例 |
|----------|------|------|
| **水平分片** | 按行拆分，不同节点的表结构相同 | 按用户ID取模/范围分片 |
| **垂直分片** | 按列拆分，不同节点存不同列 | 用户基本信息 + 用户扩展信息分库 |
| **导出分片** | 基于另一关系的属性分片 | 订单表按所属用户的地区分片 |
| **混合分片** | 结合多种分片方式 | 先水平再垂直 |

**分片透明性**：应用无需知道数据如何分布（4级透明：分片透明、位置透明、局部映射透明、数据模型透明）。

### 7.3 分布式事务（简要）

> 详细内容见 [07-分布式系统与中间件.md](07-分布式系统与中间件.md)

| 协议 | 核心思想 | 特点 |
|------|---------|------|
| **2PC（两阶段提交）** | 协调者 → 参与者：Prepare → 所有回复OK → Commit | 强一致，阻塞协议 |
| **3PC（三阶段提交）** | 2PC加超时机制，增加预提交阶段 | 减少阻塞，但更复杂 |
| **TCC** | Try-Confirm-Cancel，业务层补偿 | 业务侵入性大，性能好 |
| **Saga** | 长事务拆分，每个本地事务+补偿操作 | 最终一致性 |

## 8. NoSQL 与 NewSQL

### 8.1 NoSQL 四大类型

| 类型 | 数据模型 | 代表产品 | 适用场景 |
|------|---------|---------|---------|
| **键值存储** | Key → Value | Redis, Memcached | 缓存、会话存储、计数 |
| **文档数据库** | JSON/BSON 文档 | MongoDB, CouchDB | 内容管理、用户资料、日志 |
| **列族数据库** | 行键 → 列族 → 列 | HBase, Cassandra | 日志、时序数据、物联网 |
| **图数据库** | 节点 + 边 + 属性 | Neo4j, JanusGraph | 社交网络、推荐、知识图谱 |

### 8.2 CAP 与 NoSQL 选型

| 数据库 | CAP定位 | 说明 |
|--------|---------|------|
| MongoDB | CP（可配置为AP） | 默认强一致 |
| Cassandra | AP | 最终一致性，高可用 |
| HBase | CP | 强一致性，分区容忍 |
| Redis（集群） | CP | 主从切换期间不可用 |
| Neo4j（集群） | CP | 主从模式 |

### 8.3 NewSQL

NewSQL = 关系模型 + 分布式扩展能力，兼具ACID和水平扩展。

| 代表 | 特点 |
|------|------|
| **TiDB** | 开源分布式HTAP数据库，兼容MySQL协议 |
| **CockroachDB** | 分布式SQL数据库，兼容PostgreSQL |
| **Spanner** | Google全球分布式数据库，TrueTime时钟 |

## 9. 数据仓库与数据挖掘

### 9.1 OLTP vs OLAP

| 维度 | OLTP（联机事务处理） | OLAP（联机分析处理） |
|------|---------------------|---------------------|
| 目的 | 日常事务处理 | 决策分析支持 |
| 操作 | 增删改查（大量短事务） | 复杂查询（少量长查询） |
| 数据 | 当前、详细、更新频繁 | 历史、汇总、只读 |
| 数据量 | GB级 | TB/PB级 |
| 数据模型 | E-R模型 / 规范化表 | 星型/雪花型 |
| 并发用户 | 大量 | 少量 |
| 响应时间 | 毫秒级 | 秒至分钟级 |

### 9.2 数据仓库建模

**维度建模**：

| 模式 | 说明 | 特点 |
|------|------|------|
| **星型模式** | 一个事实表 + 多个维度表，维度表直接关联事实表 | 查询效率高、存在冗余 |
| **雪花型模式** | 星型的维度表进一步规范化 | 无冗余、查询需多表连接 |
| **星座模式** | 多个事实表共享维度表 | 复杂分析场景 |

**基本元素**：
- **事实表**：存储度量值（销售额、数量），由外键+数值型度量组成
- **维度表**：描述分析角度（时间、地区、产品、客户）

### 9.3 数据挖掘方法

| 方法 | 说明 | 典型算法 |
|------|------|---------|
| **分类（Classification）** | 预测离散类别标签 | 决策树、朴素贝叶斯、SVM、神经网络 |
| **聚类（Clustering）** | 将相似对象归为一组（无监督） | K-means、DBSCAN、层次聚类 |
| **关联规则** | 发现项之间的关联 | Apriori、FP-Growth |
| **回归（Regression）** | 预测连续数值 | 线性回归、逻辑回归 |
| **异常检测** | 发现异常/离群点 | 基于统计、基于距离 |

### 9.4 大数据技术栈

| 组件 | 用途 |
|------|------|
| **Hadoop HDFS** | 分布式文件存储 |
| **Hadoop MapReduce** | 分布式批处理计算 |
| **Spark** | 内存计算引擎（批/流/图/ML） |
| **Hive** | SQL on Hadoop（数据仓库） |
| **Flink** | 实时流处理 |
| **Kafka** | 消息队列/流平台 |
| **HBase** | NoSQL列族数据库 on HDFS |
| **Elasticsearch** | 全文搜索引擎 |

## 10. 常考考点速查

### 10.1 范式判定步骤

```
给定关系R和函数依赖集F：
1. 找出候选码
2. 1NF：所有属性是否原子 → 是则1NF
3. 2NF：非主属性是否存在对候选码的部分依赖 → 否则2NF
4. 3NF：非主属性是否存在对候选码的传递依赖 → 否则3NF
5. BCNF：每个FD的决定因素是否都包含码 → 是则BCNF
```

### 10.2 关键对比

| 对比项 | A | B |
|--------|---|---|
| **自然连接 vs 等值连接** | 公共属性去重 | 公共属性保留（两次） |
| **外连接 vs 内连接** | 保留悬浮元组 | 只保留匹配元组 |
| **TRUNCATE vs DELETE** | DDL、不可回滚、快 | DML、可回滚、慢 |
| **DROP vs DELETE** | DDL、删表结构+数据 | DML、只删数据 |

### 10.3 E-R图→关系模式转换要点

```
实体 ────────────→ 独立关系（表）
1:1联系 ──────────→ 任意一方加入外码，或合并为一个关系
1:N联系 ──────────→ N方加入1方主码作为外码
M:N联系 ──────────→ 独立关系（中间表），两端主码联合
弱实体 ────────────→ 独立关系，含标识实体主码（联合主码）
```

### 10.4 SQL 核心语法速查

```sql
-- 基本查询
SELECT [DISTINCT] 列名 FROM 表名
  WHERE 条件
  GROUP BY 分组列 HAVING 分组条件
  ORDER BY 排序列 [ASC|DESC]
  LIMIT 偏移, 数量;

-- 连接
SELECT * FROM A INNER JOIN B ON A.id = B.aid;     -- 内连接
SELECT * FROM A LEFT JOIN B ON A.id = B.aid;       -- 左外连接
SELECT * FROM A RIGHT JOIN B ON A.id = B.aid;      -- 右外连接

-- 子查询
SELECT * FROM A WHERE id IN (SELECT aid FROM B WHERE ...);
SELECT * FROM A WHERE EXISTS (SELECT 1 FROM B WHERE B.aid = A.id);

-- 集合操作
SELECT id FROM A UNION SELECT id FROM B;            -- 并集去重
SELECT id FROM A UNION ALL SELECT id FROM B;        -- 并集不去重
SELECT id FROM A INTERSECT SELECT id FROM B;        -- 交集
SELECT id FROM A EXCEPT SELECT id FROM B;           -- 差集（MySQL不支持）

-- 索引与视图
CREATE INDEX idx_name ON 表名(字段);
CREATE VIEW 视图名 AS SELECT ...;
```
