# 13 — 嵌入式系统架构设计理论与实践

## 1. 嵌入式系统基础

### 1.1 定义与特征

**嵌入式系统**：以应用为中心，以计算机技术为基础，软硬件可裁剪，满足应用系统对功能、可靠性、成本、体积、功耗有严格要求的专用计算机系统。

**嵌入式系统核心特征**：

| 特征 | 说明 |
|------|------|
| **专用性** | 完成特定功能，非通用计算 |
| **嵌入式** | 嵌入到宿主设备中（非独立计算机） |
| **可裁剪** | 软硬件可根据应用需求定制裁剪 |
| **实时性** | 多数有实时性要求 |
| **可靠性** | 长时间无故障运行（无人值守） |
| **资源受限** | 计算资源、内存、功耗严格受限 |
| **低成本** | 大规模量产，对成本高度敏感 |

**嵌入式系统 vs 通用计算机**：

| 维度 | 嵌入式系统 | 通用计算机（PC/Server） |
|------|-----------|------------------------|
| 功能 | 专用、固定 | 通用、可编程扩展 |
| 资源 | 严格受限（低功耗/小内存） | 相对充裕 |
| 实时性 | 通常有实时要求 | 一般无硬实时要求 |
| 操作系统 | RTOS、裸机、定制Linux | 通用OS（Windows/Linux） |
| 可靠性 | 极高（无人值守长期运行） | 中等（可容忍偶尔死机） |
| 升级方式 | OTA远程升级或出厂前烧录 | 用户自行安装更新 |
| 典型产品 | 智能手表、汽车ECU、工业PLC | 个人电脑、服务器 |

### 1.2 嵌入式系统分类

| 分类维度 | 类型 | 说明 |
|----------|------|------|
| **按实时性** | 硬实时系统 | 任务必须在截止时间前完成，否则系统失效 |
| | 软实时系统 | 错过截止时间性能降级但不失效 |
| | 非实时系统 | 无时间约束 |
| **按复杂度** | 简单嵌入式 | 8/16位MCU、裸机/简单RTOS（遥控器、电子表） |
| | 中等嵌入式 | 32位MCU/MPU、RTOS（智能家居、工业控制） |
| | 复杂嵌入式 | 高性能SoC/多核、Linux/Android（手机、车载） |
| **按应用领域** | 消费电子 | 智能手机、智能穿戴、智能家电 |
| | 工业控制 | PLC、工业机器人、SCADA |
| | 汽车电子 | ECU、ADAS、车载娱乐系统 |
| | 航空航天 | 飞控计算机、卫星星载系统 |
| | 医疗电子 | 心电图、CT、血糖仪 |
| | 军事国防 | 制导系统、通信系统 |

## 2. 嵌入式系统硬件基础

### 2.1 嵌入式处理器分类

| 类型 | 全称 | 特征 | 典型产品 | 应用 |
|------|------|------|---------|------|
| **MCU** | 微控制器（单片机） | CPU+RAM+ROM+I/O集成单芯片 | STM32、MSP430、51系列 | 简单控制、传感器 |
| **MPU** | 微处理器 | 仅CPU核心，需外接存储/外设 | ARM Cortex-A系列、PowerPC | 网关、高端嵌入式 |
| **DSP** | 数字信号处理器 | 哈佛结构、硬件乘法器、MAC指令 | TI TMS320系列 | 音视频处理、雷达 |
| **SoC** | 片上系统 | 集成CPU+GPU+NPU+通信+存储的单芯片 | 高通骁龙、华为海思、Apple A系列 | 智能手机、平板 |
| **FPGA** | 现场可编程门阵列 | 硬件可编程、并行处理 | Xilinx、Altera(Intel) | 原型验证、高速数据处理 |
| **ASIC** | 专用集成电路 | 功能固化、不可修改 | 挖矿芯片、AI推理芯片 | 特定功能、大批量 |

**MCU vs MPU**：
| 维度 | MCU | MPU |
|------|-----|-----|
| 集成度 | CPU+存储+外设集成芯片 | 仅CPU，外接存储和外设 |
| 功耗 | 极低（μA~mA级） | 较高 |
| 操作系统 | 裸机/RTOS | Linux/Android/RTOS |
| 价格 | 极低 | 较高 |
| 典型应用 | 小家电、传感器节点 | 车载中控、网关 |

### 2.2 嵌入式处理器架构

| 架构 | 特点 | 代表厂商 |
|------|------|---------|
| **ARM** | RISC，低功耗，IP授权模式，市场主导 | ARM Cortex-M/A/R系列 |
| **RISC-V** | 开源RISC，自由定制，新兴势力 | SiFive、阿里平头哥 |
| **MIPS** | 经典RISC，曾广泛用于嵌入式 | 龙芯早期 |
| **x86** | CISC，高性能高功耗 | Intel Atom（低功耗x86） |

**ARM Cortex 系列区分**：

| 系列 | 定位 | 性能 | 应用 |
|------|------|------|------|
| **Cortex-M** | 微控制器 | 低 | IoT、电机控制、传感器 |
| **Cortex-R** | 实时处理 | 中 | 汽车安全、硬盘控制、基站 |
| **Cortex-A** | 应用处理器 | 高 | 手机、平板、车载娱乐 |

### 2.3 嵌入式存储器体系

```
速度 ↑                                     容量 ↑
最快 ┌──────────┐  最快
     │ 寄存器    │ (CPU内)
     ├──────────┤
     │ Cache    │ (L1/L2)
     ├──────────┤
     │ SRAM     │ (片上/片外，高速缓存)
     ├──────────┤
     │ DRAM     │ (DDR3/DDR4/LPDDR，主存)
     ├──────────┤
     │ NAND Flash│ (eMMC/UFS，固态存储)
     ├──────────┤
最慢 │ NOR Flash │ (代码存储，支持XIP)
     └──────────┘  最慢
```

**关键存储技术**：
| 类型 | 特点 | 用途 |
|------|------|------|
| **NOR Flash** | 支持XIP（片内执行），读取快、写入慢 | 固件存储、Bootloader |
| **NAND Flash** | 容量大、成本低、按块操作 | 数据存储（eMMC/UFS/SSD） |
| **SRAM** | 速度快、价格昂贵 | Cache、紧耦合内存（TCM） |
| **DRAM** | 需刷新、容量大、价格适中 | 主存（LPDDR/DDR） |
| **EEPROM** | 可按字节擦写 | 参数存储、配置信息 |

**XIP（eXecute In Place）**：代码直接在Flash中执行，不需加载到RAM。

### 2.4 常用接口与总线

| 接口 | 类型 | 速率 | 典型用途 |
|------|------|------|---------|
| **UART** | 串行异步 | 低（KB/s~MB/s） | 调试串口、GPS模块 |
| **I²C** | 串行同步（双线） | 中（100K~3.4Mbps） | 传感器、EEPROM、触摸屏 |
| **SPI** | 串行同步（四线） | 高（MB/s~几十MB/s） | Flash、显示屏、ADC |
| **CAN** | 差分串行 | 中（最高1Mbps） | 汽车电子、工业控制 |
| **USB** | 高速串行 | 高（480M~10Gbps） | 外设连接、充电 |
| **Ethernet** | 网络 | 高（100M~10Gbps） | 工业网络、智能网关 |
| **PCIe** | 高速串行 | 极高（GB/s） | 高性能嵌入式、AI加速器 |
| **MIPI** | 串行差分 | 高 | 摄像头、显示屏 |
| **GPIO** | 通用数字接口 | — | 按键、LED、继电器 |

## 3. 嵌入式操作系统

### 3.1 嵌入式OS 分类

| 类型 | 特点 | 典型系统 | 适用 |
|------|------|---------|------|
| **裸机（Bare Metal）** | 无OS，主循环+中断 | 前后台系统 | 极简单设备 |
| **RTOS** | 实时内核，确定性调度 | FreeRTOS、μC/OS、VxWorks、RT-Thread | 工业控制、汽车 |
| **嵌入式Linux** | 功能丰富，非实时 | Yocto Linux、OpenWrt、Android | 网关、HMI |
| **实时Linux** | Linux + 实时补丁 | PREEMPT_RT Linux、Xenomai | 复杂实时系统 |

### 3.2 实时操作系统（RTOS）核心机制

#### 3.2.1 任务管理

**任务（Task/Thread）**：RTOS中独立执行的程序实体，具有独立栈空间和优先级。

**任务状态模型**：
```
        ┌──────────────────────────┐
        │                          ↓
    就绪态(Ready) ──调度──→ 运行态(Running)
        ↑                    │        │
        │     ┌──────────────┘        │
        │     ↓                       ↓
        │  阻塞态(Blocked)         挂起态(Suspended)
        │     │                       │
        └─────┴───────────────────────┘
           (从阻塞/挂起恢复)
```

**任务控制块（TCB）**：每个任务的数据结构，存储任务ID、优先级、栈指针、状态、CPU寄存器上下文。

#### 3.2.2 实时调度算法

| 算法 | 类型 | 原理 | 特点 |
|------|------|------|------|
| **FIFO（先来先服务）** | 非抢占 | 按创建顺序执行 | 简单但无法保证实时性 |
| **抢占式优先级调度** | 优先级抢占 | 高优先级任务可抢占低优先级 | RTOS标配 |
| **时间片轮转（Round-Robin）** | 时间片 | 同优先级任务轮流执行 | 同一优先级公平性 |
| **RMS（单调速率调度）** | 静态优先级 | 周期越短优先级越高 | 最优静态优先级算法 |
| **EDF（最早截止时间优先）** | 动态优先级 | 截止时间越近优先级越高 | 最优动态优先级算法 |
| **LLF（最小松弛优先）** | 动态优先级 | 松弛时间越少优先级越高 | 理论最优，实用较少 |

**RMS 可调度判定**：
- 对于 n 个独立周期任务，若 CPU 利用率 U ≤ n(2^(1/n) - 1)，则一定可调度
- n → ∞ 时，U ≤ ln2 ≈ 69.3%

**EDF**：只要 U ≤ 100%，就存在合法的调度方案。

**优先级反转（Priority Inversion）**：
```
高优先级任务H等待中优先级任务M释放资源，
而M又被低优先级任务L抢占 → H实际优先级被"反转"为最低

解决：优先级继承（Priority Inheritance）、优先级天花板（Priority Ceiling）
```

#### 3.2.3 任务间通信与同步

| 机制 | 用途 | 特点 |
|------|------|------|
| **信号量（Semaphore）** | 资源互斥访问、任务同步 | 计数信号量/二值信号量 |
| **互斥量（Mutex）** | 共享资源互斥（含优先级继承） | 与二值信号量有别（所有权） |
| **消息队列（Message Queue）** | 任务间数据传递 | FIFO，支持紧急消息插队 |
| **事件标志组（Event Flag）** | 多事件同步 | 任务等待多个事件条件 |
| **邮箱（Mailbox）** | 任务间发送固定大小消息 | 类似队列但容量通常为1 |
| **信号（Signal）** | 异步通知 | 类似中断处理，实时性高 |

**信号量 vs 互斥量**：
| 维度 | 信号量 | 互斥量 |
|------|--------|--------|
| 所有权 | 无所有权概念 | 有（只有获得锁的任务才能释放） |
| 优先级继承 | 不支持 | 支持（解决优先级反转） |
| 递归获取 | 通常不支持 | 部分支持（递归锁） |
| 用途 | 同步、信号通知 | 资源互斥访问 |

#### 3.2.4 中断管理

**中断服务程序（ISR）设计原则**：
- ISR内尽量简短（只做必要的事，其余交给任务）
- 不在ISR中做不确定的等待操作
- ISR与任务之间通过信号量/消息队列通信

**中断延迟** = 关中断最长时间 + 硬件响应时间 + 中断向量跳转时间

**中断响应时间** = 中断延迟 + ISR开头保护现场时间 + 首次执行用户代码时间

### 3.3 内存管理

**RTOS 内存管理方式**：

| 方式 | 特点 | 适用 |
|------|------|------|
| **静态分配** | 编译时确定，无碎片、确定性高 | 安全关键系统（航空） |
| **内存池（Memory Pool）** | 固定大小块，无碎片、速度快 | 消息缓冲、网络包缓冲 |
| **堆分配（malloc/free）** | 灵活但有碎片风险 | 非硬实时系统 |
| **MMU虚拟内存** | 进程隔离（MPU即可） | Linux/Android |

**MPU vs MMU**：
| | MPU（内存保护单元） | MMU（内存管理单元） |
|------|------|------|
| 功能 | 区域访问权限保护 | 虚拟地址映射+保护 |
| 复杂度 | 低 | 高 |
| 功耗 | 低 | 较高 |
| 适用处理器 | Cortex-M/R | Cortex-A |

### 3.4 主流 RTOS 对比

| RTOS | 特点 | 应用领域 |
|------|------|---------|
| **FreeRTOS** | 开源免费、轻量级、AWS维护、市场份额高 | IoT、消费电子 |
| **μC/OS** | 源码开放、认证支持（安全关键） | 医疗器械、航空 |
| **VxWorks** | 商业闭源、高性能、硬实时 | 航空航天、国防 |
| **RT-Thread** | 国产开源、组件丰富、IoT友好 | 工业、IoT |
| **QNX** | 微内核、极高可靠性、商业 | 汽车（仪表/ADAS） |
| **ThreadX** | 商业、微软收购（现Azure RTOS） | 消费、工业 |
| **LiteOS** | 华为开源、面向IoT | IoT、智能家居 |

## 4. 嵌入式系统软件架构设计

### 4.1 嵌入式软件架构模式

#### 4.1.1 前后台系统（Foreground/Background）

```
主循环（后台/Background）              中断服务程序（前台/Foreground）
┌─────────────────────────┐       ┌──────────────────────┐
│ while(1) {              │       │ ISR1() {             │
│   Task1();              │  抢   │  处理紧急事件          │
│   Task2();              │ ←占→  │  设置标志位            │
│   Task3();              │       │ }                    │
│ }                       │       │ ISR2() { ... }       │
└─────────────────────────┘       └──────────────────────┘
```

- **前台**：中断处理紧急事务
- **后台**：主循环轮询处理非紧急事务
- **优点**：简单，无OS开销
- **缺点**：任务执行时间不确定，实时性差，扩展困难
- **适用**：极简单设备（遥控器、电子表）

#### 4.1.2 轮询式架构（Round-Robin）

所有任务在主循环中按固定顺序执行，无中断、无抢占。
- **适用**：任务固定、对实时性无要求的场景

#### 4.1.3 中断驱动架构

系统主循环处于休眠/低功耗模式，所有操作由中断触发。
- **适用**：电池供电、低功耗设备（传感器节点）

#### 4.1.4 基于RTOS的多任务架构

```
       ┌─────────┐  ┌─────────┐  ┌─────────┐
       │ Task A  │  │ Task B  │  │ Task C  │
       │ (高优先级)│  │ (中优先级)│  │ (低优先级)│
       └────┬────┘  └────┬────┘  └────┬────┘
            │            │            │
       ┌────┴────────────┴────────────┴────────┐
       │            RTOS 内核                   │
       │  ┌─────────────────────────────────┐  │
       │  │ 调度器 │ IPC │ 内存管理 │ 中断管理 │  │
       │  └─────────────────────────────────┘  │
       └──────────────────┬────────────────────┘
                          │
             ┌────────────┴────────────┐
             │      硬件抽象层(HAL)      │
             └─────────────────────────┘
```

- **分层设计**：应用层 → Middleware → OS → BSP/HAL → 硬件
- **优点**：模块化、实时性可控、可扩展
- **适用**：中大型嵌入式系统

#### 4.1.5 事件驱动架构（Event-Driven）

系统由事件（内部/外部）触发状态转移，适用于状态机模型明显的场景（通信协议栈、GUI）。

**状态机实现方式**：
- 嵌套 switch-case
- 状态表（State Table）
- 状态模式（面向对象）
- 分层状态机（Harel Statechart）

### 4.2 嵌入式系统软件分层架构

```
┌───────────────────────────────────┐
│         应用层（Application）       │  ← 业务逻辑
├───────────────────────────────────┤
│        中间件层（Middleware）        │  ← 协议栈、文件系统、GUI
├───────────────────────────────────┤
│     操作系统层（OS Kernel）          │  ← 调度、IPC、内存管理
├───────────────────────────────────┤
│    板级支持包（BSP / HAL）          │  ← 硬件抽象、驱动接口
├───────────────────────────────────┤
│         硬件层（Hardware）          │  ← CPU、存储、外设
└───────────────────────────────────┘
```

**BSP（板级支持包）**：介于OS和硬件之间，提供硬件初始化、外设驱动接口。

**HAL（硬件抽象层）**：屏蔽硬件差异，为上层提供统一接口。

### 4.3 嵌入式Linux 架构

```
┌─────────────────────────────────────┐
│              Application            │  ← 用户空间应用
├─────────────────────────────────────┤
│       C Library (glibc/uClibc)      │
├────────────────═════════════════════┤
│           Linux Kernel              │  ← 内核空间
│  ┌─────┬────────┬──────┬─────────┐ │
│  │VFS  │网络栈   │调度器 │驱动框架  │ │
│  └─────┴────────┴──────┴─────────┘ │
├─────────────────────────────────────┤
│             硬件                     │
└─────────────────────────────────────┘
```

**嵌入式Linux 构建工具**：
| 工具 | 说明 |
|------|------|
| **Yocto Project** | 构建定制Linux发行版（最主流） |
| **Buildroot** | 轻量级嵌入式Linux构建 |
| **OpenWrt** | 面向路由器的Linux发行版 |
| **Android** | 基于Linux内核的移动OS |

## 5. 实时系统设计

### 5.1 实时系统分类

| 类型 | 定义 | 超时后果 | 示例 |
|------|------|---------|------|
| **硬实时（Hard RT）** | 任务必须在截止时间前完成 | 系统失效、灾难性后果 | 飞控系统、气囊控制、起搏器 |
| **软实时（Soft RT）** | 允许偶尔超时 | 性能降级、用户体验差 | 视频播放、在线交易 |
| **固实时（Firm RT）** | 超时无价值但不致命 | 结果无意义、丢弃 | 天气预报计算、股票交易提醒 |

### 5.2 实时系统设计方法

| 方法 | 说明 |
|------|------|
| **结构化设计** | DARTS（Design Approach for Real-Time Systems），扩展自结构化设计 |
| **面向对象设计** | ROOM（Real-Time Object-Oriented Modeling），基于Actor模型 |
| **模型驱动设计** | UML-RT（实时UML扩展），SysML系统建模 |
| **形式化方法** | 数学精确定义系统行为（Z语言、Timed Automata） |

**DARTS 任务划分准则**：
1. I/O设备依赖 → 独立任务
2. 时间关键功能 → 高优先级任务
3. 计算密集型功能 → 低优先级任务
4. 具有相同周期性/触发源的合并
5. 异步功能之间独立

### 5.3 实时性能分析

**WCET（最坏情况执行时间）分析**：
| 方法 | 说明 | 精确度 |
|------|------|--------|
| **静态分析** | 分析代码和控制流（不运行） | 安全但偏保守 |
| **基于测量** | 在目标硬件上实际测量 | 精确但不保证覆盖最坏 |
| **混合方法** | 测量基础块+静态分析路径 | 平衡 |

**响应时间分析（Rate Monotonic Analysis, RMA）**：
```
任务i的响应时间 R_i = C_i + Σ_{j∈hp(i)} ⌈R_i/T_j⌉ × C_j
其中：C_i = 执行时间, T_j = 周期, hp(i) = 比i优先级高的任务集
```

## 6. 嵌入式系统开发与调试

### 6.1 交叉开发模型

```
宿主机（Host/PC）               目标机（Target/嵌入式设备）
┌──────────────┐              ┌──────────────┐
│ 交叉编译器     │  ──下载──→   │ 可执行程序     │
│ 链接器        │              │ Bootloader   │
│ 调试器(GDB)   │ ←──调试──→   │ 内核/RTOS     │
│ IDE          │              │ 应用程序      │
└──────────────┘              └──────────────┘
```

**工具链（Toolchain）三要素**：
| 组件 | 功能 | 示例 |
|------|------|------|
| **交叉编译器** | 在Host编译Target代码 | `arm-none-eabi-gcc` |
| **链接器** | 将目标文件+库链接为可执行映像 | `arm-none-eabi-ld` |
| **调试器** | 远程调试目标程序 | `arm-none-eabi-gdb` |

### 6.2 启动过程（Boot Sequence）

```
上电 → BootROM（芯片内置固件）
     → Bootloader（U-Boot / Barebox）
        → 初始化DDR/存储/外设
        → 加载内核/应用程序映像
     → 内核启动（RTOS初始化 / Linux Kernel boot）
        → 加载驱动
        → 启动首要任务/init进程
     → 应用程序运行
```

**Bootloader 双阶段**：
| 阶段 | 位置 | 大小 | 任务 |
|------|------|------|------|
| SPL（Secondary Program Loader）/BL1 | 内部SRAM | < 几十KB | 初始化DDR，加载BL2 |
| BL2/U-Boot | DDR | 几百KB | 完整初始化，加载内核 |

### 6.3 调试方法

| 方法 | 硬件需求 | 特点 |
|------|---------|------|
| **LED/GPIO调试** | 无 | 最原始，控制LED闪烁指示状态 |
| **串口打印** | UART | printf调试，最常用 |
| **JTAG调试** | JTAG/SWD接口 | 断点/单步/变量查看/Flash烧写 |
| **逻辑分析仪** | 探头 | 分析多路时序信号 |
| **示波器** | 探头 | 信号波形、时序分析 |
| **Trace调试（ETM）** | 芯片内置Trace单元 | 指令级执行历史记录 |

**JTAG/SWD**：
| 接口 | 引脚数 | 速度 | 适用 |
|------|--------|------|------|
| JTAG | 4-5线（TDI/TDO/TMS/TCK/TRST） | 慢-中 | 传统标准 |
| SWD | 2线（SWDIO/SWCLK） | 中-快 | ARM Cortex-M主流 |

### 6.4 测试方法

| 测试类型 | 说明 |
|----------|------|
| **单元测试** | 在PC上测试（使用Mock/Stub模拟硬件），提高效率 |
| **硬件在环测试（HIL）** | 真实控制器 + 仿真被控对象 |
| **软件在环测试（SIL）** | 控制器和被控对象都是软件仿真 |
| **模型在环测试（MIL）** | 控制器模型+被控对象模型联合仿真 |
| **目标机测试** | 在真实硬件上测试 |

## 7. 嵌入式系统设计方法

### 7.1 软硬件协同设计（Hardware-Software Co-Design）

软硬件协同设计打破了"先硬件后软件"的串行模式，在系统级同时考虑软硬件划分。

```
需求分析 → 系统建模（System-Level Model）
          → 软硬件划分（HW/SW Partitioning）
          → 硬件设计 + 软件设计（并行）
          → 软硬件集成与协同仿真
          → 系统验证与测试
```

**划分依据**：
| 因素 | 倾向于硬件实现 | 倾向于软件实现 |
|------|--------------|--------------|
| 速度要求 | 高（纳秒级） | 低-中 |
| 功耗要求 | 专用硬件更省电 | CPU功耗高 |
| 灵活性 | 固定（不可改） | 可编程修改 |
| 成本 | NRE成本高，量产单位成本低 | 软硬件通用，利用已有CPU |
| 批量 | 极大批量 | 中小批量 |
| 复杂度 | 算法固定简单 | 算法复杂多变 |

### 7.2 低功耗设计

**功耗公式**：P = P_dynamic + P_static
- P_dynamic = α × C × V² × f（开关功耗，占主导）
- P_static = V × I_leakage（漏电功耗）

**低功耗设计技术**：

| 层次 | 技术 | 原理 |
|------|------|------|
| **系统级** | 功耗感知调度、动态电压频率调节（DVFS） | 空闲时降频降压 |
| **架构级** | 多核异构（big.LITTLE）、异步设计 | 不同负载用不同核 |
| **RTL级** | 时钟门控（Clock Gating）、操作数隔离 | 关断空闲模块时钟 |
| **晶体管级** | 多阈值电压（Multi-Vt）、电源门控（Power Gating） | 降低漏电 |
| **软件级** | WFI/WFE指令、减少外设时钟、算法优化 | CPU进入低功耗模式 |

**MCU 低功耗模式**：
| 模式 | 说明 | 唤醒方式 |
|------|------|---------|
| **Run** | 正常运行 | — |
| **Sleep** | CPU停、外设运行 | 任意中断 |
| **Deep Sleep** | CPU+高速时钟停 | 特定唤醒源（RTC、外部中断） |
| **Standby/Shutdown** | 几乎全关，仅保留备份域 | 外部复位、RTC唤醒 |

### 7.3 功能安全设计

**功能安全标准**：

| 标准 | 领域 | 安全等级 |
|------|------|---------|
| **IEC 61508** | 通用功能安全 | SIL 1-4 |
| **ISO 26262** | 汽车功能安全 | ASIL A/B/C/D |
| **DO-178C** | 航空机载软件 | DAL A/B/C/D/E |
| **IEC 62304** | 医疗器械软件 | A/B/C |
| **EN 50128** | 铁路信号软件 | SIL 0-4 |

**安全设计关键措施**：
- 冗余+表决（双核锁步 Dual-Core LockStep）
- 看门狗（内部+外部，独立时钟源）
- ECC/奇偶校验保护关键数据
- MPU/MMU 内存隔离
- 自检（POST上电自检 + 周期自检）
- 故障安全状态设计（Fail-Safe）

## 8. 物联网与边缘计算架构

### 8.1 物联网四层架构

```
┌──────────────────────────────────────┐
│       应用层（Application）           │  ← 智慧城市、工业互联网、车联网
├──────────────────────────────────────┤
│     平台层（Platform/Cloud）          │  ← IoT平台（AWS IoT/Aliyun IoT）
├──────────────────────────────────────┤
│    网络层（Network/Transport）        │  ← WiFi/BLE/Zigbee/LoRa/NB-IoT/5G
├──────────────────────────────────────┤
│     感知层（Perception/Device）       │  ← 传感器、执行器、标签
└──────────────────────────────────────┘
```

### 8.2 物联网常用通信协议

**近距离无线**：
| 协议 | 频段 | 速率 | 距离 | 功耗 | 典型应用 |
|------|------|------|------|------|---------|
| **BLE** | 2.4GHz | 1-2Mbps | ~50m | 极低 | 穿戴设备、信标 |
| **WiFi** | 2.4/5GHz | 数百Mbps | ~100m | 中高 | 智能家居网关 |
| **Zigbee** | 2.4GHz | 250Kbps | ~100m | 低 | 智能家居传感网 |
| **Z-Wave** | 800-900MHz | 100Kbps | ~30m | 低 | 智能家居 |
| **NFC** | 13.56MHz | 106-424Kbps | <10cm | — | 支付、门禁 |

**低功耗广域网（LPWAN）**：
| 协议 | 频段 | 速率 | 距离 | 特点 |
|------|------|------|------|------|
| **LoRa/LoRaWAN** | 非授权（433/868/915MHz） | 0.3-50Kbps | 2-15km | 自建网络 |
| **NB-IoT** | 授权（LTE频段） | <250Kbps | 10km+ | 运营商网络 |

**应用层协议**：
| 协议 | 传输层 | 模式 | 特点 |
|------|--------|------|------|
| **MQTT** | TCP | 发布-订阅 | 轻量级、QoS、IoT首选 |
| **CoAP** | UDP | 请求-响应（RESTful） | 类HTTP、适合受限设备 |
| **HTTP/2** | TCP | 请求-响应 | 通用、开销大 |
| **AMQP** | TCP | 发布-订阅 | 企业级、支持事务 |
| **DDS** | UDP/TCP | 发布-订阅 | 实时分布式系统 |
| **OPC UA** | TCP | 客户端-服务器 | 工业自动化的互操作标准 |

### 8.3 边缘计算架构

```
           Cloud（云端）
               ↑
       ┌───────┴────────┐
       │    Edge（边缘）   │  ← 边缘网关/边缘服务器
       └───────┬────────┘
               ↑
      ┌────────┴─────────┐
      │  Device（设备端）  │  ← 传感器/执行器/终端
      └──────────────────┘
```

**边缘计算的优势**：
- 减少延迟（数据在本地处理，不回传云端）
- 节省带宽（只将关键数据上传）
- 隐私保护（敏感数据本地化处理）
- 离线可用（网络中断时仍运行）

**边缘计算典型场景**：工业预测性维护、智能交通路口控制、AR/VR实时渲染、视频监控智能分析。

## 9. 常考考点速查

### 9.1 处理器对比速查

| | MCU | DSP | FPGA | SoC |
|------|-----|-----|------|-----|
| 结构 | CPU+外设集成 | 哈佛+MAC | 可编程逻辑阵列 | CPU+GPU+...集成 |
| 并行 | 单/多核 | 指令级并行 | 硬件级并行 | 多核异构 |
| 灵活性 | 软件编程 | 软件编程 | 硬件编程 | 软件编程 |
| 功耗 | 极低 | 中 | 中高 | 中 |
| 代表 | STM32 | TI C6000 | Xilinx Zynq | 骁龙 |

### 9.2 实时调度对比

| | RMS | EDF |
|------|-----|-----|
| 优先级 | 静态（周期越小越高） | 动态（截止时间越近越高） |
| 理论利用率 | ≤ 69.3% (n→∞) | ≤ 100% |
| 实现复杂度 | 低 | 中 |
| 过载行为 | 低优先级任务先受影响 | 不确定 |
| 实际使用 | 广泛 | 较少 |

### 9.3 优先级反转问题

```
场景：H(高) > M(中) > L(低)

1. L持有锁 → H等待锁（阻塞）
2. M抢占L → H等待M...但M和锁无关！
   → H被"优先级反转"

解决方案：
- 优先级继承：L临时继承H的优先级，不让M抢占
- 优先级天花板：锁的优先级 = 所有可能获得该锁的任务的最高优先级
```

### 9.4 嵌入式OS 选型决策

```
系统需求
├── 极简单（几个任务、无联网） → 裸机/前后台
├── 需要实时性 + 资源有限
│   ├── 开源、轻量 → FreeRTOS
│   ├── 安全认证（IEC 61508/DO-178） → VxWorks / μC/OS
│   └── 国产化、IoT → RT-Thread
├── 需要丰富功能（网络/GUI/文件系统）
│   └── 嵌入式Linux（Yocto / Buildroot）
└── 汽车仪表/ADAS → QNX / AUTOSAR OS
```
