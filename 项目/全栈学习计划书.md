# 全栈学习项目计划书：团队协作空间（Kanban + Chat）

## 一、项目概述

一个团队协作工具，核心能力：

- **看板模块**：创建项目 → 自定义列（待办/进行中/已完成）→ 拖拽卡片 → 分配成员 → 设置截止日期
- **聊天模块**：项目内嵌实时群聊 → 支持在线成员显示 → 消息持久化 → 支持 @提及

两者自然关联：每个项目自带一个聊天室，卡片流转时自动推送消息到聊天频道。

## 二、技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite |
| 后端框架 | NestJS + TypeScript |
| 数据库 ORM | Prisma |
| 数据库 | PostgreSQL（Docker） |
| 实时通信 | NestJS WebSocket（Socket.IO） |
| 缓存/消息 | Redis（可选，后期加） |
| 部署 | Docker Compose |

## 三、数据库核心模型

```

ProjectMember (id, project_id, user_id, role)
```

## 四、学习阶段（6 阶段，约 10-12 周）

### 第一阶段：NestJS 基础 + 用户系统（第 1-2 周）

学习 NestJS 核心概念的同时搭建基石模块：

```
AuthModule:
- POST /auth/register
- POST /auth/login → JWT
- JwtStrategy + AuthGuard（全局守卫）

UserModule:
- GET /users/me（当前用户信息）
- GET /users/search?keyword=xxx（@提及用）
```

**学习点**：模块化、依赖注入、管道验证、JWT 鉴权、守卫

### 第二阶段：项目管理 CRUD（第 3-4 周）

```
ProjectModule:
- POST /projects
- GET /projects（当前用户参与的项目列表）
- GET /projects/:id（含成员列表）
- PATCH /projects/:id
- DELETE /projects/:id
- POST /projects/:id/members（添加成员）
- DELETE /projects/:id/members/:userId（移除成员）

ColumnModule:
- POST /projects/:id/columns
- PATCH /columns/:id（编辑列名）
- DELETE /columns/:id
- PATCH /columns/reorder（拖拽排序列）
```

**学习点**：一对多关系建模、权限校验（只允许项目成员操作）、排序更新的事务处理

### 第三阶段：卡片 CRUD + 拖拽流转（第 5-6 周）

```
CardModule:
- POST /columns/:id/cards
- GET /projects/:id/cards（按列分组返回）
- PATCH /cards/:id（编辑标题/描述/负责人/截止日期）
- PATCH /cards/:id/move（跨列移动 + 排序）
- DELETE /cards/:id
- GET /cards/:id/history（操作历史）
```

**核心难点**：卡片跨列移动时，同时更新 `column_id` 和两个列的 `sort_order`，用事务保证一致性。

**学习点**：事务操作、复杂更新逻辑、操作日志自动记录

### 第四阶段：实时聊天（第 7-8 周）

这是和普通 CRUD 项目拉开差距的阶段：

**WebSocket 网关设计**：

```typescript
// ChatGateway
@WebSocketGateway({ namespace: '/chat' })
export class ChatGateway {
  // 加入项目聊天室
  @SubscribeMessage('joinRoom')
  handleJoinRoom(client, payload: { projectId: string })

  // 发送消息
  @SubscribeMessage('sendMessage')
  handleMessage(client, payload: { projectId: string, content: string })

  // 服务端推送：新消息
  // server.to(room).emit('newMessage', data)
}
```

**关键功能点**：

| 功能 | 实现方式 |
|---|---|
| 加入/离开房间 | `socket.join(projectId)` / `socket.leave(projectId)` |
| 消息发送与广播 | `client.to(room).emit('newMessage', msg)` |
| 在线成员列表 | `Map<projectId, Set<userId>>` 内存追踪 |
| 消息持久化 | 收到消息后写 ChatMessage 表再广播 |
| 卡片变更通知 | `EventEmitter` → ChatGateway 监听 → 发送系统消息 "张三将"登录页"移至已完成" |
| @提及高亮 | 前端解析 `@username`，后端查询目标用户 ws 连接单独推送 |

**学习点**：
- WebSocket 生命周期（连接/断开/鉴权）—— 从 JWT 中提取用户
- Socket.IO 的房间与命名空间
- EventEmitter 实现跨模块解耦（卡片模块发事件，聊天模块监听）
- 前端 Socket.IO Client 集成

### 第五阶段：前后端串联（第 9-10 周）

```
前端架构：
- 看板页面：列 + 卡片拖拽
- 项目聊天面板（侧边栏或右下角弹出）
- WebSocket 连接管理（进项目页面建连，离开断开）
- 消息 UI（区分普通消息/系统消息，@提及高亮）
```

**前后端联调检查清单**：
- [ ] 看板拖拽卡片后刷新页面，列和位置不变
- [ ] 卡片移动后聊天频道自动出现系统消息
- [ ] 在线成员列表中的人发的消息灰显为"离线"
- [ ] @提及某人后对方浏览器弹出通知

### 第六阶段：进阶特性 + 部署（第 11-12 周）

按优先级排列：

| 优先级 | 特性 | 技术点 |
|---|---|---|
| 必做 | Swagger 接口文档 | `@nestjs/swagger` |
| 必做 | 单元测试 | Jest → gateway 的 ws 测试 |
| 建议 | 卡片标签/优先级 | 多对多关系、前端 Color Tag |
| 建议 | 搜索卡片/消息 | PostgreSQL 全文搜索或 LIKE |
| 可选 | 未读消息红点 | Redis 计数器 |
| 可选 | 文件/图片上传 | Multer + OSS |
| 最后 | Docker Compose 部署 | NestJS + PostgreSQL + Nginx |

## 六、和纯 CRUD 项目的核心区别

这个项目能证明你掌握了全栈的核心能力：

| 能力 | 对应项目点 |
|---|---|
| 数据库设计 | 五张核心表的关联设计 |
| 事务一致性 | 卡片移动时的多表更新 |
| 实时通信 | WebSocket 聊天 + 系统通知 |
| 跨模块解耦 | EventEmitter 串联卡片与聊天 |
| 权限体系 | JWT + 项目成员守卫 |
| 部署运维 | Docker Compose 编排 |

面试时聊这个项目会比一个普通博客系统有竞争力得多。
